## 1. 起因与待分辨的假设

E2 算法线三个月、十五个以上候选全部停止。07-25 终止报告提出两个互斥解释：

- **A**：登记参数下电动车不经济，模型正确拒绝电动化；
- **B**：完成器"先全燃油骨架、再逐路线电动化"的顺序架构抑制电动化。

用户明确不接受 A。本审计以七项零搜索测量分辨，结果是两者皆非主因，真正的
阻断点此前从未被识别。

## 2. 测量结果

### M1 闲置车队（720 车场×种子单元）

登记车位 6745，实际使用 4932，闲置 1813（26.9%）。电动车位 1545，使用 477，
**闲置 1068（69.1%）**；320/720 个单元零电动车。

`fleet_caps.csv` 全部 144 行满足 `num_cv == base_all_cv_routes_Rd`。完成器唯一的
强制规则 `required_ev = max(0, 路线数 − num_cv)` 在 720 个单元中**恒为 0**，
且搜索**从未**使用超过全燃油所需的车数。电动车从不被强制启用。

### M2 路线固定下的强制电动化（2958 候选）

保持封存解的客户分组与顺序不变，对每条路线尝试三种充电策略电动化，不论成本
升降都记录，再强制填满电动车位：

- 可行 **291**，不可行 **2667**，不可行原因**全部为 `CAPACITY`**；
- 可行候选中比燃油便宜的：**291 / 291（100%）**，单次平均省 60.97 元；
- 强制填满电动车位后与封存解**逐位相同（81/81）**；
- 公共充电站使用：**0 / 291**。

**结论：解释 A 证伪**（电动车可用时无一例外更便宜）；**完成器在路线固定时已达
最优**，贪心+严格改善没有漏掉任何机会，解释 B 的"贪心太保守"子假设亦证伪。

### M4 节省与里程的关系

省钱与里程强线性：`节省 ≈ 4.92 + 0.8635 × 里程(km)`，Pearson r = **0.9758**。
但当前不可电动化的重路线**更短**（71.4 km vs 78.0 km），故其预测节省
66.57 元/条，低于已电动化路线的 72.24 元。M3 的上界因此略偏乐观而非偏保守。

### M3 载重再平衡上界（放宽算术界）

保持车辆数不变、按 `k ≤ (N×1735 − L)/735` 重新分配载重：额外可电动化 **+37 条**，
按 66.57 元/条计约 **2463 元 = 0.85%**。载重利用率均值 **88.2%**，中位 90.8%。
该式忽略地理、时间窗与载重不可分割性，是乐观上界。

### M5 载重再平衡实测

按"移出最少客户使路线降到 1000 kg 以下再电动化"的确定性探针执行：
**接受 0 次，跨 81 算例增益 0.0000%**。

### M6 移动可行性普查（889 条重载燃油路线）

- 能挪出**哪怕一个**客户的路线：**226 / 889（25.4%）**；
- 若载重可无限细分则装得下的：421 / 889（47.4%）——这正是 M3 隐含假设的口径；
- 中位最小客户 **139 kg**，中位接收方剩余容量 **137 kg**；
- 中位需挪走量 **667 kg**。

解已处于装箱意义上的死紧状态。M5 的 0 是真实结构结果，不是探针限制造成的假象。

### M7 拆分路线并动用闲置电动车位（683 次真实评价）

对每条两个电动车载重可覆盖的燃油路线，穷举全部连续拆分点，两半均电动化，
用完整模型评分：

- 尝试 **683**，可行拆分覆盖 37 个算例，**接受 0**；
- 最好一次仍**多花 136.83 元**，中位 **+168.27 元**；
- 对照：多开一辆车的固定成本 = **170.00 元**。

电动化的运行成本节省填不平多开一辆车的固定成本。该杠杆亦封死。

### M8 载重门槛普查——断崖，不是渐变

986 条路线的载重中位 **1667 kg**、均值 1581 kg，**紧贴燃油车 1735 kg 上限**：

| 电动车载重门槛 | 物理上可电动化路线 |
|---:|---:|
| 1000 kg（当前采用的厢式版） | 97 / 986 = **9.8%** |
| 1300 kg（参数候选表推荐的载货/栏板版） | 110 / 986 = 11.2% |
| 1500 kg | 150 / 986 = 15.2% |
| 1600 kg | 277 / 986 = 28.1% |
| 1735 kg（与燃油车持平） | 986 / 986 = **100%** |

## 3. 真正的阻断点

冻结车型参数（`china81.py::_china_vehicle_parameters`）：

| | 燃油 JAC-WL-K7-box | 电动 FOTON-AUMARK-ES1-140-box |
|---|---|---|
| 额定载质量 | **1735 kg** | **1000 kg** |
| 整备质量 | 2565 kg | 3300 kg |
| 总质量 | 4495 kg | 4495 kg |

总质量同为 4495 kg，整备质量差 **735 kg**，与载重差 **735 kg** 完全相等：在固定
总质量下，电池重量精确地吃掉了载重。

因果链：

搜索最小化车辆数 → 每条路线装到接近燃油车 1735 kg（中位 1667 kg）→ 电动车
只能装 1000 kg → 2667 个电动候选全部 `CAPACITY` 失败 → 仅 9.8% 的路线在物理上
可电动 → 电动车承担客户约 7.8% → 69.1% 电动车位永久闲置 → 公共充电站零使用
→ 三个月内所有针对充电、碳、车型、跨场机制的算法候选都在优化一个未被激活的
机制。

**这不是算法缺陷，也不是经济性结论，而是车型选配造成的结构性上限。**

关键的非线性：门槛从 1000 提到 1500 kg 只把可电动化比例从 9.8% 抬到 15.2%，
而提到与燃油车持平的 1735 kg 则跳到 100%。**任何低于燃油车载重的电动车都近乎
无效**，因为路径优化总会装到较大的那个容量。

## 4. 结论

在当前 China81 算例与当前车型参数下：

- 电动车在可用时严格更便宜（291/291），**不存在"电动车不经济"的证据**；
- 完成器在路线固定时已最优（81/81 逐位相同）；
- 载重再平衡实测增益 **0**，且普查证明无可用移动；
- 拆分动用闲置车位实测增益 **0**，683/683 被固定成本否决；
- 因此**任何算法在当前设定下提高电动化比例的空间约等于零**。

已冻结 G3 门要求 A+B 相对 `min(A,B)` 平均降幅 ≥ 0.50%。本审计表明该门在当前
车型参数下不可能通过，且原因与算法设计无关。
