# 有界历史优解池 P1：一次性执行失败审计

结论是 `INCONCLUSIVE_EXECUTION_FAILURE`，不是算法 PASS，也不是算法 STOP。
20、25、50 客户的六个固定评分工作进程已经返回，但运行器在随后整理方案
证明时退出，任何数值结果都没有写入 `raw_runs.csv` 或 `decision.json`，因此
本次没有一个分数可用。

故障只在证明层。运行器用“忽略路线、充电动作和跨场记录列表顺序”的语义哈希
给方案分组，却用“保留原列表顺序”的快照判断两份方案是否相同。20 客户控制臂
的第一份档案成品与对应原始方案业务内容相同、列表顺序不同，于是被误报成哈希
碰撞。该函数在搜索和完整复算完成后才调用，不会改变算法选择；但证明文件没有
闭合，所以不能从技术性质反推任何胜负。

执行合同事前写明：中止或崩溃也不能覆盖现场、换目录重跑。故本审计永久保留
原失败目录及监控异常现场，不清理其中 16 个 AppleDouble 伴随项，不补写遗失
分数，也不建立恢复门。旧三题重跑、新鲜 D3、正式对比、阶段二和全量实验全部
保持禁止。

允许的修复仅限零评分基础设施：完整内容哈希必须与保存的保序快照对应；忽略
列表顺序的语义哈希另列字段。回归测试覆盖列表重排、相同快照重复登记和微小
浮点变化。算法开发转向事前登记的后路：只在燃油路线接近电动化边界时搬移一名
客户或一小段客户，并在两条受影响路线间联合重选车型、充电与碳时刻。
