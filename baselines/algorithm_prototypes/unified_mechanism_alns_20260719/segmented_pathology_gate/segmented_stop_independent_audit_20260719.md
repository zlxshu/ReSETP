# 经典分段平均轮盘病灶门：独立复核

复核结论：`SCIENTIFIC_STOP_CONFIRMED / COVERAGE_ONLY_SUCCESS_COST_FAILURE`。

这次短门只回答一个问题：消除原选择器的算子调用垄断，能否直接改善完整成本。答案是否定的。候选在六个配对中都调用了六类拆除办法，单类最大调用占比为 18.5% 至 23.25%；控制组多数由一类办法占据 97% 至 100%。但是候选完整成本六对全部退步，严格胜为 0/6，中位退步 4.110602%，最差退步 12.150610%。因此只能说“选择次数更均匀没有转化为更优解”，不能扩大为“多样性有害”，也不能反过来声称“按病灶调度必然有效”。

预算与可行性独立复核通过。十二个运行臂均满足：

- `eval_budget = evaluations = candidate_scores = candidate_channel_scores = actual_moves = selector_selection_count = 400`；
- 拆除次数和算子对次数分别逐臂合计为 400；
- `exact_budget = true`、`feasible = true`；
- 由 `solution_witnesses.json` 重建十二个终局解后，使用 280 kWh 当前成本函数和可行性检查器独立复算，十二个成本差均为零、硬违规均为零、十二个签名均匹配；
- 两种起点的 witness 签名与 `raw_runs.csv` 的十二条 `start_signature` 全部匹配。

六对候选相对控制的改善依次为：

`-0.831316%`、`-12.150610%`、`-5.101145%`、`-3.572409%`、`-0.034080%`、`-4.648796%`。

速度门通过，中位墙钟比为 1.129422，最大墙钟比为 1.323990；但成本三道门全部失败：没有达到至少 4/6 严格胜，中位改善没有达到 1%，并出现超过 2% 的倒退。因此 `TRAINING_STOP_AVERAGED_SEGMENTED_ROULETTE` 是预先登记规则下的机械判定，不是事后解释。

当前证据目录无 AppleDouble 文件。`metadata.json` 已补登记九个输入算例文件和 `solver/src/setp_solver/prices.py` 的 SHA-256；合同及四个实现文件的哈希也已登记。运行时工作树包含无关未提交内容，因此 `git_head` 不能单独代表完整运行现场；本包以逐文件哈希、原始运行表、解 witness 和独立复算闭合迁移链。

下一步边界：停止继续调分段轮盘、Softmax 或通用覆盖规则。下一候选只能检验“当前解出现明确业务病灶时，稀疏调用对应专用办法，并保持同一条连续搜索轨迹”；这个方向仍需新鲜证据，当前 STOP 不构成其有效性证明。
