# 算法章“数学论证”的体裁标准盘点

盘点目的：回答“从零设计一篇目标期刊风格的启发式算法，数学论证实际要做到什么深度”。本文件只记录已发表论文的算法章、模型章和对应实验页所显示的写法，不把作者没有做的内容补成应有内容。

## 阅读口径

- `物理页`按 PDF 文件页序；`印刷页`按论文页眉或页码。网络首发论文若没有正式卷页，印刷页记为其 PDF 中显示的页码。
- PDF 文字抽取仅用于定位。关于“没有流程图、没有伪代码、没有复杂度、没有定理、没有消融”等判断，已对算法章和对应实验主体页渲染后目视核对。
- 原文短引只保留能够说明体裁动作的一小句；不把作者的结果数字迁移为本项目结果。
- 本轮完整逐项盘点三篇优先论文。饶卫振等 2022 的扫描件已确认在本地，但本轮未展开成同等粒度的 a–i 表，不把它混入下面的标准汇总。

## 四、体裁标准汇总

下面的“必须包含”是从三篇优先论文的共同骨架和本项目指定总模板抽出的最低体裁要求；“可选增强”是单篇论文已经做到、但三篇不共同具备的高配项。它们是体裁证据，不是用户已经拍板的本项目设计方案。

| 设计书部分 | 体裁最低要求 | 证据中的实际深度 | 本项目设计书应写到的深度 |
|---|---|---|---|
| 问题与模型接口 | 必须有完整问题描述、假设、符号、目标和约束 | 三篇均有目标与编号约束；陈雨蝶和陈婉茹逐条解释约束 | 把每个算法动作能够改变的对象、受哪个约束限制、评价如何回写说清楚；公式编号闭合 |
| 算法总体 | 必须让读者看懂从初始化到终止的完整链条 | 陈雨蝶、陈婉茹用流程图；金东遥用算法 1伪代码 | 至少一张总体流程图或等价的总伪代码；入口、评价、接受/拒绝、更新、终止都不能留黑箱 |
| 核心组件 | 每个核心策略都要说明动作、输入输出和作用 | 三篇均逐项列策略；多数是文字操作定义，不是统一的集合公式 | 对每个承担贡献的组件给出可执行定义，并明确它针对模型的哪个结构困难 |
| 模型特点到算法动作 | 必须有解释性桥梁 | 陈雨蝶用“复杂约束→全局/局部搜索”；陈婉茹把速度优化连到能耗凸性；金东遥把双层染色体连到 CVRP/FRVCP 分解 | 每个实验机制至少有一条“模型结构→搜索困难→组件动作→预期改善对象”的论证链；不要只罗列算子名称 |
| 适应度/评价/罚分 | 有内部机制时必须给公式和变量解释 | 陈婉茹给总评价函数；金东遥给路径罚分、个体适应值和多样性排名；陈雨蝶主要复用目标倒数 | 把正式目标、约束违约、不可行解处理、组件排序/选择的实际口径统一写成公式；若无概率公式，不要虚写概率机制 |
| 可行性 | 必须说明编码/解码和何时产生不可行解 | 陈雨蝶说明染色体解码与硬时间窗；金东遥明确可行/不可行双种群和充电子问题 | 对每个产生候选的位置说明可行性如何检查、修复或保留；区分“结构上保持可行”和“允许不可行搜索” |
| 复杂度 | 共同最低要求不是定理，而是让主要开销可解释 | 陈雨蝶、陈婉茹没有专门复杂度；金东遥逐算子并汇总为一次迭代最坏复杂度 | 体裁上不是三篇共同硬门槛；若本设计书把某组件称为结构性创新，建议至少给核心算子和一次迭代的复杂度粒度，做到金东遥式的可核对程度 |
| 数学证明 | 不要求收敛性/全局最优定理 | 陈雨蝶、金东遥没有算法证明；陈婉茹只有能耗函数凸性和最优速度命题，不是算法收敛证明 | 可以证明确实能证明的局部性质：评价单调性、速度子问题、可行性保持或算子复杂度前提；不得为了“数学论证”虚构收敛性定理 |
| 参数 | 必须给核心参数、数值、停止条件、机器和重复次数 | 三篇均给参数；陈雨蝶和陈婉茹部分来自文献/规模规则；金东遥明确默认参数且不按实例调谐 | 区分模型参数、算法参数、预算和停止条件；给出处或本算例标定依据；不要把代理猜的数值写成文献标准 |
| 组件贡献 | 必须有某种内部/外部验证算法设计不是只靠叙述 | 陈雨蝶三臂 GA/VNS/MPGA-VNS；陈婉茹三臂完整/去全局破坏修复/去并行；金东遥没有组件消融但有外部比较和参数敏感性 | 设计书至少先提出组件对应的可检验贡献，再在实验中设置与主张一一对应的臂；组件没做消融时，不把它写成已被单独证明有效 |
| 重复与统计 | 必须交代重复次数和报告的统计量 | 陈雨蝶 10 次，报告逐次值、最小、平均、最大和时间；陈婉茹 10 次规则但表 8未再次标明，报告最优、平均、Gap、时间；金东遥 20 次，报告平均、标准差、最小/最大等 | 明确每个实验的重复数、种子/配对方式和统计量；不要只报一条最好值 |
| 收敛/迭代展品 | 不是证明，但通常是算法章的重要实验展品 | 三篇均有迭代或收敛曲线；横轴可为迭代次数或时间 | 若主张搜索速度、阶段作用或早停依据，给对应曲线；图是经验轨迹，不把“平台”写成数学收敛 |

### 该体裁明确不做什么

1. 不把“有流程图、伪代码和曲线”写成收敛性证明。三篇优先论文都没有用经验曲线替代定理，也没有给算法全局最优保证。
2. 不要求每个邻域算子都写成复杂的集合论公式。实际论文通常给出明确的操作定义、适用对象和搜索作用；只有评价、罚分、速度子问题或动态规模等内部量需要时才公式化。
3. 不把模型性质证明冒充算法性质证明。陈婉茹的命题 1–2证明的是能耗函数凸性和最优速度存在，不是 PIVNS-SOA 收敛。
4. 不把外部基准比较冒充组件消融。金东遥的 BHGS 对比 BACO、VNS、GA、CPLEX证明的是相对表现；它没有因此证明 BHGS 的每个内部组件各自贡献。
5. 不把参数敏感性冒充组件贡献。改变 `nElite`、`nClosest` 或碳价，回答的是参数/机制变化；只有保留同一问题、同一预算并拆掉组件，才是组件消融。
6. 不把“参考文献设置参数”写成算法数学论证。参数来源、重复次数、机器和预算属于实验可复核性；它们不能替代算法结构与评价机制的推导。
7. 不为了显得“像数学论文”虚构复杂度、可行性保持、单调性或收敛定理。若前提和推导不成立，体裁标准允许写成算法解释和实验验证，不能用定理名词填空。

### 由盘点得到的最低可验收清单

- [ ] 模型目标、约束、变量和算法评价接口编号闭合。
- [ ] 总流程从初始化、候选生成、评价、接受/拒绝、更新到终止可复述。
- [ ] 每个承担研究主张的组件都有动作定义、作用对象和针对的搜索困难。
- [ ] 罚分、适应度、排序、多样性或概率机制按实际实现给公式；没有的机制不虚写。
- [ ] 说明候选何时可行、何时允许不可行、如何修复或如何处罚。
- [ ] 给出主要组件的复杂度粒度，或明确说明当前体裁证据只支持文字算法而无复杂度小节。
- [ ] 只证明能够从模型或算子前提推出的性质；不写无依据的收敛性/最优性保证。
- [ ] 参数、停止条件、重复次数、统计量、预算和硬件口径可追溯。
- [ ] 组件主张有对应的消融臂；外部对比、敏感性和收敛图分别解释，不混称。
- [ ] 收敛图作为经验搜索轨迹展示，不能升级成数学收敛结论。
