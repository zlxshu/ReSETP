## 0. 人话结论

正式公开赛场不再先拍脑袋定为 CVRP。正确顺序是：

1. 先确定本文算法真正由哪些搜索能力组成；
2. 再选能代表当前同行水平、且与这些能力同题竞争的外部算法；
3. 最后取这些算法共同使用、带逐题最好解和可复算原题的交集。

按这个顺序筛选后，当前最合适的公开主场是 Vidal 等（2013）提出的 28 道
大型多车场带时间窗算例，以下简称 `V13-MDVRPTW-28`。它比 X-CVRP 更适合
ReSETP，不是因为名称更复杂，而是因为：

- 多车场和时间窗正是 China81 的共同骨架；
- 纯路由母算法、现代开源通用求解器和最新多算法混合体都在这 28 道题上有结果；
- 原始文件公开，当前最好解有路线文件，不只是表格里的一个数字；
- 规模为 360--960 客户，仍有真实改进空间，适合检验“是否产生新最好解”。

## 1. 从陈雨蝶论文中照搬的不是题名，而是选择逻辑

陈雨蝶等（2023、2025）的公开题承担“完整算法在同行中是否有竞争力”；外部对手
来自使用同一批题、能按同一最好值计算误差的论文。其自建复杂题则承担“母算法、
另一组成算法和完整混合体是什么关系”，不把一批不能表达完整模型的算法硬塞进去。

ReSETP 对应为：

| 要回答的问题 | 算例 | 对手结构 |
|---|---|---|
| 完整算法在同行里强不强 | `V13-MDVRPTW-28` | 当前最好解、经典 HGS、当前开源强手、最新相近混合体、本文完整算法 |
| 混合到底有没有必要 | 一道事前选定的公开代表题 | 母体、独立破坏重建/精修部分、完整混合体 |
| 能否解决本文完整模型 | China81 全部 81 题 | 同完成器的母体、独立 ReSETP ALNS、完整混合体 |

这三张表不能混成一张。

## 2. 候选赛场筛选

### 2.1 五条入场硬条件

公开主场必须同时满足：

1. 与 ReSETP 至少共享两项基础结构，而不是只共享“都是 VRP”；
2. 至少有一项经典强方法、一项当前可运行开源强方法和一项较新的相近混合方法；
3. 所有正式对手在同一批原题上有逐题目标值，不能只拿汇总平均数；
4. 原题和最好解路线可下载、可哈希、可独立验可行与目标；
5. 不依赖本文结果来挑题。

### 2.2 候选结论

| 候选族 | 与本文共同骨架 | 强手共同面 | 最好解可复算 | 结论 |
|---|---|---|---|---|
| CVRPLIB X-CVRP | 容量、路径 | 很强，算法很多 | 很强 | 保留为通用路由备用场，不作主表 |
| Solomon/Homberger VRPTW | 容量、时间窗 | 较强 | 很强 | 缺少多车场，保留为接口回归，不作主表 |
| 大型 HFVRP | 容量、异质车队 | 中等 | 较强 | 缺少多车场和时间窗，不作主表 |
| 典型 EVRPTW | 时间窗、补能 | 定义和计分口径分散 | BKS 口径不够统一 | 不作主表 |
| `V13-MDVRPTW-28` | **多车场、容量、时间窗、车场车辆上限** | **经典 HGS、PyVRP、2026 混合算法共同覆盖** | **28/28 有路线证书** | **入选** |

X-CVRP 不是坏题；它只是没有 `V13-MDVRPTW-28` 那么贴近本文问题。保留其
历史审计，可以防止以后又从头重复筛选。

## 3. 为什么是 `V13-MDVRPTW-28`

### 3.1 原题

Vidal 等（2013）按 Cordeau 系列的生成方法构造了 28 道大型多车场带时间窗题：
`pr11a/pr11b` 到 `pr24a/pr24b`，规模 360--960 客户，车场数为 4、6 或
12。原始压缩包由作者资源页公开；VRP-REP 也登记了同一 28 题。

PyVRP/Instances 将它们转成明确的 VRPLIB 方言，并给每辆车显式绑定所属车场。
零搜索审计必须同时保存作者原始压缩包与 PyVRP 规范化文件，并逐字段核对客户、
车场、坐标、需求、服务时间、时间窗、车辆数、容量和最长路线时长，不能因为文件
名相同就假定等价。

### 3.2 当前最好解

PyVRP/Instances 为 28 题逐题保存了解路线，而不是只保存成本。每条路线都能按
车辆序号还原所属车场。正式 BKS 快照必须锁定仓库提交，完成两套检查：

1. PyVRP 官方解析器检查完整性和可行性；
2. 本项目独立解析器重算客户覆盖、车场归属、载重、时间窗、路线时长和整数距离。

2026 年 MDFIHA-ETGA 论文报告了大量比 2013 年 HGS 更好的上界，但其论文写明
源码和解要等论文接收后再公开。因此这些逐题值是“必须面对的最新论文目标”，
不是已经独立验真的路线证书。

本合同的零搜索审计还发现：锁定提交中的 PyVRP 当前可验 BKS 在 28/28 题上都
严格低于 MDFIHA-ETGA 论文值。这个结果说明“最新论文”不等于“当前最好路线”。
正式目标仍取下列数值的最小值：

`min(当前可验 BKS，VCGP，PyVRP 同机结果，MDFIHA，MDFIHA-ETGA)`。

只有本文自己的路线文件通过独立复算，且严格低于这个最小值，才称为新公开 BKS。

## 4. 公开外部对手：每一个都有不同职责

### 4.1 进入主表

| 对手 | 角色 | 为什么必须进 |
|---|---|---|
| 当前可验 BKS | 逐题目标 | 防止只赢某个算法却仍落后于公开最好解 |
| `VCGP/HGSADC` | 经典母体与原始强手 | 它提出这批大题并给出完整 28 题结果 |
| `PyVRP 0.13.4` | 当前开源、可同机运行的通用强手 | MIT 许可，支持多车场和时间窗，当前 BKS 更新与其 0.13 系列直接相关 |
| `MDFIHA` | 当前 CPU 多算法混合强手 | 多群体、路线交换、可行/不可行联合搜索和多车场专用移动与本文方向最接近 |
| `MDFIHA-ETGA` | 最新、结构最相近的论文强手 | 使用 GPU 多动作精修并报告大量新上界，但 28/28 仍高于当前可验 BKS |
| 本文完整算法 | 被检验对象 | 必须同时面对上述逐题最小值 |

### 4.2 为什么不再塞其他算法

SCA、早期 VNS、经典禁忌搜索等方法没有全部覆盖 `V13-MDVRPTW-28`，或已被上述
方法在同一问题上继承、超过。它们进入文献综述和设计来源表，不进正式主表。这样
不是隐藏对手，而是确保每一列都回答一个新问题。

MDFIHA-ETGA 当前没有公开代码，不能伪装成同机速度对比。论文只比较目标值；
同机时间和稳定性只比较 PyVRP、本文母体、本文独立组成算法和本文完整算法。

## 5. 像陈雨蝶 `A-n45-k7` 一样的结构解释题

结构解释题事前固定为 `PR17A`。规则不是看算法结果：

1. 取三个车场数量层级的中间层，即 6 个车场；
2. 在该层取客户数最少的题，降低结构解释和调试成本；
3. A/B 并列时按字典序取 A。

它只用于说明“母体、停滞破坏重建、后期精修和完整混合体”的关系与收敛过程，
不负责证明整体领先。

## 6. 开发、确认和封存的结果盲划分

按每个车场层级与 A/B 类型分层：

- 开发块：每层最小规模，共 6 题：
  `PR11A/PR11B/PR17A/PR17B/PR21A/PR21B`；
- 确认块：每层最大规模，共 6 题：
  `PR16A/PR16B/PR20A/PR20B/PR24A/PR24B`；
- 封存块：其余 16 题。

开发只允许一个候选和一套事前参数；确认打开后不得回开发块救参数；封存块只在
确认通过并获得用户批准后运行。最终论文公开表必须覆盖 28 题，不能只报通过的题。

## 8. China81：只按完整模型的算法血缘比较

China81 最终仍是完整 `9 城 × 3 规模 × 3 地图 = 81`，不挑城市、不挑有利题。
正式主表只放：

1. 母体多群体路由搜索 + 公共 ReSETP 完成器；
2. 独立 ReSETP 机制 ALNS + 同一个完成器；
3. 完整机制化混合算法 + 同一个完成器。

三臂共享车型、补能、碳、电价、公平、动态状态和最终评价入口。不得让完整算法
看见完整模型，而让对手只看里程。

为画收敛图和解释算法阶段，可按输入特征事前选择一题：在 China81 生成并冻结后，
只用客户数、车场数、需求离散度、时间窗紧度、EV 可达率等零搜索特征，选择离全体
中位特征最近的一题；并列按实例 ID。不得按求解结果选择。

## 9. China81 的“最好解”怎样才不自说自话

China81 尚无外部 BKS。正式做法是：

1. 先冻结并公开 81 个实例及独立检查器；
2. 先跑母体和独立 ALNS，封存 `China81-BKS-v0` 路线账；
3. 再打开完整混合体；
4. 完整混合体若严格改善且路线通过检查，记为新的项目 BKS；
5. 只有实例、旧账、新解和检查器一并对外发布后，才在论文中称
   “China81 新最好解”；否则只能称“本研究当前最好可行解”。

这能避免“自己出题、自己第一次求解，就自称刷新世界纪录”。

## 10. “最强算法逐题输给我”的诚实机器口径

这是最终期望，不伪装成已经实现。

- 若某题已证明最优：本文达到同一最优值即到数学上限，不能要求严格更低；
- 其余题：本文每题目标严格低于第 3.2 节的逐题最小目标，才算完整达成；
- 同机算法还要在相同单核墙钟下比较；内部拆解另加相同完整评价数；
- 任何不可行解、不同距离取整、不同车辆上限或未计入的补全调用，一律不算赢。

小门可以用“强向好预警”决定是否继续，但不得把小门的部分胜利写成最终逐题胜利。
