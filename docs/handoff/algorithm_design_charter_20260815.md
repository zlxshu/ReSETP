# 算法设计阶段章程（2026-08-15）

状态：`DESIGN_PHASE_ACTIVE`。本文件是算法设计阶段的唯一流程入口；五项奠基决定的正文在
`docs/paper_gci_dmm_vrp_20260804/pending_decisions.md` **P66**，本文不复制其正文。

## 一、这一阶段要交付什么

从「底座能跑、零个已证实贡献」走到「一条定型的串行算法」。验收三层（均为既有用户决定）：

1. **公开侧**：与 VCGP 2013／MDFIHA 2026／MDFIHA-ETGA 2026 同台不落下风（P37 选项 C、P40、P45）；
   超过冻结 HGS 为后置冲刺目标，不是本阶段验收线。
2. **私有侧**：机制真正进入搜索、入群、生存与父代选择（P31）；
   自研部件靠同种子配对消融证明稳定增量，证不出即废弃（P42/P43）。
3. **终局（最高验收线）**：算法必须把统一算例上已就位的作用空间兑现为
   三大实验与支撑机制的明显效应（P37 终局句）——「仅公开 benchmark 加私有消融不算完成」。

## 二、角色

- **用户**：拍板者。三方案三选一；触及红线的事项逐项批。
- **Claude**：设计师＋监工＋文档；不运行、不修改代码。
- **Codex**：设计期与 Claude 平级设计师（独立立场、对辩）；施工期为施工方。

## 三、围栏——设计辩论不得重开的已决事项

一条串行链（P36）；两手抓（P49）；一本钱账主目标（P44）；公开表对手集合（P40/P45）；
预算由收敛曲线定且排在算法定型之后（P47）；统一算例与编号均分归属（P65）；
机制必须进搜索（P31）；已废弃件不复活（P42 三挂件；SISR 两轮判负按预注册停止；
逐移动精确排程 Oracle 用法作废）；等墙钟净机同批次对照（P45/P43-K）；
测试是检验不是跑分（缺陷台账 §17）。

辩论只能在这些决定的框内进行；若认为某已决事项本身站不住，单列一节陈述证据交用户裁决，不得先斩后奏。

## 四、用户 2026-08-15 追加的三条工作纪律（原话要点）

1. **不造轮子**：能用开源就用开源，能用别人论文现成的就用现成的；
   本地没找到大概率是本地文献少，应上网检索，不自造。
2. **不给自己加用户没要求的条条框框。**
3. **算法唯一使命：为各实验与机制的效应服务**——「我不管什么专业的」。

## 五、通知义务（P66-3 用户附则的落实）

设计中若发现用户既有拍板属「拍脑袋」且与文献证据相悖：按文献证据修改方案，
**必须在下一次汇报中明报该处**（原拍板是什么、文献证据是什么、改成什么），
并尽量不触碰建模层；只有建模确有冲突或遗漏时才提议改建模，且单独报批。

## 六、流程

0. **摸底探针**（P66-4 边界内）：刷新新算例上的死因、通道活性、吞吐量。
   旧算例的历史数字（88.9% 充电拒绝、98.7% 交叉被拒等）一律只作方向对照，不得当现状引用。
1. **背靠背立场书**：Claude 与 Codex 各自独立写算法设计立场书，互不先看对方（防锚定）。落点：
   - Claude：`docs/handoff/algorithm_design_position_claude_20260815.md`
   - Codex：`docs/handoff/algorithm_design_position_codex_20260815.md`
2. **对撞若干轮**：每条主张必须带三种证据之一——**文献页码／代码行号／探针数字**；
   空口主张双方均可判无效。记录落 `docs/handoff/algorithm_design_debate_20260815/`。
3. **收敛为三个方案**：`docs/handoff/algorithm_design_three_proposals_20260815.md`，
   每方案写清代价与好处，交用户三选一。
4. 用户拍板后进入施工；Codex 施工、Claude 逐份 review（受保护文件与哈希纪律照旧）。

## 七、三方案的完成标准（九项，缺一即不完整）

1. 消融起点配置（「改进了百分之几」的分母），含它为何是合法求解器；
2. 串行链构成与层间传导关系（上层如何用下层的真实代价评价自己）；
3. 充电可行性架构立场（硬拒绝／外围缺口罚分／评价器罚分维度），各自证据与报批需求；
4. 公平参与约束的位置（P66-5 先软后硬的具体接法）；
5. **完整动态设计**（订单流重建规格、机械在线基线 P38/P41、动态插入接入、触发规则 P10）
   ——施工分期，设计不分期（P66-2）；
6. 验收判据：按实测噪声标定、开跑前冻结，不自造数值门槛；
7. 低成本否决点阶梯（吞吐量→方向→确认，秒级到分钟级优先）；
8. 失败退路（每个零件死了退到哪、如实报什么）；
9. 施工顺序、每步验收动作、风险清单（最可能翻车处明写）。

## 八、探针边界（P66-4 要点）

只用统一算例 `cn-jjj-50c-01-DEPOTSEARCH-d996f755bd`（或其非正式副本）、单种子、
**每次墙钟 ≤ 20 分钟（越快越好）**、不写正式实验包、不碰三个受保护文件、不改算例数据；
免逐次请示；尽可能不跑全量，追求低成本试错试跑；探针数字只用于设计判断，不进论文。
每次派工照旧：harness 后台任务＋一任务一哨兵＋逐份 review。

## 十、用户反复强调的常驻要求（2026-08-16 用户逐条重申并要求落档，原话要点）

**任务定位**：今天的任务是**定算法**；正式跑实验是定型后的流程活，「不再大力调试」。
**图表只是设计时重点参考的指标，不是现在要出的成品图**——「分清先后、主次」。
算例已生成好、挑选好，**只差算法**，不得再动算例。
算法要为算例、实验、机制服务：**既设计算法本体，又调试实验与机制的代码底座**。
**以终为始**——按算例与实验机制的特点把算法设计出来；最终目标是**之前的每个图表都出成绩出效应**
（图表与文字相辅相成，共同承托成绩与效应，最终服务于故事和逻辑）。

**论证标准**：要**从算法流程从零论证**，像期刊论文那样做数学论证；
不能以经验 debug 冒充论证。要**从零搭积木，每个实验每个机制都在算法上找到恰当有效的设计**（陈 2025 式）。
（V1 被驳回的原话判词：「只解决了表面，这和之前翻车的经历很相似，让我感到怀疑」。）

**发动机与赛道**：HGS 是"法拉利发动机"，任务是**造车**；发动机本身也可继续优化。
算例固定＝**赛道不是国道**，可以**像 F1 那样追求极致**——用冻结且已披露的算例结构做偏置与裁剪属合法设计。

**工作方式**：Claude 设计＋监工，Codex 施工；**设计期两者平级设计师**，带**文献与代码原始证据**
对辩、逐步收敛，**最终用户拍板**。需要用户提前拍板奠基的，**当场用大白话提出**。
方案须**说清代价与好处**供用户选择，拍板后才施工。
**尽可能把问题扼杀在讨论中**（金门大桥级别：不翻车、一次到位）。
**自主探索的定义**：产出**最终设计方案＋施工详情方案**，满足有证据、有技术论证等既有流程要求
（**包括用户未当次提及、但记载于上下文与文档中的事项**），**用户批准后才施工**。

**红线**：不给自己加用户没要求的条条框框；**不造轮子**（能用开源/论文现成的就用，
本地找不到先上网搜，不自造）；只管算法能否为各实验与机制的**效应**服务；
**与用户交流全程用高中生能懂的大白话，非必要不讲术语**；
用户未说的叮嘱在既有规矩与经历中，须遵守文档与纪律；
用户留过的假想须逐条落位（点名：**分钱机制如何进入算法**，见 P63-2、P67-4）。
