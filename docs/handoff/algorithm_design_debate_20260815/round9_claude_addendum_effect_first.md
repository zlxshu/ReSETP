## 一、`CORRECTION`：我原立场书的结构性错误

原主链是一条直线：

```
提速甲 → 收敛观测 → 噪声实测 → 冻结协议 → P70 标定 → 定稿 → 实验阶段 → 八行总表回填
```

**错在哪**：它把**全部效应工作压在"定稿"之后排队**，而"定稿"又被我定义成包含
"回归全绿＋标定完成＋配置冻结"。结果就是——**论文的归宿（效应与故事）成了整条链的最后一节，
前面全是调算法**。这正是用户说的"为了调试算法而调试算法"的**结构性成因**：
不是哪个动作错了，是排序本身把手段放到了目的前面。

`INFERENCE`（我漏掉的关键区分，Codex 在其独立立场 §2.4 独立撞出同一点）：
**"算法够用"有两个完全不同的门槛，我把它们混成了一个词。**

| 门槛 | 要求 | 现状 |
|---|---|---|
| **服务机制实验**（八行里的七行） | 能稳定产出**可信的可行解**；对参数变化**有反应**；语义已冻结不再变 | **已基本达到**（2864.86 那个解：可行、0 违规、50/50 客户、13264 kg、2CV+6EV；各档 CV/EV 对参数确有反应） |
| **服务公开对比表**（八行里的一行） | 搜索**强度**要赢过最强对手 | **未达到**（14:14 / 13:15） |

把两者绑在"定稿"一个词里，等于让**七行图表去等那一行的强度问题**。这没有道理。

`SCOPE`（与 P79 的关系，不是推翻）：P79「先把算法修好定稿，再考虑实验出图出表」的**目的**
是防止在半成品上跑正式实验、拿到作废数字。该目的由**语义冻结**满足即可——
即"不再有会让已出结果失效的代码改动"，**不等于"搜索强度最优化完成"**。
故本文提议的执行口径是：**结构冻结（语义不再变）→ 效应线开跑；强度线并行推进，只服务公开表那一行。**
此口径调整须用户确认（决策包 D0，见第五节）。

**`INFERENCE`（本文最重要的一条）：#1、#2、#3、#5 四个候选，全部不依赖算法强度**——
它们要的是"一个可信可行解 ＋ 换参数重跑"，而可行解**已经在手**。
把它们排在提速与标定之后，是把最容易兑现的效应压在最难的问题后面。

### 关于"把死的说成活的"——已有一个正当范例

时变碳择时通道 **5,210 次提案 → 0 次接受**，看起来是死的。
但把它换成政策口径就是活的：**"现行碳价 0.075 元/kg 比行为翻转临界点 1.47 元/kg 低约 20 倍，
因此理性企业不会主动挑干净时段充电——碳价必须涨到 1.47 元/kg 才会内生改变充电行为。"**
这是一句有政策分量的结论，而且**是算出来的真事实**，不是修辞。
同类正当路子还有：非线性充电够不到拐点 → 用**线性影子臂**（按邱式"每次充满"内生把 SOC 推过拐点，
P72-2 提案，未批）；不是改数字，是换实验设计让机制有机会显形。

**边界（用户自己定的，本文只是执行）**：AGENTS 第十节四条未裁决冲突中第一条明确——
看到结果不合预期，如实报、然后停下来问；不筛结果、不调参救结果、不预写结论。
上面这些路子之所以合法，是因为它们**改的是实验设计与呈现口径，不是数字本身**。
