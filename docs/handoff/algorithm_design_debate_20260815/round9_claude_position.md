## 二、验收框架（本立场书的核心，直接回答用户批评）

原则：**每个工作件必须归入以下五类之一；每类的合法性都追溯到一条既有用户决定或铁条；
凡数值线一律流向用户。** 类型外的验收写法（比如临时发明一个百分比）自动无效。

### 验收甲｜逐位一致（二值，代理可判）
- **来源**：P76 修复铁条（用户既批）。
- **适用**：提速、缓存、重构、默认关的新开关。
- **判定**：同算例、同种子、**同迭代数**下，终解指纹＋成本逐字相同。
- **关键技术点（本立场最重要的一处，请 Codex 核代码）**：逐位一致的口径**必须是固定迭代数，不能是固定墙钟**。
  此前 SC2/SC8/SC10 的"默认关闭逐位一致"在 900 秒墙钟下成立，是因为默认关不改变每圈工作量，
  同墙钟自然同迭代；而提速甲**本身就改变每圈耗时**，固定墙钟下迭代数必变、轨迹必变，
  逐位验收会被自己的成功搞垮。故甲的验收台架需要一个迭代封顶口径——
  现有代码里有没有这个开关，是 Q1（见第七节）。
- **失败退路**：回滚；或如实改列"语义变更"报批，不得赖成提速。

### 验收乙｜形态判据（定性，用户判）
- **来源**：P79 用户原话——收敛只看曲线是否走出陈式经典形态，判官是用户的眼睛。
- **适用**：收敛观测、预算读出。
- **判定**：产出落仓库的 `convergence.csv`＋收敛图，**用户看图说像不像**；
  代理只报改进点数量、曲线与运行档案，不设"多少个点算够"。
- **失败退路**：形态出不来**本身就是 P78 提速的立案证据**——这条失败路直接变成下一步的输入，不是死胡同。

### 验收丙｜行通判据（两级，数据级代理判、效应级用户判）
- **来源**：P71 八行总表＋P37 终局句。
- **适用**：机制/实验类零件（动态流修复、公平账本、碳记账、混合车队内生选择……）。
- **判定·数据级**（代理可判，存在性而非质量线）：该图表行所需字段从**保存的产物**中真实产出、
  过完整评价、同批次同评价器、服务量红线满足。
- **判定·效应级**（用户判）："明显"由用户看图表定，代理不得代设"≥x% 算明显"。
- **失败退路**：数据级不通＝报 HALT 与病灶，按四类原因分诊（AGENTS 十一.2），不硬写。

### 验收丁｜方向读数（结论降级，自动生效）
- **来源**：P73＋P79 探索口径。
- **适用**：一切探索期读数。
- **判定**：只允许三类结论——通/不通、方向、机理。**任何量级或优劣结论自动无效**，
  不需要谁来枪毙；这是给探索读数戴的天花板，防再犯"平台"式错误。
- **失败退路**：无所谓失败——丁类读数本来就不进结论，只导航。

### 验收戊｜用户定阈（流程，代理只产分布）
- **来源**：P63-2（阈值由用户给或按实测噪声标定后定，开跑前冻结）；P06/P11/P47 均为用户保留。
- **适用**：一切"会影响哪些结果进结论"的数值线——公平退回三维度、种子数、预算冻结、入文门。
- **判定**：代理产出实测分布（噪声、极差、收敛读数），把**选项＋代价**摆给用户，
  用户给数，开跑前冻结；冻结前相关比较一律不开跑。
- **失败退路**：等待期间只做丁类探索，不停工也不偷跑。

### 三条横切不变量（既有铁律的执行位，不是新规矩）
1. **产物合同**（P80）：落仓库、完成信号文件、续跑说明，三要素齐才算交付。
2. **服务量红线**（AGENTS 6.3）：逐结果报完成客户数与需求量。
3. **同批可比**（P43-K）：正式对照同批次等墙钟；形态判读以迭代序为轴（抗负载污染），墙钟轴另标。

### 反坑自检（对照"自建门槛病"的四个特征逐类检查）
历史上卡死项目的门槛有四个特征：无文献或用户来源／影响启动或结论准入／代理自判／失败无路。
逐类对照：甲有用户铁条来源、二值、失败有回滚路；乙判官是用户、失败路通向 P78；
丙数据级是存在性判定不是质量线；丁是结论降级不是停机门；戊把一切数值线交用户。
**五类中没有任何一类会出现"代理用自设数字拦住进展"的形态。**

### 当前悬空清单（本框架要修的既有伤口）
设计书与施工书至少四处写着"在噪声内"（公平表验收、C7 退回判据、公开性能、公平退回阈值）。
它们脚下的唯一实测数字 8.8% 已于今晚降级为无产物（P80 CORRECTION）。
**这四处现在是空中楼阁**——修法见第五节第 6 条：一律改指戊类流程，不留裸百分比。

## 三、主链与排序论证

```
D1 提速甲（批）──► 收敛观测（形态＋预算读出）──► 噪声实测（多种子，须批）
      ──► 用户冻结协议（种子数/阈值/预算＝戊类收口）──► P70 标定（已批三口径）
      ──► 定稿（第一节四条件）──► 实验阶段（10 种子正式战役）──► 八行总表回填
```

**为什么甲最先**：它压缩后面每一环的机时（观测、噪声、标定全是机时大户）；
验收甲二值、零语义风险；且 P76-1 已把病灶定位到行级，施工面清楚。

**为什么观测排第二而不抢第一**：若甲真逐位一致，则**按迭代序的轨迹不变**，
先修甲等于同样的观测能看得更远。例外：若用户批了观测未批甲，观测可先行
（机器夜间独占，尊重 M1 8GB 约束，AGENTS 6.2——观测跑与构建跑不同时上机）。

**为什么噪声实测在观测之后**：噪声要测在"跑到位"的解上才有意义；
形态没出来之前测噪声，测的是半途读数的离散，量级失真（这正是 8.8% 那次的隐藏缺陷——
它测在两条未收敛的跑上）。

**为什么 P70 标定最后**：P73 已定"配置比较推迟到多种子协议冻结后"；P70 三口径已批，只欠排期。

**每个节点的产物合同**：输出目录 `solver/reports/<件名>_<日期>/`、`done.json` 完成信号、
`report.md` 首行状态码、续跑说明——P80 三要素，逐件写进施工卡。

**在制约束**：主链一次只推一个节点；支线并行度由依赖与机器负载定（单机 8GB，
求解长跑期间不并行第二个求解任务），不设固定数字。
