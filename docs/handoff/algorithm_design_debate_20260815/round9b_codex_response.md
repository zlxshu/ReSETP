# 第九轮补轮答复：Q9—Q11

## 先给结论

1. `INFERENCE`：我的“结构冻结／效果闭合”与 Claude 的“两个够用门槛”抓到了同一个根本问题——不能让论文机制实验无限等待公开对比表。但两套词**不是一一对应**。Claude 的第一个门槛把“语义已冻结”“解可信可行”“对参数有反应”混在了一起；前者属于结构冻结，后两者属于机制效果证据。统一后应是三件事：**结构冻结、机制效果闭合、公开强度闭合**。
2. `FACT`：P52 已明确要求每个机制臂从头重新优化路线，再由同一个完整评价器算分；固定一条路线换参数，只能保留为解析性质、物理系数、效应上限或诊断，不能替代正式机制实验。证据：`docs/paper_gci_dmm_vrp_20260804/pending_decisions.md:654-664`。
3. `INFERENCE`：Claude 所说“四个候选全部不吃算法强度”只在“它们不要求先赢公开对手”这个窄含义下成立；若“算法强度”还包括每个机制臂能在可接受机时内充分重搜，那么这句话不成立。午休充电、完整碳价扫描和混合车队扫描都直接吃搜索吞吐与内部求解能力；`2.7–27.5` 的固定物理系数图本身可以零搜索。
4. `DECISION`：施工顺序应明确改为：**先结构冻结，再做不改语义的安全提速 D1，再观察收敛并读出预算，随后跑效应扫描**。D0 可以先确认“机制效果与公开强度分开闭合”这项原则，但 D0 中“结构一冻就立即开扫描”的执行句不能先于 D1。
5. `FACT`：现成 `cross_depot` 关闭开关锁住的是初始解中的客户—车场映射，不是 P65 冻结的 25/25 企业责任归属；两个哈希不同。因此它可以做算子消融，不能直接冒充“两家企业各自单干”的政策对照。正式协同最小设计是每颗种子 **A 单干一次＋B 单干一次＋联合一次**，不是两次搜索。
6. `INFERENCE`：Claude 的“全项目最便宜空白”按字面应推翻。零搜索的解析图更便宜；正确的企业协同对照每颗种子需要三次求解，与三臂充电实验同为 30 次求解，不是唯一最便宜。只有把问题降为“同一联合模型内的跨场算子开／关消融”时，两臂 20 次才是当前最少的正式搜索对照，但那回答不了企业协同政策问题。

## Q9｜统一定义与结构冻结的二值条件

### 1. 两套说法怎样对齐

`FACT`：Claude 原文确实把“可信可行解、参数反应、语义冻结”合并为第一个门槛，并把公开比较另列为第二个门槛；见 `docs/handoff/algorithm_design_debate_20260815/round9_claude_addendum_effect_first.md:28-41`。

`INFERENCE`：所以，两边**方向一致、切分粒度不同**。最不容易再混淆的说法不是“两道门”，而是“一个语义状态＋两条证据闭合线”。结构冻结只回答“以后还会不会因为算法含义改变而使结果作废”；它不回答算法好不好，也不回答效应大不大。
