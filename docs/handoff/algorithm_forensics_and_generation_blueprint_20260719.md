# 第一部分 · 法医报告：为什么一晚上全败

## 0. 死因（一句话）

**机制一直活在"评价 / 排序 / 接受"三层，从未进入"生成"层；决定"哪些客户组成哪条路线"的，始终是几何（里程/邻近）。** 机制只能给几何生成好的东西打分、排序、或在固定路线骨架上挑车型/充电/车场；一旦机制想改动路线结构本身，就被几何驱动的修复/收尾/接受撤回或根本没被生成出来。所有失败是这一个病的不同临床表现。

## 1. 死因的精确定义

任何元启发都有三层：

```
生成（构造 + 邻域 destroy/repair）  ──►  评价（完整成本）  ──►  接受（是否收下）
```

- **机制进过评价**（用完整模型给候选算成本）。
- **机制进过接受**（机制归一化接受）。
- **机制进过"固定骨架上的属性生成"**：v7 的 `joint_fleet_charge_decode` 在**已给定的路线**上选车型+充电；责任解码器在**已给定的路线**上改车场归属。
- **机制从未进过"路线成员生成"**：没有任何算子让机制去决定"哪些客户该被放进同一条路线"。这块是几何的独占领地——Shaw 相关性按距离/时间、worst 按距离、random 按几何。

**瓶颈就在这块未被穿透的领地。** 机制在下游再强，也只能在几何画好的骨架里挑属性、或在几何采样出的候选里重排。

## 2. 逐案尸检（每案 → 同一病理 + 证据）

| # | 失败项 | 机制被允许进到哪层 | 谁生成路线成员 | 死法 | 证据 |
|---|---|---|---|---|---|
| 1 | 通用 HGS–ALNS 融合 | 评价 | HGS 按几何交叉 | 1/6，机制搭不上车 | arch §6.1 |
| 2 | HGS 内嵌两教育器 | 评价 | HGS 按几何 | ALNS 教育 0/6、ruin-recreate 1/6，改 2/4/8 频率仍全败 | arch §6.1 `STOP_CURRENT_GENERIC_EDUCATORS` |
| 3 | 路线池集合划分融合 | 评价（选路线） | HGS/ALNS 各自按几何生成路线 | 真实 25/50c **一条 HGS 路线都没选中**，逐位退回 ALNS 父解 | arch §6.2 `STOP_ROUTE_POOL_FUSION` |
| 4 | 机制归一化接受 | **接受** | 几何 | donor02 60/112c，100/100 评价，**相对 v7 退步 7.207%/5.416%**——把机制塞进接受只加成本、不加新触达 | arch §6.2 `STOP_MECHANISM_NORMALIZED_ACCEPTANCE` |
| 5 | 单客户电动化搬移 | 移动是机制的、**收尾是几何的** | 几何收尾 | 20c 绑定 3 个完整候选**全部被通用收尾撤回**：成本 621.0831→621.0831、燃油路线 1→1、接受 0 | arch §6.3 `STOP_ELECTRIFICATION_RELOCATE_RESIZE` |
| 6 | 整条燃油路线拆散重组 | 评价 | 几何生成重组 | 全部更贵，接受 0 | 用户复盘 §3 |
| 7 | 机制计价双路线重切 | **排序** | 几何一次性生成 39 候选 | 见 §3（冒烟的枪）；且夹具无 EV，连充电/碳/车型都没证 | `mechanism_priced_pair_resplit_behavior_gate/decision.json` |
| 8 | SISR / SWAP* | 生成，但 | — | SISR 三种子调用 0 次失活；SWAP* 在所需问题类型无覆盖 | 阶段一收口 |

**共同病理**：#1–3 机制只能评价几何生成物；#4 机制进接受、不进生成；#5 机制生成的移动被几何收尾撤回；#6 生成本身是几何的；#7 机制只重排几何候选。**无一例让机制去生成路线成员。**

## 3. 冒烟的枪（两个最强单一证据）

**枪一 · 机制最优解在里程排序里排第 13。**
`mechanism_priced_pair_resplit_behavior_gate/decision.json`：`oracle_distance_rank: 13`。两条臂**共用同一组 39 个候选**（同一 `candidate_set_sha256`），只差 `ranking_score`（里程 vs 机制）。玩具是 6 客户 2 路线、**能穷举全部 39 个切分**，所以按机制排序能捞到第 13 名。**但真实算例无法穷举**——主搜索按几何采样前 K 个邻域，机制最优解排第 13（甚至第 500）时**根本不会被生成出来**。这一条**直接证明**：几何采样的邻域会系统性漏掉机制最优解，而重排救不了没被生成的解。

**枪二 · 机制的移动成立，几何的收尾把它撤了。**
arch §6.3 代码级诊断原话：**"中性搬移本身成立，通用收尾随后撤回搬移"**。这是评价/生成错配的最干净标本：一个机制动机的移动是合法的、有益的，但紧随其后的几何驱动收尾把它复原了。机制在生成层没有话语权，只要它动了结构，几何就会否决。

## 4. 为什么这不是"调参/工程"问题

八案的失败模式完全一致、跨越完全不同的实现（融合/教育器/路线池/接受/搬移/重切）。**同一病理在正交实现上重复出现 = 结构性根因，不是某个 bug 或某组参数。** Codex 看起来在"修边角"，是因为它每次都造**评价侧**零件——那是低风险增量动作；而真正的病在**生成侧**，那是它一直没敢碰的硬承诺。这也是你直觉"死在底层逻辑和设计"的准确含义。

# 第二部分 · 施工图：把机制搬进"生成"

## 5. 设计原则（唯一的北极星）

**让机制去"提出移动、形成路线成员"，而不只是"给几何的结果打分"。** 三个注入点，按代价从小到大：

```
注入点①构造：机制亲和分组，从起点就形成机制友好的路线成员
注入点②邻域：机制赤字驱动 destroy + 机制成本 repair（机制提出破坏与重建）
注入点③解码：资源扩展 Split，一次性联合决定 成员/车场/车型/充电
```

①②是**扩现有 v7、保 ALNS 身份**的务实起点；③是"从一开始共同决定"的完全体，代价大、身份实际偏 HGS 式（若走则诚实改名）。

## 6. 施工件 A（务实起点，扩 v7，先做这个）

### A1 · 机制赤字破坏算子（让机制提出"该拆谁"）

现状：destroy 的"worst"按距离。Ropke-Pisinger 的 worst-removal 对**任意成本**都成立，所以把"worst"泛化到机制成本是**有依据的最小改动**。新增五个 destroy 算子，各按一个机制赤字定义"该被移除的客户"：

| 算子 | badness（该客户的机制赤字） | 依据 |
|---|---|---|
| remove-by-depot-deficit | 该客户当前车场服务成本 − 其最优车场服务成本（含跨场费） | 责任解码器已有车场成本；Soriano 2023 |
| remove-by-vehicle-mismatch | 该客户所在路线在当前车型 vs 最优车型下的边际成本差 | v7 `route_variants` 已算逐车型代理成本；Hiermann 2016 |
| remove-by-charging-conflict | 该客户导致的充电不可行/桩冲突/高碳时刻惩罚 | frvcpy 精确充电（Froger 2019 / Kullman 2021） |
| remove-by-fairness-shortfall | 该客户所属车场的参与收益缺口权重 | Soriano 2023 公平修正 |
| remove-by-carbon-timing | 该客户充电落在高碳/高电价窗的超额排放/成本 | 时变碳 × 分时电价（模型补全后） |

统一 destroy 接口：`select_removals(solution, k, badness_fn) → customers`。`badness_fn` 可加权组合（自适应权重复用现有 AlphaUCB 轮盘赌）。

### A2 · 机制成本修复（让机制决定"重建到哪"）

repair 时按**完整机制成本**而非里程增量选插入位置，并**分层筛选**避免爆预算（复用 v7 已证机制）：

```
包络筛选（proxy，route_variants 的廉价车型/充电代理）  →  记 screen_evaluations
   └─只对 top-B 候选调 frvcpy 精确充电 + 完整评价      →  记 route_oracle_calls / complete_candidate_evaluations
```

依据：v7 `joint_fleet_charge_decode` 已做"proxy 先筛、少量完整评价"，把它从"给定路线选车型"推广到"给定移除集选插入位置+车型+充电"。Vidal 2014 的多属性专用评价支持高效增量机制评价。

### A3 · 机制亲和构造（让机制打好起点，回应你"初始化要强"）

初始解不按纯几何邻近成组，而按**机制亲和**：先按 (可行车场集 ∩ EV 可达性 ∩ 充电窗兼容) 把客户分簇，簇内再按几何+时窗排序成路线；GRASP 随机化产生多样起点池喂多重启。依据：GRASP（Feo-Resende）+ 机制感知播种（Zhao 2025 的"业务耦合专用动作"思想在构造侧的落地）。

### A 的过关标准（每个算子）

沿用五关：①文献出处 ②对真实耦合 ③绑定区打赢删减版 ④等完整评价预算 ⑤非病灶精确 no-op。**新增第 ⑥ 关（本报告核心）：该算子必须能生成一个"里程排序看不见、完整模型更好"且被主搜索真实采纳的解**——即枪一的反面，直接证明它进了生成、不是又一个重排。

## 7. 施工件 B（北极星：资源扩展 Split 联合解码器）

只有 A 不足以胜 v7 时才建。这是"从一开始共同决定"的完全体。

- **解表达**：客户顺序（giant tour），无路线/车场/车型/充电边界。
- **DP 状态**：`(顺序位置 i, 资源向量 R)`；`R = {当前路线车场 d, 车型 t, SOC, 时间, 碳/电价窗}`。
- **转移**：在位置 i 要么"延长当前路线"（更新 SOC/时间/碳，必要时插充电=frvcpy 子问题）要么"收口并新开路线"（重选 d、t）。
- **代价**：每段按**完整模型成本**（含 £固定/车型/充电/碳/跨场），不是纯距离。
- **可解性**：标签支配 + 资源上下界剪枝（Froger 的支配规则）；精确 frvcpy 最坏指数，故充电子问题用分层：包络下界筛 → top-B 精确。
- **复杂度**：`O(n · |R| · L)`，`L`=充电子问题代价；`|R|` 靠支配控制。
- **身份诚实**：这条一旦成为主力，算法实际是"资源扩展 Split + 局部搜索"的 HGS/route-first 家族，**必须诚实改名，不再叫 ALNS**（用户 2026-07-19 已授权"身份变了就诚实命名"）。
- 依据：Prins 2004（Split）+ Vidal 2012（多资源 HGS）+ Froger 2019/frvcpy（非线性充电精确）+ Hiermann 2016（车型-路线联合）。

## 8. 绕不过的前提（否则每道门天生无效）

1. **模型补全**：非线性充电曲线 + 分时电价进正式模型。否则 A1 的 charging/carbon 破坏算子、A2 的 frvcpy 精算**没有真实语义可绑定**，碳/充电机制无法真正 binding。走 `model_change_approval_register` 八步审批。
2. **造有 headroom 的算例**：每个机制单独设计**病灶压力区**算例（该机制真正 binding 且有可改善空间），而非当前饱和的 20–50c 玩具。逐机制：多车场=跨场有真实收益的责任错配；公平=弱场不接公平就亏损；碳=分时便宜窗与低碳窗冲突（已定 2025-02-12）；动态=事件到达扰动大。
3. **结果盲、同起点、同预算、同墙钟**：新鲜算例，见 §9。

## 9. 总架构淘汰门（预注册，二值，不可救援）

```
对照臂：v7（当前最强）｜v7 + 生成侧件 A｜相同动作但只看里程（几何对照）
条件：同起点 · 同完整评价次数 · 同墙钟 · 结果盲新鲜算例（含机制 headroom）
过：生成侧件 A 在≥预注册题数上严格胜 v7 且严格胜几何对照 → 生成侧方向成立，继续（B 视需要）
不过：立即淘汰，不在已见题上调参救援；判定 v7 后处理架构为天花板 → 停止再造架构，v7 + 消融 + 诚实路由定位写论文
强信号后：才加纯 HGS/纯 ALNS 对照（benchmark 战场），三者过同一完整模型补全与复算
```

这就是你说"缺一次足够果断的总架构淘汰门"。它一次性判决"生成侧到底行不行"，而不是再一个一个造零件。

## 10. 依据映射 + 治理边界

**依据映射**（每个设计决策 → 出处）：
- 机制赤字破坏 = Ropke-Pisinger worst/Shaw removal 对任意成本的泛化。
- 机制成本修复分层 = v7 joint_fleet_charge 已证 + Vidal 2014 多属性评价。
- 机制亲和构造 = GRASP（Feo-Resende）+ Zhao 2025 业务耦合专用动作。
- 资源扩展 Split = Prins 2004 + Vidal 2012 + Froger 2019/frvcpy + Hiermann 2016。
- 双路线重接 = Potvin-Rousseau 1995 2-opt*（已在 pair-resplit 用）。
- 公平 = Soriano 2023；动态 = Pillac 2012 / Vallée 2020。

**治理边界**：
- 保护文件（`cost.py`/`check.py`/`search/evaluation.py`/`prices.py` 默认值/TeX）未获批不得改。
- 触及 SOC/非线性充电/分时电价/目标/约束/可行性者走 `model_change_approval_register` 八步；批准前只接口桩 + 预算 0/1/2/5 探针。
- 正式搜索、China81、E2–E7 重跑仍须单独批准；机制原型独立目录、不进正式 runner。
- 预算四分账：`screen_evaluations` / `route_oracle_calls` / `complete_candidate_evaluations` / `reference_evaluations`。
- 诚实纪律：不得把行为门/HOLD/单预算侥幸包装成性能胜利；M1 唯一正式基准。

## 11. 诚实底线

本报告的**诊断**（机制在评价、不在生成）是读证据的硬结论，八案自洽。本报告的**施工图**是当前最有依据的方向，但**尚未证明胜 v7**——§9 的门决定它成不成。两个结局都体面：生成侧胜 v7 → 统一新算法、诚实命名；不胜 → v7 是天花板、停止追架构、诚实写作。由门判决，不由对某个名字或零件的偏爱判决。
