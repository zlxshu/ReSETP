# 问题型 HGS 成熟零件重组方案

日期：2026-08-11  
范围：只处理 EV 路线代理分辨率、私有消融基线和可组装成熟零件；不重做算法底座，不改 China81，不跑正式实验。

## 一、结论

1. **FACT——“按移动后的真实充电窗口精确计价”不能直接替换当前静态弧成本，同时保住复制内核的 O(1) 增量评价。** 真实单位电价和碳强度取决于整条 Duty 的到达时刻、SOC、充电量、趟间窗口及共享桩占用；同一条弧放进不同路径或不同趟后，推进电量最终落在哪个充电时段并不固定。当前复制内核则要求每个 `起点—终点—车辆 profile` 只有一个预先写入的整数弧成本（`kernel_proposals.py:413-461`）。把真实排程放回每个移动，会回到已证伪的约 1 秒／单车调用。
2. **执行结果——没有把精确窗口 Oracle 硬塞进移动评价。** 新增了明确的 `include_propulsion_proxy` 开关；私有消融 A0 关闭全天平均推进／碳代理，仅保留非能源里程、车辆固定成本、路线时间、独立路线内核、路线级趟指派交叉和确定性充电补全。完整评价器仍按真实时刻、真实车型和完整约束裁决候选。
3. **执行结果——私有消融臂表已经重置。** 当前可运行臂只保留 A0“只看路线基线”；旧 A2 已从 CLI 选择表删除。旧 A1 是排程协调器交叉回退，旧 A3 又建立在 A2 的逐移动 Oracle 之上，都不属于新的“逐个增加成熟零件”链，所以没有继续冒充有效后续臂。相关 Oracle／捕获源码均保留。
4. **后续组合方向——用一条串行链逐个加入成熟零件。** 零件可以来自不同论文，但每次只新增一个清楚的决策动作；候选先由确定性补全和完整评价器检查，再由现行种群生存规则决定是否留下。下文只登记已有出处的零件，不把登记写成已批准实施。

## 二、EV 路线代理：为什么精确替换会破坏 O(1)

### 2.1 当前内核实际依赖什么

复制内核在建模时把每条弧的成本一次性写入 `Model.add_edge()`。局部搜索随后通过增删少量弧计算移动差值；这要求弧成本只依赖弧和静态车辆 profile，不能依赖完整路径前缀。

当前全天平均代理满足“静态可加”，但分辨率不够：EV 每 kWh 单位成本是车场全天所有时段的电价与碳成本均值。真实评价则按充电动作实际覆盖的时段逐段计价。同一条客户弧可能因为前序客户、返场时间、下一趟、到站 SOC 或其他车辆占桩而对应谷、平、峰中的任何一个时段。因此不存在一个既精确、又与路径状态无关的静态弧值。

### 2.2 可行的退路及代价

| 做法 | 能否保住单次移动 O(1) | 能得到什么 | 主要代价 | 本轮状态 |
|---|---|---|---|---|
| A0 关闭推进／碳代理 | 是 | 干净的“只看路线”参照系，不再被全天均值误导 | 路线内核不再主动偏好低电耗或低碳时段；这些只由完整评价器裁决 | **已实现，仅用于 A0** |
| 每实体车冻结窗口值 | 是；但每轮进入内核前要重建或刷新 profile | 用当前完整 Duty 的合法充电窗口算一个固定单位值，比全天均值更贴近该车 | 同一次局部搜索中新移动创造或消灭窗口时，代理不会同步变化；若内核不支持安全刷新，要重建 `ProblemData` 和局部搜索对象 | **可行近似，未实施** |
| 车场×时段分档静态 profile | 档内是 O(1) | 比全天均值多一层时间分辨率 | 必须先决定一条 Duty 属于哪个时段；跨档后仍需刷新，且分档粒度／汇总方式会影响结果 | **可行近似，未实施** |
| 每移动调用精确排程或状态扩展标签 | 否 | 可以表达真实时刻、SOC、非线性充电和共享桩 | 破坏当前静态弧增量；现有 Oracle 实测约 1 秒／单车，远超 1 毫秒目标 | **该用法已作废** |

本轮没有替用户选“窗口内均值、边际时段值、最低值或电量加权值”，也没有新增时段阈值。若后续采用冻结窗口近似，最小改动面是：把 profile 从“车型×车场”细化到实体 Duty，在每次路线局部搜索开始前从当前完整 Duty 提取窗口，重建／刷新静态弧成本，并把窗口来源与代理值写进运行身份。它仍只能叫“冻结窗口近似”，不能叫精确窗口成本。

## 三、新的私有消融参照系

### 3.1 当前可运行臂

| 臂 | 搜索中开启的内容 | 明确关闭的内容 | 最终裁决 |
|---|---|---|---|
| A0 | 独立路线内核、路线级趟指派交叉、确定性充电补全 | 推进／碳路线代理、机制提案流、交叉排程 Oracle 回退、逐移动 Oracle、空 Duty 激活／清空开关 | 仍使用完整评价器；服务客户数和完成需求量必须完整报告 |

A0 必须保留注册实体车、车场和 Duty 身份，才能把复制内核的路线安全解码回完整候选；这些是适配器语义，不作为 A0 的问题特化零件。确定性补全只负责把路线骨架变成可评价候选，不让 A0 用不完整路线获得虚假低成本。

### 3.2 为什么参照私有侧

- `FACT`：公开侧冻结 HGS 相对已验证最好解平均只剩约 1.14% 空间（`CURRENT_PROJECT_CONTEXT.md:109`）。
- `FACT`：私有侧九题全油与全电可达构造的成本差为 17.109%–26.235%，排放差为 47.239%–82.354%，九题方向一致（`solver/reports/effect_ceiling_forecast_20260811/report.md:42-59`）。
- `INFERENCE`：问题零件在私有完整模型上有可观察的结构空间；公开侧零点几个百分点的总头部空间不适合承担主要部件消融的参照责任。

天花板只说明“有空间”，不证明某个零件一定有效。后续每个新增臂仍需同种子、同初始种群、同完整评价上下文和同墙钟预算；本轮没有启动这些实验。

## 五、建议的单链装配顺序

以下是 `DECISION（代理建议）`，不是用户已批准的臂编号或实现授权：

1. A0 保持只看路线，用作固定参照。
2. 先加时空聚类初始解：只改变种群起点，改动小，容易确认是否真正进入种群。
3. 再加 Montoya 充电站插入，然后加 Keskin–Çatay 部分充电量：先解决“去哪充”，再解决“充多少”。
4. 复用现有 regret-2、整 Duty 清空和车型换型，形成车辆数／车型／动态订单的结构修复；不重复造算子。
5. 双目标模式使用现有 NSGA-II 生存和非支配档案。
6. 单串行精英重启只在来源参数和本机收敛标定完成后接入；不移植多种群并行部分。
7. SP 单独等待 P21。若用户以后选择整日 Duty 列或显式车辆资源主问题，再作为末端列重组；在此之前不挂进链。

每一步都应形成“前一臂＋一个零件”的累加消融；A2 这个旧 Oracle 臂身份不再使用。具体未来臂名、参数和正式预算均为 `UNKNOWN`，本文件不替用户设定。
