# 附件算法与阶段一报告核验

日期：2026-07-18

核验对象：用户附件 `pasted-text.txt`。

## 总判定

报告作为“不要让算法支线独占阶段一”的提醒是有价值的；作为算法根因或阶段合同则不够可靠。它正确汇总了若干历史负证据，但把三种不同证据层混在一起：已退役英国E2、当前BKS盲Homberger G1、尚未生成的China81。由此产生了几个超过证据的结论。

## 成立的部分

1. 旧英国E2确有路线数/固定趟次成本残差。历史hard subset记录的A0相对LNS平均总成本差约23.78、路线数差0.3125、固定成本差25.0；这是该历史合同下的重要诊断。
2. winner与LNS基线确实都能调用 `_apply_strong_alns_destroy_repair`。这说明两者共享一个强重组组件，算法增量必须与该共享能力区分。
3. 选择器饥饿、历史局部搜索预算少记和大量默认关闭诊断旗标均有仓库证据。G0之前的若干正信号确实不能直接恢复为公平性能证据。
4. 英国E2的810行十种子矩阵真实封存，`staged_hybrid_carbon_aware`总排名第一；但它现在属于英国历史轨，不是China81主结果。
5. 阶段一不能只盯算法。MC-002延后项、重庆客户池、九城入口、备选车场和本地路由前置都仍是实际工作。

## 需要纠正的部分

### “ALNS和LNS是同一个算法”

不成立。两者共享一个strong-bridge函数，但winner还有分阶段预算、ChainUCB/算子集合、接受与重启逻辑，LNS基线有自己的搜索会话和调度。准确说法是“共享关键强重组组件，新增方法必须证明超出共享组件的边际价值”，不能说“让一个东西赢它自己”。

### “目标函数只有一个£80离散台阶，所以没有搜索空间”

只对旧英国E2的一个历史hard subset成立。`vehicle_fixed_cost=80`属于英国价格合同；Homberger G1使用车辆数优先、双精度距离次优的BKS盲目标，未来China81还要使用中国CNY与非线性物理合同。历史残差不能外推为三套问题的共同天花板。

即使在旧E2，若干探针失败也只说明已测试实现没有稳定headroom，不证明数学上或算法类上“没有可搜空间”。

### “单解ALNS结构上做不了路线消除/ejection chain”

不成立。ALNS可以把整路线移除、路线消除或有限深度逐出链作为destroy/repair；当前独立ALNS代码已经存在默认关闭的`route_elimination_removal`和整路线移除。历史实现没有稳定过门，与算法范式结构上不可能是两回事。

### “真正SWAP*活性仍坏，必须先修”

过时。当前源码C1/B160接入复验已真实触发2次、占8次统一完整评价。R1单种子0次是该运行没有形成合同要求的连续停滞窗口，不是接线断裂。继续改触发器会成为追结果；正确做法是结果盲、多类实例的顺序门。

### “英国E2冠军已经是当前论文正式结果”

边界不完整。英国E2封存结果是真的，但2026-07-18中国切换合同明确规定英国轨不再进入中国主线参数表、主结果表、统计汇总或结论分母。它可作历史算法证据和回归锚，不能替代China81同版本重跑。

### “六条线就是既有正式阶段一”

原仓库没有这份六线阶段合同；这是报告作者的整理。用户本轮已明确阶段一并行、阶段一全完才进阶段二，因此现已用`docs/handoff/phase1_parallel_completion_contract_20260718.md`把六线变成正式可验收合同。

## 可保留的一句话

旧E2表明共享强重组已经很强，历史残差常落在路线数；但这只说明新候选必须用统一预算证明独立边际价值，不证明ALNS没有改进空间，也不能替代Homberger与China81的分层验证。
