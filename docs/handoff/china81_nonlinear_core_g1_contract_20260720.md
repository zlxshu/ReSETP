## 1. 授权与目标

用户已授权以算法最终性能和后续 E1--E7 可用性为中心，自主决定实现顺序、算法结构
和参数；证据向好时逐级扩大，证据否定时及时止损。本合同把该授权落实到
`G1-FREEZE-MERGE` 的唯一剩余物理阻断：把已经通过独立固定方案复算的分段非线性
充电规律迁入共享求解器，并以同一内核闭合排班、成本、检查和动态继承。

本项不是新的算法候选，也不恢复已经停止的公开题比例、时点或参数微调。当前公开核心
继续冻结为 `MDA-ILS-VNS`；China81 的机制算法只有在本合同的物理门通过后才允许作
胜负探针。

## 2. 分批顺序

### NL0：唯一纯数学内核

新增 `solver/src/setp_solver/charging_curve.py`，迁移并合并已经通过数学测试的：

- 归一 SOC 断点与相对功率曲线缩放；
- 累计充电时间、逆函数、给定时长可达电量；
- 多趟车辆链的最小发车电量倒推；
- 充电阶段、半小时槽电量精确积分和候选开始时点。

NL0 不修改 `cost.py`、`check.py`、`prices.py`、解结构或正式搜索入口。必须证明
`L100_control` 逐位退化到旧恒功率公式，并与原冻结复算模块逐项一致。

### NL1：解结构与排班接线

NL0 全绿后，才允许：

- 在 `ChargingAction` 末尾增加可选的起始电量、结束电量和曲线 ID，保持旧位置参数和
  历史 JSON 只读兼容；
- 把多趟排班中的 `gap × power` 和 `energy / power` 改为唯一曲线内核；
- 新证书冻结曲线 ID 和曲线参数哈希；
- 以 `L100_control` 跑旧排班回归，以 `NL90_mild` 对照既有固定方案复算。

### NL2：充电修复、成本与检查接线

NL1 全绿后，才允许逐个接入充电修复、碳择时、成本、排放、利润和独立检查器。
每接一个入口都必须同时做到：动作有明确起止电量；时长由曲线计算；分时电量精确闭合；
旧线性对照不漂移。禁止用 `energy <= power × time` 代替曲线等式。

### NL3：动态继承与 China81 汇合

NL2 全绿后，接动态多趟状态继承和执行证书，随后运行：

1. 三曲线数学与联合回归；
2. 原冻结固定方案的 `NL90_mild` 逐项复算；
3. China81 81/81 零搜索物理预检；
4. 最终 `China81_FINAL` 合成与独立失败关闭审计。

只有四项全过，才允许把 `formal_search_allowed` 改为 `true`。

## 3. 最低成本性能门

正式 81 题不是开发集。物理门通过后，先按零搜索输入特征事前固定三个开发实例：
三个地区各一个、客户规模取中等档，复本固定为 01；不得按算法结果换题。三臂共用同一
非线性完成器和最终检查器：

1. 强公开母体 `MDA-ILS-VNS`；
2. 独立机制 ALNS；
3. 完整机制化混合体。

第一门只跑一个共同种子和短预算，目标是检查完整体是否零负且至少两胜、机制是否真实
改变车型、充电时刻、责任或路线结构。未过先做一次源码尸检；只允许修明确的接线错误，
不允许换题、放宽物理或事后挑机制。强信号后才扩种子和规模。

## 4. 保护边界

- `cost.py`、`check.py`、`search/evaluation.py`、`prices.py` 和主 TeX 继续是保护文件；
  NL0 不得修改它们，NL1/NL2 只有在前一门封存后按本合同逐个修改并完整回归。
- 不删除旧线性历史证据，不把非线性新结果拼接到旧线性 E2--E7。
- 三条曲线是明确标注的归一形状情景，不冒充特定车辆实测曲线。
- 任何不可行、方向反转、超时和坏例都原样保留。
- 所有代码、合同、日志和证据留在 ReSETP 仓库内。

## 5. NL0 验收标准

NL0 只有同时满足下列条件才通过：

1. 曲线参数有限、功率正且不递增、累计时间连续单调；
2. 逆函数在断点和内部点闭合；
3. 跨断点动作能量和时长守恒；
4. `L100_control` 对旧恒功率公式逐位退化；
5. 多趟后向递推与穷举小例一致；
6. 分时电量与候选时点和冻结复算模块一致；
7. Ruff、编译和目标测试全过；
8. 产出五记录面并独立复算哈希。

NL0 通过只表示统一数学内核可接线，不表示 China81 已可搜索或算法已经胜出。
