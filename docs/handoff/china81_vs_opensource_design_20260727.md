# China81：MV-HGS-SP 对开源 HGS 的正面对照设计

编号：`E2-CHINA81-VS-OPENSOURCE-001`
日期：2026-07-27
状态：`CONFIRMATION_COMPLETE__EVIDENCE_FROZEN`

## 1. 这一仗要证明什么

用户 2026-07-27 裁决：公开算例允许机制退化、不在其上做消融；**China81 是消融
主战场，且对照必须包含真正的开源 HGS，不能只跟自家弱视角比**。私有算例消融
**允许不等算力**（收敛式预算 + 逐算法披露 CPU），此为陈雨蝶（2025）采用、目标
期刊接受的惯例。

因此本对照只回答一个问题：

> **在 China81 完整模型下，MV-HGS-SP 是否显著优于直接套用的开源 HGS？**

不追 BKS，不追 SOTA（China81 是构造情景，两者均不存在）。

## 2. 五个臂

| 臂 | 搜索时的弧成本代理 | 说明 |
|---|---|---|
| **O** | **原始距离** | **真正的"开源 HGS 直接用"**：PyVRP 只看距离，对油电、充电、碳、分时电价一无所知 |
| F | 燃油成本代理（`cv_only`） | 只考虑燃油车的成本，不含电动 |
| E | 简化电动代理（`naive_ev`） | 含电动但不含时变成本 |
| M | 完整机制代理（`mechanism_ev`） | 含电动 + 分时电价/碳强度 |
| **MV** | 三视角 + 集合划分（完整体） | 当前冻结算法 |

**关键区分（此前差点打偏）**：`cv_only` **已经是成本代理**（含半载重油耗成本），
不是纯距离。所以 F 不能当作"开源基线"，必须另立 O 臂。O 是本设计的唯一新增
组件，实现方式为在适配器中新增 `distance_only` 代理模式，弧成本 = 原始距离，
不含任何能耗/碳/电价项。

所有五臂**共用同一个完整完成器与同一个精确评分器**（`china81_completion.py` +
`exact_china81_score`），差别只在搜索阶段看到什么代理成本。这保证比较的是
"搜索时是否感知机制"，而不是"评分口径不同"。

## 3. 预算与统计口径

- **收敛式预算**：各臂跑到自身收敛（`NoImprovement` 触发），不设等算力硬门槛。
- **必须逐算法披露 CPU 与墙钟**，论文中与结果并列呈现。不得把收敛式结果写成
  等算力优越。
- 停机不使用墙钟做算法内部判据（沿用 07-26 用户裁决）。

## 4. 算例与种子

- **开发集（先跑）**：9 题 = 3 城市群 × 3 规模（小/中/大各一），种子 1--3，
  共 135 单元（9 × 3 × 5 臂）。
- **确认集（开发集通过后再跑）**：全部 81 题 × 种子 1--5。
- 开发集在论文中如实标注为开发集。

## 5. 判读（运行前定，但不设过多硬门）

主结论看两条：

1. **MV 对 O 的逐题配对胜负与平均改进**——这是"干过开源"这句话的直接证据。
2. **阶梯是否成立**：O → F → E → M → MV 的成本是否单调下降。若成立，消融表
   自然成立，每一层机制的边际贡献可读。

若 MV 不显著优于 O，如实报告，不调参救。该结果虽不利，但必须我方先知道，
不能留给审稿人发现。

## 6. 与已有证据的关系

23 负、对 HGS-M 为 144 胜 261 平 0 负。**本设计不推翻它，而是补上它缺的那一

## 7. 实现边界

- 多进程必须非沙箱启动。

## 9. 2026-07-27 全 81 题确认结果

用户随后明确授权确认集。沿用完全相同的隔离适配器、完成器、精确评分器和
`NoImprovement(3000)` 协议，以 6 个进程完成 81 题 × 5 种子的 405 个 O 臂单元；
F/E/M/MV 继续只读复用 v7 封存的 1620 行，最终矩阵为 2025/2025 行。独立核验结果：
2025 个 `(instance_id, seed, arm)` 主键全部唯一；405 个 O 解全部 PASS、精确可行、
违约数为 0；runner/adapter 哈希零漂移，7 个登记产物哈希全部匹配。

确认集主结果：MV 对 O 为 **354 胜、46 平、5 负**，平均成本改进
**1.919118015025895%**。因此“MV-HGS-SP 在 China81 完整评分下总体优于直接套用的
纯距离开源 HGS”获得全量配对证据，但不是逐单元支配。五级完整非增阶梯仅
**299/405** 成立；转移计数为 O→F `268/115/22`、F→E `290/86/29`、
E→M `79/249/77`、M→MV `114/291/0`（改善/平/回退）。因此不得声称每一层机制在
每个单元都单调贡献；可单独声称 M→MV 在本矩阵中从不回退。

O 臂最终选择中，390/405 由 `distance_only_hgs_search` 胜出，15/405 由共同初始解
安全网胜出；后者集中在 3 个算例、各 5 个种子。O 臂累计 CPU 为
18435.601032 秒，累计逐单元墙钟为 19388.929480863968 秒；停止迭代数最小/中位/
最大为 3001/4121/30509。墙钟是并行单元耗时之和，不是整批经过时间。F/E/M/MV
仍是历史固定迭代批次，故这些数不能用于声称同批、同机、同停止规则或等算力。
