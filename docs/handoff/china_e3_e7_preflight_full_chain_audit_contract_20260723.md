# China81 / E3--E7 正式实验前全链路 Reviewer 审计合同

合同编号：`PRE-E3-FULL-CHAIN-REVIEWER-AUDIT-001`

状态：`IN_PROGRESS__FORMAL_SEARCH_HELD`

日期：2026-07-23

## 1. 目的

本审计在任何 E3--E7 正式搜索前，以严格审稿人和可证伪工程审计的双重口径，复核
China81 从来源、空间归属、参数映射、物理模型、算法、评价器、实验设计、统计、
证据封存到论文表述的完整链条。目标不是证明现有实现正确，而是主动寻找能够改变
可行性、目标值、比较结论或论文主张的反例。

本合同不授权正式搜索。审计期间
`formal_search_allowed=false`、`search_evaluations=0`；现有 E2 结果只读保留，
但若确认 P0/P1 问题影响 E2，则必须撤销“E2 已闭合”的适用范围并重跑受影响部分。

## 2. 用户已确认的授权

1. 允许追溯 E2；若问题影响成本、可行性或胜负，接受重开并重跑受影响部分。
2. 审计覆盖“输入--代码--证据--论文”全链。
3. 明确的映射、单位、连接和验证器实现错误可直接修复并保留旧 HALT；模型、参数、
   代理选择和统计口径变化必须暂停并提交用户裁决。
4. 禁止静默代理。缺少城市本地数据时只能显式登记 `SCENARIO_PROXY`，披露来源、
   边界并在可能影响结论时做敏感性分析或 HALT。
5. 经纬度只用于行政区/供电区一致性校验；价区由显式 `price_area_id` 决定，具体
   档位由用户类别、报装容量、电压、计量方式和利用小时共同决定。
6. 论文只称“构造情景”；同时应尽最大努力接近并使用实际运营参数，不得写成命名
   车场实测合同。
7. 允许使用官方网络来源、Zotero 文献、行政区 GIS 边界，并在项目隔离环境安装
   必要审计工具；来源、版本和 SHA-256 必须封存。
8. E3 放行硬门：P0=0、P1=0；81/81 bundle 通过；全部区域映射闭合；目标函数与
   独立复算一致；错区、错单位、错时段、错列反例均能被主动拒绝。

## 3. 严重度与处理规则

- `P0_CRITICAL`：改变可行性、目标函数语义、主要结论、样本身份或产生数据污染。
  发现即 HALT；定位影响面；禁止继续正式实验。
- `P1_HIGH`：可实质改变目标值、算法比较、统计推断、区域参数或实验公平性。
  修复并完成影响分析前不得放行。
- `P2_MEDIUM`：不一定改变当前数字，但破坏复现、证据血缘、失败关闭或必要披露。
  必须修复或形成明确、可验收的边界。
- `P3_LOW`：维护性、命名、冗余或不影响科学判断的展示问题。登记后可延期。

“当前结果恰好未变化”不自动降低严重度；能够在其他实例、日期或分支静默产生错误的
实现仍按潜在影响评级。

## 4. 审计顺序

### A1 权威血缘与陈旧入口

确认唯一正式入口、版本覆盖、源文件哈希、冻结文件是否漂移、旧 v1/v2 与新 overlay
的消费关系、dirty worktree 归属、当前环境和依赖。任何运行时读取已被新登记取代的
旧语义而无校验，至少列为 P1 候选。

### A2 空间与区域归属

对九城车场、公共充电站和全部客户的 WGS84 坐标做行政区边界核验；核对 BD09/GCJ02/
WGS84 转换血缘、道路图区域、`city`、`region`、`price_area_id`、碳强度列和柴油
价格区。建立显式映射注册表，并加入错区故障注入门。

### A3 价格、费用与单位

逐城核对车场电价、公共站电能价、服务费、占用费、柴油价、碳价、固定费、币种、
含税口径、尖峰/峰/平/谷时段和半小时槽。区分观察值、官方目录值、构造情景和统一
代理；禁止将区域代理写成本地实测。

### A4 碳强度与时空传播

核对省级列、城市映射、Asia/Shanghai 时区、2025-02 全月、共同解释日、节假日敏感性、
半小时槽边界和跨日处理。逐充电动作验证城市、槽位、能量和 kg/g 单位传播，检查
碳盲对照是否只关闭碳信号而不改变其他机制。

### A5 车辆、道路、能耗与充电物理

核对 CV/EV 两类车辆、载重、整备质量、总质量、电池、功率、非线性曲线、初始 SOC、
续航、道路距离/时间/`Σ(v²d)`三矩阵、多趟实体车、共享桩容量和等待。建立守恒、
边界与错单位反例。

### A6 目标、约束与独立评价

逐项对齐论文公式、`cost.py`、`check.py`、完整完成器、exact scorer 和保存 witness。
检查成本分解、碳排、收益、公平、时间窗、容量、SOC、客户覆盖、车场责任、共享桩、
动态冻结。全解约束不得误用于路线片段；局部检查不得漏掉全局约束。

### A7 算法和代理语义

复核 HGS-F/HGS-E/HGS-M、完整模型裁判、SP 路线池、单调保护、随机流、收敛条件、
失败语义和轨迹口径。代理评价不得被误写成完整目标；额外算力和 CPU 口径必须披露。

### A8 E3--E7 设计与统计

核对任务生成、臂定义、共同种子、地图/种子/cell 三层样本单位、缺失与不可行处理、
预算公平、主要终点、方向、多重校正、效应量、置信区间和结果盲扩种规则。防止伪重复、
事后改端点、按显著性补种子或静默删除失败单元。

### A9 协同、公平与动态

核对责任基线、独立经营、跨场服务、参与约束、收益定义、滚动事件流、冻结历史、
状态继承、事件身份和动态×协同/公平/碳三交互。空机制、未绑定机制或退化曝光不得
写成机制有效。

### A10 证据、恢复、环境与安全

复核 metadata/raw/decision/hash/report、独立复算证书、断点幂等、原子发布、
AppleDouble 排除、依赖与许可证、随机种子、线程/CPU 合同、日志和源码安全扫描。

### A11 论文一致性

把每个参数、公式、表、图、样本量、算法名、统计句和因果/机制主张映射到运行时字段
与封存证据。构造情景、观察值、代理、推断和未知必须使用不同证据等级。

### A12 红队与总裁决

实施错城市、错价区、错碳列、错时区、错单位、缺槽、重复客户、跨城充电、无碳曝光、
代理/完整排序冲突和断点损坏等故障注入。只有错误均被 fail-closed 捕获，且 P0/P1
清零，才可判 `GO_E3`；否则为 `HOLD_E3_AUDIT_FINDINGS_OPEN` 或具体 `HALT_*`。

## 5. 修复与证据纪律

- 审计发现与修复分开记录；先保存复现证据，再修改。
- 旧 HALT、旧 raw、旧 manifest 不改写；修复另立 v2 或新目录。
- 修复确定性实现错误后，只运行受影响的零搜索验证、单元/性质测试和必要影响复算。
- 任何会改变正式输入数字、模型、单位、代理、主要终点或统计方法的修复，先写
  `HALT_*_AWAITING_USER_APPROVAL`。
- 若问题影响 E2，先形成影响矩阵，不直接覆盖 E2 结果。
- 审计产物目录：
  `baselines/china_e3_e7/pre_e3_full_chain_audit_20260723/`。

## 6. 放行标准

同时满足以下条件才可 `GO_E3`：

1. P0/P1 开放项均为 0。
2. 81/81 bundle 与全部源哈希通过；无陈旧权威入口。
3. 5805 个客户、九城车场和公共站的空间/城市/参数映射闭合。
4. 电价、碳、柴油及全部关键参数都有来源等级和运行时消费证明。
5. 成本、约束、碳排、公平和动态关键量至少有两条独立复算路径。
6. E3--E7 样本单位、任务数、臂、预算、缺失规则和统计合同一致。
7. 红队故障注入全部被预期拒绝。
8. 论文不含超出证据的事实或因果主张。
9. 五件套、独立复算、哈希和 AppleDouble 门全部通过。
10. `formal_search_allowed` 只能由独立 release 决定显式修改，审计脚本本身不得放行。
