# China81 E3 正式执行放行合同

合同编号：`CHINA-E3-FORMAL-RELEASE-001`

状态：`IMPLEMENTATION_AND_ZERO_SEARCH_GATES_IN_PROGRESS`。本合同落实用户于
2026-07-23 对 D1--D6 的明确批准；在独立 release 证据判定 `GO_E3` 前，
`formal_search_allowed=false`，不得启动 E3 正式搜索。

## 1. 单一时空结算主键

所有 China81 正式任务必须绑定同一个联合主键：

`instance_id + node_id + city + price_area_id + carbon_source_column + diesel_zone + scenario_date + hourly_calendar_row`。

其中，节点经纬度只验证 `node_id -> city` 的空间归属，不直接选择电价、碳强度或
柴油价。电价由 `price_area_id` 选择，碳强度由 `carbon_source_column` 选择，
柴油价由路线起点车场城市对应的 `diesel_zone` 选择；三者必须共同使用
`2025-02-12`，电价和碳强度必须使用同一 1--48 半小时槽。缺城市、错日期、错槽、
重复槽、跨城市列、跨价区、跨柴油区、来源哈希不一致或数值不闭合时一律失败关闭。

正式任务必须保存该联合映射文件及其 SHA-256；只保存一个“地区”字段或在运行时
退回城市群均值不合格。

## 3. D2：有限车队与构造充电设施

每个实例、每个车场独立形成零搜索车队基数 `R_d`。构造器只使用冻结客户归属、
需求、时窗、服务时长、修正后的有向行程时间和车辆容量，以
`(最晚时间, 最早时间, customer_id)` 固定顺序做确定性首次可行装箱；每次插入均由
共享时间递推和容量约束验证，不比较目标值、不调用元启发式。构造结果必须给出完整
全燃油可行 witness；失败则停止，不得放宽约束或用搜索结果反推车队。

主情景总储备系数预注册为 `1.25`：

- 燃油车上限 `num_cv(d)=R_d`，保证零搜索全燃油后备方案仍可执行；
- 电动车上限 `num_ev(d)=max(1, ceil(0.25 R_d))`；
- 车场总上限为两者之和，不得由客户数覆盖或运行时环境变量扩大。

车队敏感性固定为 `1.10/1.25/1.50`，对应
`num_ev(d)=max(1, ceil((rho-1)R_d))`，燃油车上限始终为 `R_d`。该设计是构造情景，
不是九个物流园的实测车队。

车场充电主情景保持每场 `2 x 22 kW`，公共站保持冻结登记值；其枪数和功率明确称为
构造情景。车场枪数敏感性固定为 `1/2/3`，功率敏感性固定为 `11/22/44 kW`。
任何展示不得称为真实园区合同容量。

## 4. D3：E3 成对臂

控制臂 `status_quo_responsibility` 对每个客户硬锁
`customer_home_depot[customer_id]`。控制臂的初解、搜索候选、路线池和 MIP 列均须
满足所属车场；任一跨场客户即为硬违约，不能只靠高罚值或关闭某一个算子。

处理臂 `optimized_responsibility_cooperation` 解除所属车场锁，允许不同车场路线间
双向交换/搬移；必须记录跨场候选调用、两个方向的可行候选及最终跨场服务。两个臂
共享输入字节、初解规则、种子、完整候选评价预算、墙钟安全上限、评价器、MIP 时限和
证书。责任映射哈希必须逐任务绑定。

## 5. D4：预算与运行环境

主要预算单位为“提交完整补全、完整目标函数和硬约束检查的候选次数”，无论候选最终
可行与否均记一次。成对臂必须具有相同预算；达到预算立即正常停止。墙钟只作安全上限，
触发即记 `HALT_SAFETY_WALLCLOCK`，该单元不进入成对效果统计。

预算 pilot 预注册为珠三角 `10/75/200` 三档、地图 01、共同种子 1、两个 E3 臂；
只读取候选提交数、完整补全成功/失败数、耗时和安全上限状态，不写出或比较目标值。
候选预算候选值固定为每个视角 24 个归档候选，加每视角共同初解与代理最优各 1 次，
再加 MIP incumbent（或父方案回退）的独立复算与最终完整补全各 1 次，即每臂每单元
`3 x (24 + 2) + 2 = 80` 次。pilot 仅判断该预算是否可稳定消费及是否需因吞吐下调，
不得据臂间效果选数。

正式 HGS 路线生成固定每视角最多 5,000 次遗传迭代；这只是候选生成上限，不替代上述
主要预算。每视角墙钟安全上限为 `max(180, 2n)` 秒，触发即 HALT，不作为正常终止条件。
限时 MIP 路线池重组固定 5 秒。正式环境固定 PyVRP 0.12.2、
同一 Python/SciPy/HiGHS 版本和单线程
`OMP_NUM_THREADS=OPENBLAS_NUM_THREADS=MKL_NUM_THREADS=VECLIB_MAXIMUM_THREADS=1`。
每个任务保存环境、输入、责任映射、初解、算法、评价器、结果解、证书和独立复算哈希。

## 6. D5：限时 MIP 路线池重组

组件统一称“限时 MIP 路线池重组”，不得再称“精确 SP”。每次调用必须保存
HiGHS `status/message`、可行 incumbent、objective、dual bound、relative gap、
node count、time limit 和是否证明最优。只要 incumbent 经完整模型复算可行，即可与
最佳父方案取优；未证明最优时只能称“限时可行重组”，不能写精确最优。

无 incumbent、覆盖不闭合、车辆上限不闭合、完整检查失败或状态字段缺失时退回最佳
完整父方案并如实登记，禁止使用残缺 `x`。

## 7. D6：重跑与历史边界

完成本合同的零搜索、单元、性质、故障注入和独立复算门后：

1. 在新目录完整重跑修正权威下的 China81 私有 E2 及 S3--S5，不覆盖旧 raw/HALT；
2. 公开 P1 不重新搜索，只对确有封存 witness 的单元做当前检查器无搜索重放；缺 witness
   的单元明确记 `NOT_REPLAYABLE_NO_SEALED_WITNESS`，不得补造；
3. E3 只有在独立 `GO_E3` 五件套证明 P0/P1 均为 0 后才能正式启动。

## 8. 放行硬门

`GO_E3` 必须同时证明：81/81 修正 bundle 通过；5805 个客户和九城设施的联合主键
闭合；城市柴油成本、节点电价与节点碳强度有运行时消费见证；有限车队 witness
81/81 可行；控制臂跨场服务严格为 0；处理臂双向跨场邻域有独立活动见证；评价预算
精确相等；MIP 状态/gap 完整；独立复算与红队故障注入通过；AppleDouble 为 0；
五件套和全部哈希闭合。任一项缺失即保持 `HOLD_E3`。
