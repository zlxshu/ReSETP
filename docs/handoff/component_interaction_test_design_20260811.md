# 零件交互测试台架设计

日期：2026-08-11  
本轮边界：只做静态分析、台架代码和秒级单测；没有启动真实算例、28 题批跑、排程器重放或正式实验。

## 结论

当前问题不是“每个零件各优化各的”。路线内核提出候选后，仍由完整评价决定教育动作是否接受（`education.py:366-423`）。真正的冲突风险来自三类接缝：

1. 两个零件反复改同一批任务分配、趟序或充电安排，但候选生成阶段用的方向不同；
2. 结构零件一改路线就触发充电重建，可能把刚完成的充电择时覆盖掉；
3. 双目标种群按非支配等级和拥挤度保留候选，但当前局部教育仍按完整成本单指标接受。

第一版可执行的 `2^3` 矩阵选择：**路线内核局部搜索、充电择时、车型换型**。三者现已能从同一提案流中独立开关，且正面覆盖“平均电价代理—实际时段成本—油电车型分配”的已知风险链。整趟指派遗传交叉、完整评价器、注册表内空 Duty 激活许可和单目标种群保持为共同背景，不计入这轮三因子效应。

## 一、零件—决策维度—接受判据

### 1. 路线内核局部搜索

- **改什么**：客户属于哪个实体 Duty、客户访问顺序、同车多趟的客户链，以及 Duty 的空／非空状态。内核返回路线骨架，再解码成完整 Duty 变更（`kernel_proposals.py:191-242,299-329`）。
- **内部方向**：复制内核先按静态路线代理做局部搜索。该代理包含车辆固定成本、车型相关非能源里程、油／电推进成本和碳成本（`kernel_proposals.py:508-569`）；EV 单位成本目前是按车场对全天时段取平均（`:399-418`）。
- **最终接受**：骨架改动先重建受影响 EV 的充电，再由完整增量评价计算；教育层只接受完整罚分成本严格改善的动作（`education.py:203-241,396-423`）。
- **能否撤销别的零件**：能。它可重新分配客户、改变趟链、搬空或启用 Duty；这些结构变化又会重建该 Duty 的未锁定充电安排。

### 2. 整趟指派遗传交叉

- **改什么**：从第二父代取一整趟客户链，追加到第一父代某个接收实体车，再清除重复客户。接收车的身份、车型、车场和动态历史保持不变，受影响充电由完整模型重建（`crossover.py:279-291,394-455`）。
- **最终接受**：同一次交叉产生的可行候选先按完整罚分成本选一个（`integrated_private.py:501-529`）；它不是“必须优于父代才进入”，而是作为子代进入 HGS 种群，再由种群生存与父代选择决定去留（`third_party/setp_hgs_kernel/setp_hgs_kernel/IntegratedGeneticAlgorithm.py:145-170`）。
- **能否撤销别的零件**：能。它可覆盖路线内核或车型换型形成的任务归属，并因结构变化重建充电安排。
- **本台架状态**：当前核心没有独立关闭这个遗传交叉的外部开关。第一版将它固定开启，避免为做台架而修改正在变化的核心文件；因此第一版不估计它自己的主效应。

### 3. 充电修复／充电择时

- **改什么**：充电站、充电量、开始时刻、占用时长，以及途中公共站访问。显式充电候选会替换一个 EV Duty 的完整充电会话和逐趟访问见证（`operators.py:530-569`；候选生成见 `proposals.py:143-192`）。
- **两种身份**：充电修复是结构动作后的可行性构造步骤；充电择时是可独立比较的改进候选。两者不能混成一个“是否调用过”的计数。
- **最终接受**：择时候选与其他教育动作一样，按完整罚分成本严格改善接受（`education.py:396-423`）；完整评价按真实充电时刻计电费和排放。
- **能否撤销别的零件**：能覆盖先前未锁定的充电安排；反过来，任何改变 EV 趟链的路线、交叉或换型动作都会重新构造该 Duty 的充电安排。

### 4. 车型换型

- **改什么**：同一车场的一辆 EV 与一辆 CV 交换完整未锁定任务链。车辆自身的车型字段不变，实际变化的是“哪批任务由哪种车型和哪辆实体车执行”；原充电会话被清空后重建（`operators.py:572-620`）。
- **最终接受**：由 `MechanismProposalEngine` 枚举（`proposals.py:118-141`），再按完整罚分成本严格改善接受。
- **能否撤销别的零件**：能撤销路线内核或整趟交叉形成的车型—任务归属，也会覆盖相关 EV 的未锁定充电安排。

### 5. 消车／车队级重构

- **当前事实更正**：当前工作区没有 `fleet_restructure.py`。同日的专项设计复核认定，现有整 Duty 换型、路线内核搬空和空 Duty 注册表已经能表达“某车清空”及“CV 全日任务交给空 EV”，因此明确停止创建同义模块（`docs/handoff/fleet_restructure_operator_design_20260811.md:8-18`）。
- **现有能力改什么**：任务归属、实体车空／非空状态、实际启用车型数量；一对一整 Duty 换型已有，专门的“一辆来源车多趟原子分散给多辆接收车”生成器未发现（同报告 `:22-34`）。
- **接受判据**：现有路径仍走完整评价和 HGS 接受逻辑。条件性备用设计也要求所有受影响 Duty 联合排程、完整服务后再交现有 HGS 接受，不另设阈值（同报告 `:85-103`）。
- **能否撤销别的零件**：若未来确需专用多接收车动作，它会直接覆盖路线、车型分配和 Duty 启用状态；与现有路线内核、车型换型、空 Duty 激活高度重叠。
- **本台架状态**：不把不存在且已停止施工的模块伪装成可运行因子，也不新增同义 A4。

### 6. 内生车队空 Duty 启用／清空

- **改什么**：注册表固定不变，只改变某个实体车 Duty 是否包含趟。所有已登记 CV／EV 槽位均可显式为空（`fleet_registry.py:12-70`）；开关只允许或拒绝空／非空变化（`:73-109`）。
- **接受判据**：它本身不是候选生成器，也没有独立目标函数；真正的候选来自路线内核、交叉或车型换型，再交各自的完整评价路径。
- **能否撤销别的零件**：开关本身不改解；开启后，其他结构零件可以反复激活或清空 Duty。
- **本台架状态**：第一版固定开启。若把它作为后续因子，必须与真正能产生空／非空变化的结构零件一起解释，不能把“允许变化”误报成“产生了车队重构”。

### 7. 双目标非支配层

- **改什么**：不直接改路线、车型或充电决策；它改变候选的生存、父代选择和跨重启存档。当前候选按成本与总排放做非支配排序和拥挤比较（`bi_objective_population.py:94-219,258-287,399-415`）。
- **接受判据**：种群层使用非支配等级优先、同层拥挤度优先；但当前教育动作仍按完整成本严格改善，保存的“最好可行解”也以成本优先、排放破同值（`:289-306`）。
- **能否撤销别的零件**：不直接撤销决策，但可让某个成本不占优、排放占优的候选存活，并改变后续父代；因此会改变所有生成零件的实际机会分配。
- **本台架状态**：不进入第一版三因子。双目标臂不能只用一个成本数评价；至少要同时比较成本端、排放端和前沿覆盖。把它混入本轮成本交互式会改变“增益”的含义。

## 二、静态冲突判定

这里严格使用用户给出的规则：**改同一批决策变量，且用不同判据接受，就标为静态打架**。另把“同变量、同完整成本判据”标为重叠，交给数据判断是否互补。

| 组合 | 静态判定 | 原因 |
|---|---|---|
| 路线内核 × 充电择时 | **打架** | 路线内核用全天均价静态代理决定骨架方向，结构变更会重建充电；充电择时按真实时刻完整成本接受。两者共同决定 EV 的路线—时刻组合，但判据分辨率不同。 |
| 路线内核 × 车型换型 | **打架** | 两者都改任务属于哪辆／哪种车型；内核内部按静态代理爬坡，换型按完整成本严格改善。 |
| 路线内核 × 整趟交叉 | **打架** | 两者都改客户—实体车—趟归属；内核内部按代理接受移动，交叉子代不要求优于父代而由种群决定去留。 |
| 整趟交叉 × 充电择时 | **打架** | 交叉会重建受影响充电，并允许暂时非改善子代进入种群；择时只接受当前解上的完整成本改善。 |
| 整趟交叉 × 车型换型 | **打架** | 都改任务—车型／实体车归属；交叉走种群生存，换型走局部严格改善。 |
| 充电择时 × 车型换型 | **重叠，未静态判死** | 换型会清空并重建充电，确实可能覆盖择时；但两者最终都按同一完整成本严格改善，是否互补须配对数据回答。 |
| 消车备用动作 × 路线内核／车型换型／空 Duty | **重复风险高** | 当前能力已可搬空与换型；没有轨迹证明“多接收车原子消除”是缺口前，新增模块只是换名重复。 |
| 双目标层 × 各成本型局部零件 | **判据冲突** | 种群保留依据是成本—排放非支配关系，局部教育仍只接受成本改善；同一候选在两层可能得到相反排序。它不是代码错误，但必须单独测。 |
| 空 Duty 许可 × 其他零件 | **不是独立优化器** | 它只控制状态变化是否合法，没有自己的候选与接受目标；不能单独宣称互补或冲突。 |

## 三、第一版 `2^3` 因子设计

三个因子按调用参数给定顺序编码；每个因子取关／开两级，共 8 个组合：

1. 路线内核局部搜索；
2. 充电择时；
3. 车型换型。

共同固定项：同一算例、同一种子、同一冻结初始种群哈希、同一完整评价上下文哈希、同一主 RNG 种子、同一内生车队注册表、同一墙钟预算。运行串行进行。整趟指派交叉、空 Duty 许可和完整评价始终开启，种群保持单目标成本。

共享初始种群每个“算例—种子”只构造一次，然后逐臂复用。因子开关从搜索阶段生效。因此第一版回答的是“在同一共同热启动之后，各零件在搜索阶段的主效应与交互”，不把初始化收益混进零件效应。

## 四、逐种子统计量

对最小化成本，令空集臂成本为 `C0`，组件集合 `S` 的成本为 `C(S)`：

- 组合增益：`G(S) = C0 - C(S)`；正数表示省钱；
- 单件增益：`G({i}) = C0 - C({i})`；
- 用户指定的交互项：`I(S) = G(S) - Σ_i∈S G({i})`。

排放使用相同方向：`E0 - E(S)` 为正表示减排。对两件组合，`I({i,j})` 就是清楚的二件非加性；对三件组合，当前公式得到的是“三件整体超过各单件简单相加的余量”，其中包含两两交互与纯三阶交互，不能另称为纯三阶系数。

`raw_runs.csv` 每行直接保存：基线值、组合增益、单件增益和、交互项、组成该交互项的臂 ID、完成客户数和完成需求量。只要基线、相关单件臂或组合臂缺失，该交互项留空；若服务量不一致，数值保留核账但不进入汇总。

跨种子只报交互项的配对均值、样本标准差和标准误差 `SE = s/√n`，不内置正负阈值或“显著”标签。若以后需要正式显著性检验，检验方法与显著性水平须进入获批正式协议，不由台架暗设。

## 五、为什么同种子配对有辨别力

既有 PRD50 静态三种子结果的成本相对样本标准差为 1.659387%，但其元数据并未严格闭合机器字段；它是噪声量级参考，不是门槛（`solver/reports/carpet_sweep_20260810/noise_and_headroom/report.md:33-43,58`）。

独立比较把“这个种子本来就难／容易”也算进组间波动。同种子配对固定随机流、初始种群、评价上下文和预算后，先在每个种子内部做差：

`Var(A-B) = Var(A) + Var(B) - 2Cov(A,B)`。

两臂受到共同难度影响时通常正相关，协方差项会抵消共同波动，所以配对差方差可小于 1.66% 的原始跨种子成本方差。到底缩小多少不预设，直接由新包中配对差和交互项的样本标准差、标准误差回答。

`--dry-run` 不导入求解器、不创建输出目录，只打印 8 臂接线、共同背景、配对字段和计划身份。去掉 `--dry-run` 才会串行执行真实求解；本轮没有执行。

## 七、EV 路线代理改用实际可用充电窗口：可行性与改动面

### 直接回答

**精确版本可做，但不是“改一个平均数”这么小，也不能保持当前纯静态弧成本的 O(1) 增量前提。** 当前均价在路线内核构造时按车场计算一次（`kernel_proposals.py:399-418`），随后写入静态边成本（`:430-440`）。而“该车实际可用充电窗口”取决于当前 Duty 的趟序、返回时刻、下一趟出发时刻、SOC、其他车占用和局部移动后的新结构；一次路线移动可能同时改变多个窗口及其电价权重。若每次移动都精确重算窗口，代价不再是只看少数增删弧的 O(1)。

### 最低成本的诚实近似

在每次调用路线内核前，从**当前完整 Duty** 提取每辆 EV 此刻的合法充电窗口，计算该窗口内的固定电价＋碳价单位成本，并在这一次局部搜索调用内冻结为该实体车的代理单位成本。这样：

- 一次局部搜索内部的边成本仍是静态的，原有 O(1) 弧增量可以保留；
- 下一次局部搜索前，按新的完整 Duty 重新计算窗口代理；
- 完整评价器仍按真实分钟和真实充电安排拍板，因此近似不会改变最终成本真值；
- 该代理仍不能感知同一次局部搜索中“移动本身创造了新窗口”的二阶效果，必须在报告中称为冻结窗口近似，不能称为精确窗口成本。

### 改动面

最小改动仍涉及 `kernel_proposals.py` 的三个位置：

1. 把现在“每车场一个全天均值”改成“每次 `propose()` 前、每实体车一个冻结窗口值”；
2. 让临时 `ProblemData`／车辆 profile 使用这些值，或确认复制内核支持安全刷新边成本；
3. 把窗口来源与代理值写入 `identity_sha256` 和运行元数据，并补静态窗口、无窗口回退、不同车辆不同窗口和完整评价不变的单测。

如果复制内核不支持原地刷新静态边成本，就需要为每次提案重建临时数据和局部搜索对象；这会保住单次移动的 O(1) 公式，但可能显著增加每轮固定开销。因此建议先做接口级微基准再决定是否实施。本轮按用户边界只做评估，没有修改该代理。

## 八、停止位置

本轮没有运行任何真实算例，没有进入四个活动结果目录，没有修改 China81、三个受保护文件或现有算法核心。台架只提供第一版三因子的可执行组合、配对身份校验、原始交互量计算和无阈值汇总；整趟交叉、空 Duty 与双目标如需作为新因子，应在对应开关语义稳定后扩展，不能由第一版结果代替。
