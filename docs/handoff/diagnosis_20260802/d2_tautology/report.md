# D2：两个最大数字是否属于“放松约束必然改善”

状态：`D2_TAUTOLOGY_REVIEW_COMPLETE`

## 判决

`DECISION`：**论断 T 作为整体不成立，但它命中了一个重要局部问题。**

论断 T 成立的部分是：E3 的联合臂确实只比固定归属臂少一个客户归属锁；在精确最优值层面，联合可行域包含固定归属可行域，所以“最优成本不升”的方向不是发现。E3 的 36.477%只能算这个合成情景下的效应量，不能算“解除限制会更好”这一方向性命题的发现。E3 入口只用 `hard_home_depot_lock` 区分两臂，其余求解参数相同（`baselines/china_e3_e7/e3_scattered_ownership_20260801/run_e3_capacity_rank_aligned.py:155-176`）；当前 TeX 也明确写出一臂禁止客户转交、另一臂解除限制（`docs/paper_v2/paper_main.tex:1380-1387`）。

论断 T 不成立的部分有三项。第一，直接同类文献没有形成“此类增益只能作为情景设定、不得作为结果”的统一规范：目标期刊两篇论文把合作节约作为算例结果，其中 2022 年论文还把显著节约写进数值实验结论；王勇等、Wang 等则把类似嵌套情景的节约明确写入结论或管理启示。第二，E3 的 36.477%幅度不是由可行域包含关系推出的；有限预算启发式也不保证每次联合搜索都优于受限搜索。第三，E6 的四个 singleton 成本和不是一份全局可执行路线：既有拼接核验出现 2 处公共充电站容量冲突，故大联盟可行域并不严格包含“四个 singleton 最优解的笛卡尔积”；这里不存在论断 T 所说的纯粹包含定理（`baselines/china_e3_e7/e3_scattered_ownership_20260801/e3_diag_03_independent_baseline_20260801.md:9-24`）。

两个数字仍然不是两项独立的运营发现。E6 大联盟与 E3 联合臂采用同一客户映射、同一共同初解、同一无归属锁求解结构；逐字段复核 60 个算例—种子单元后，57/60 的最终成本和 `solution_sha256` 完全相同。其余 3 个单元仍是同预算同评价次数下的近邻启发式结果。当前 TeX 已自陈二者来自同类四车场结构且不能相加（`docs/paper_v2/paper_main.tex:1521-1525`）。因此，36.477%与33.018%应判为**同一运营池化杠杆在两个不同分母下的两个情景效应量**；E6 的联盟分配与稳定性结果则是另一件事。

## 一、文献锚定

### 2. 文献判别结论

`FACT`：六篇证据呈现三种用法。饶卫振等（2019）和 Soriano 等把单干—合作差额主要当作分配/公平研究的基准；饶卫振等（2022）把节约列为数值实验结论但把服务质量分配作为主贡献；王勇等（2023）、Wang 等（2023、2024）则把嵌套场景的节约幅度、车辆变化和管理含义明确写入结论。出处分别为期刊第1528–1533页、第2721及2732–2737页、第1134、1138–1139页，以及三篇英文论文 PDF 第2、7–11页、第23、27页、第26、29、31、34页。

`INFERENCE`：同类论文的实际边界不是“情景设定或发现二选一”，而是：**限制是否存在属于情景设定；精确最优值方向通常预期；效应大小、次级指标、条件异质性和分配稳定性可以作为数值发现；仅凭‘放松后更好’通常不足以构成贡献。**

`DECISION`：论断 T 的文献部分判为 `CONTRADICTED_AS_ABSOLUTE_RULE`。它可支持“不要把方向性不等式包装成贡献”，不能支持“类似论文都不把增益作为发现报告”。

## 二、本文两个数字的真实构造

### 1. E3：历史客户归属固定 vs 联合重分

#### 基准从哪里来

`FACT`：所谓“历史”不是 China81 的真实企业历史。入口先取 Soriano 公开 `Uniform_Unbalanced` 人工实例的所有权标签序列，把 China81 客户按 `node_id` 排序后逐一套入标签；再把四组标签按总需求量排序、四个现有车场按原车队载重排序并一一配对，以消除直接映射造成的运力下界不可行（`baselines/china_e3_e7/e3_scattered_ownership_20260801/README.md:3-35`；`baselines/china_e3_e7/e3_scattered_ownership_20260801/run_e3_capacity_rank_aligned.py:31-115`；原始标签见 `baselines/china_e3_e7/e3_scattered_ownership_20260801/source_p_sequences.csv:1-7`）。当前 TeX 也承认其为“构造历史客户组合”（`docs/paper_v2/paper_main.tex:1380-1383`）。

`FACT`：固定归属臂不是一份故意不优化的旧路线。它仍在同一全局模型内优化所有路线和共享充电容量，只禁止客户跨承包商；联合臂只解除这个锁（`baselines/china_e3_e7/e3_scattered_ownership_20260801/run_e3_scattered_ownership.py:128-169`；`docs/paper_v2/paper_main.tex:1384-1387`）。Solomon I1 对每个归属组构造合法路线，且初解必须无跨场服务（`baselines/china_e3_e7/e3_scattered_ownership_20260801/shared_runtime.py:63-124`）。

`INFERENCE`：它是**可执行的合成经营情景**，不是观察到的现实做法。固定承包责任本身有现实制度含义，基准也经过同一求解器充分优化；但“散乱程度”和需求—运力配对是为了实验而构造，仓库没有企业订单历史证明该格局代表现实。把它称为“真实历史表现”没有证据，把它称为“完全为了制造差距的劣质路线”也不符合 runner：需求—运力排序实际是在修复不可行，且基准自身被优化。证据为上述 README 第17–40行、runner 第69–115行和 TeX 第1380–1387行。

### 2. E6：四家 singleton 成本和 vs 四家大联盟

#### singleton 与大联盟到底怎么求

`FACT`：每个 singleton 只保留该成员车场、该成员名下客户和公共充电网络；车辆上限只保留该车场的原始 CV/EV 上限（`baselines/china_e3_e7/e6_contractor_participation_20260801/e6_methods.py:22-80`）。每家从自己的合法 Solomon 共同初解出发，再以同一 HGS—路线池流程优化；多成员联盟从该联盟自己的共同初解出发（`baselines/china_e3_e7/e6_contractor_participation_20260801/run_pilot06_direct_15.py:195-208,843-878`）。因此“单干”确实是四家各自在自己的车场、用自己的客户和车队求解，不是账面历史成本，也不是未经优化的路线。

`FACT`：大联盟没有获得额外车辆。子联盟实例的总 CV/EV 数是成员逐车场上限之和，并保留逐车场上限映射（`e6_methods.py:51-72`）；HGS 适配层及路线池重组均按每个车场—车型上限约束车辆（`baselines/algorithm_prototypes/china81_mechanism_hybrid_20260720/pyvrp_adapter.py:253-317`；`baselines/algorithm_prototypes/china81_mechanism_hybrid_20260720/route_pool_sp.py:649-688`）。正式单元的原始上限例如东莞4+1、佛山4+1、广州9+3、深圳10+3（`formal_e6a_panel_20260801/units/cn-prd-150c-01-V2-LOCATIONS/seed_01/metadata.json:6-26`）。四个 singleton 的可用车辆上限相加与大联盟完全相同；改变的是任一成员车场的车辆可以服务联盟内其他成员客户，不是把车辆实体迁到别的车场。

`FACT`：每个联盟均用100 iterations/view、archive 8、SP 5 s；正式入口锁定该预算（`run_e6a_formal.py:21-26,102-147`）。seed 1 原始账本显示四个 singleton 各32次完整候选评价，大联盟也是32次，且大联盟有108个跨承包商客户（`formal_e6a_panel_20260801/units/cn-prd-150c-01-V2-LOCATIONS/seed_01/raw_runs.csv:1-5,16`）。

`FACT`：33.018%在结算之前已经确定。runner 先求15个联盟的路线成本，再以这些成本构造 Shapley 和核；事后方法只读 `coalition_results`，不回写路线（`run_pilot06_direct_15.py:534-592,926-955`）。当前 TeX 同样写明先求联盟成本再分配，核仁不改变路线、车型和充电（`docs/paper_v2/paper_main.tex:1474-1479`）。因此，33.018%**不是结算机制效应**。

#### 车辆共享能否被单独归因

`FACT`：大联盟处理同时开放客户跨场服务和联盟车队服务能力池化，没有“允许客户重分但禁止跨车场车辆服务”或“只共享车辆、不重分客户”的正式消融臂。大联盟搜索统一设置 `hard_home_depot_lock=False`（`run_pilot06_direct_15.py:264-315`），并对跨承包商客户计数（同文件第368–375、894–916行）。

`INFERENCE`：33.018%来自**运营层的客户—车场重配与车队服务能力池化**，而不是结算；仓库证据不能进一步识别“主要是车辆共享”还是“主要是客户重分”，因为两者在同一开关中同时发生。只读聚合60个正式单元，四个 singleton 实际用车数合计平均30.767辆，大联盟平均29.317辆，每个单元少用1–3辆；这证明车辆利用改善确实发生，但不能单凭车辆数把全部成本差归给物理车辆共享。来源为 `formal_e6a_panel_20260801/units/*/seed_*/raw_runs.csv` 的 `used_cv`、`used_ev` 和 `cross_contractor_customers` 字段。

`FACT`：四个 singleton 最优解成本和不是全局可执行方案。将 singleton 解直接拼接的既有检查发现2处公共站容量冲突（`e3_diag_03_independent_baseline_20260801.md:17-24`）。因此 E6 的33.018%不是严格的“从同一可执行受限解集中放松约束”差额；事实上，忽略跨公司的公共站同时占用使 singleton 分母更低而非更高。正式60个单元中，四家 singleton 成本和均低于对应 E3 全局合法固定归属成本；只读聚合的平均相对差为−5.167%，来源为 E3 六个 `raw_runs.csv` 与 E6 六十个单元 `raw_runs.csv`。

`DECISION`：E6 的33.018%判为 `SCENARIO_EFFECT_SIZE_FROM_OPERATIONAL_POOLING_NOT_SETTLEMENT`。它是合作博弈的标准 singleton 分母下的描述性节约幅度，不是结算发现；但因公共充电容量耦合，它也不是论断 T 所称的严格可行域同义反复。

### 3. 两个数字是否在测同一件事

`FACT`：E6 直接调用 E3 的 `prepare`，复用同一映射与原 China81 车队上限，并把跨场系统费用设为0（`run_pilot06_direct_15.py:133-155`）。E3 联合臂与 E6 大联盟都从同一共同初解出发、无归属锁、使用100 iterations/view、archive 8、SP 5 s 和同一完整评价器（E3 `run_e3_capacity_rank_aligned.py:155-176,300-317`；E6 `run_pilot06_direct_15.py:264-315,864-878`）。

`FACT`：逐单元比较 E3 正式六个成员 `raw_runs.csv` 与 E6 六十个单元 `raw_runs.csv`，57/60 的 E3 联合臂和 E6 大联盟最终成本、`solution_sha256` 完全相同。三个例外均为32次完整候选评价：150c-01 seed 9 为6801.761 vs 6818.967元，seed 10 为6808.777 vs 6825.079元，200c-01 seed 4 为9257.944 vs 9256.909元。两套 treatment 的60单元平均成本仅相差0.541元。

`FACT`：分母不同。E3 用全局合法、共享充电容量受统筹的固定归属解；E6 用四个各自优化 singleton 成本之和。E6 singleton 分母在60/60单元均比 E3 固定归属成本低，因而平均节约率33.018%低于36.477%。当前 TeX 对此已有明示（`docs/paper_v2/paper_main.tex:1521-1525`）。

`DECISION`：**两个数字测的是同一运营杠杆的主体——允许客户跨原承包边界并池化各车场服务能力；它们不是同一个分母下的重复统计，但也不是两次独立机制证据。** E6 真正新增的是15联盟特征函数及其分配稳定性，不是第二次证明运营池化会降本。
