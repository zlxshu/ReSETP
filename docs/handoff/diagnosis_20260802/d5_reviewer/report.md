# D5 敌意审稿报告

任务：从《系统工程理论与实践》审稿人的立场，对论文四个核心数字分别提出一条最强拒稿理由，并列出能够击败该理由的最低证据门槛。

判定状态：`D5_REVIEWER_ATTACK_COMPLETE`

## 1. 算法比较：354胜/46平/5负，配对平均降本1.919%

**(a) 最强拒稿理由。** 五条算法臂不是同批、同停止规则、同计算预算的比较，且整组结果运行于已经被正文车型表替换的旧车型，因此354/46/5和1.919%把算法效应、资源效应与数据版本效应混在一起，不能成立为相对性能证据。

**(b) 仓库内部证据。** `baselines/algorithm_prototypes/china81_vs_opensource_20260727/decision.json` 的 `protocol_disclosure.F_E_M_MV="sealed v7 fixed-iteration archive reuse"`、`protocol_disclosure.O="new NoImprovement(3000) run"`、`archive_wallclock_available=false`、`same_batch_or_same_machine_claim_allowed=false`；同文件给出 `MV_vs_O={win:354,tie:46,loss:5}`、`mean_MV_improvement_percent_vs_O=1.919118015025895`。`raw_runs.json` 中F/E/M/MV的 `budget_rule="V7_FIXED_25000_ITERATIONS_PER_VIEW"`、封存臂 `wallclock_seconds=null`，O为 `budget_rule="NoImprovement(3000)"`；O的405个 `stop_iterations` 实际范围为3001--30509，中位数为4121。任务说明中的“中位约3100”与当前原始账本不符：3000是无改进停止阈值，不是当前405行的中位终止迭代数。`docs/handoff/e2_e7_decision_source_execution_audit_20260801.md:11`确认五臂运行于旧140.41 kWh车型；正文 `docs/paper_v2/paper_main.tex:979-987`却报告EV最大载重1700 kg、电池77.28 kWh，而正文第1296、1301--1303、1327--1329行只披露批次与停止规则，没有把旧车型结果与现行车型主张隔离。

**(c) 目标期刊同类论文实际标准。** 陈婉茹等（2023，DOI: 10.12011/SETP2022-2971）在印刷页3328明确报告统一硬件、最大迭代次数、按规模设置的最大不改进迭代次数及每例10次运行；页3328--3329的表5同时报告BKS偏差和经CPU得分换算的时间；页3331的表8报告算法变体的最优值、平均值、Gap和时间。出处：[期刊官网](https://sysengi.cjoe.ac.cn/CN/10.12011/SETP2022-2971)。该文没有规定所有对照必须同批、同停止规则或同一机器，因此“必须等预算同批次”是**审稿人偏好，非硬标准**；但“把资源条件和数据版本完整披露并给出质量--时间证据”是该同类论文可核验的实际做法。

**(d) 能击败该理由的证据。** 一张基于现行77.28 kWh、1700 kg车型的405配对重跑表：O、F、E、M、MV五臂使用同一批实例、种子、机器和预注册停止预算，逐臂给出最终成本、实际迭代/完整评价次数、CPU或墙钟；表内必须重新给出MV对O的胜/平/负、配对平均降本及配对置信区间或预注册检验结果。只有这张表能把算法差异同资源和车型版本解耦。

**(e) 证据现状与代价。** 不存在。现有包只有旧车型下的非同批五臂结果，且封存四臂无墙钟；仓库没有上述现行车型、统一预算的五臂405配对表。代价档位：`需要重新搜索`。

## 2. 历史客户重分：60配对平均降本36.477%、里程-57.372%、排放-57.307%

**(a) 最强拒稿理由。** 所谓“历史客户归属”不是任何企业历史记录，而是把外部Uniform-Unbalanced标签序列按客户组需求与车场载重容量降序一一对齐的人造反事实，并且平均121.58个客户被换承包商，所以36%--57%的头条效应无法解释为历史客户重分的经验效应。

**(b) 仓库内部证据。** 正文 `docs/paper_v2/paper_main.tex:1381-1387`自陈采用Soriano均匀--不均衡序列并按组需求与车场载重排序匹配；第1413--1418行给出60/60降本以及平均121.58个客户改由其他承包商服务。`baselines/china_e3_e7/e3_scattered_ownership_20260801/formal_panel_solomon_i1_20260801/cn-prd-150c-02-V2-LOCATIONS/metadata.json` 的 `mapping_rule="descending source-label China81 demand aligned one-to-one with descending original depot payload capacity; ties by label/depot_id"`；各成员 `raw_runs.csv` 的 `candidate_family="Uniform_Unbalanced_Capacity_Rank_Aligned"`、`source_family="Uniform_Unbalanced"`。`panel_summary/decision.json` 给出 `paired_units=60`、`joint_cost_lower_pairs=60`、`mean_cost_reduction_pct=36.477268811132966`、`mean_distance_reduction_pct=57.372322731126395`、`mean_emissions_reduction_pct=57.307070334914364`、`mean_joint_cross_contractor_customer_count=121.58333333333333`。正式目录没有 `solutions/`，只在120行聚合账本中保留 `solution_sha256`，无法逐解核验路线、服务车场、车型和排放构成。

**(c) 目标期刊同类论文实际标准。** 陈婉茹等（2023）在印刷页3328把公开MDVRPTW基准与长株潭步步高超市实例数据分开说明，在页3330明确交代仿真算例数据生成及参数来源。出处：[期刊官网](https://sysengi.cjoe.ac.cn/CN/10.12011/SETP2022-2971)。该出处体现的是“真实实例与构造仿真必须分栏、生成机制必须可追溯”的实际做法；没有目标期刊页码规定“历史归属实验必须使用企业真实归属记录”，所以把缺少观测历史直接作为拒稿门槛属于**审稿人偏好，非硬标准**。

**(d) 能击败该理由的证据。** 一份能与订单档案逐行关联的客户级历史归属表，至少含这六个算例每名客户的历史承包商、订单日期/批次和来源标识；用该观测归属重新产生同六算例×10种子的60个固定归属/联合重分配对，输出成本、里程、排放、改派客户数及120份完整可验解，并给出新的三个配对均值。只有观测归属上的重跑结果能击败“人造映射决定头条效应”的攻击。

**(e) 证据现状与代价。** 不存在。仓库只有可追溯的构造序列、映射规则、聚合指标和解哈希，没有客户级历史归属来源，也没有120份完整解。代价档位：`需要重新搜索`。

## 3. 计入碳成本的联合优化：平均减排2.679%、运营成本+0.000045%

**(a) 最强拒稿理由。** 这个数字不能证明“路线--车型--充电联合优化”的减排效应，因为28/30配对的路线和车型完全不变、180/180个车场--解单元的EV名额全部触顶，且正式解根本没有启用论文声称的实体车多趟，观测到的2.679%主要是受限单趟解上的充电时刻重排。

**(b) 仓库内部证据。** `baselines/china_e3_e7/e4_joint_routing_20260801/formal_panel_20260801/decision.json` 的 `COST_PLUS_CARBON_vs_COST_ONLY` 给出 `pair_count=30`、`mean_system_emissions_change_pct=-2.679143431232458`、`mean_operating_cost_change_pct=0.0000448066640604612`、`route_path_changed_pairs=2`、`typed_path_changed_pairs=2`。正文 `docs/paper_v2/paper_main.tex:1448-1450`也明确写出28/30运营成本完全相同且主要调整返场补电时刻。成员 `metadata.json` 的 `fleet_caps_by_depot.D_guangzhou.num_ev=1`、`D_shenzhen.num_ev=2`；`baselines/china_e3_e7/e3e6_gates_01_20260729/gate1_d2a/fleet_caps.csv` 的对应 `num_ev` 字段相同。`docs/handoff/memory/codex_audit_independent_verification_20260802.md:24-28`逐解统计90份正式解在广州、深圳的EV路线数恒为1和2，即180/180触顶；`docs/handoff/e2_e7_decision_source_execution_audit_20260801.md:18-24`记录90份解的 `#T` 次数为0、路线数等于实体车数。正文第261--267、774--776行却把实体车多趟和完整模型复算列为模型与算法能力。

**(c) 目标期刊同类论文实际标准。** 陈婉茹等（2023）在印刷页3332的表10对碳价0--1元/kg按0.1步长报告总成本、能耗成本、碳成本和碳排放，在页3333继续把碳价扩至0--5元/kg并报告电动车占比变化，以阈值和决策变量响应识别碳机制。出处：[期刊官网](https://sysengi.cjoe.ac.cn/CN/10.12011/SETP2022-2971)。这是目标期刊同类机制论文的实际证据标准；没有页码明文要求“联合优化必须有多少配对改变路线/车型”或“必须启用多趟”，这两个门槛属于**审稿人偏好，非硬标准**。

**(d) 能击败该理由的证据。** 在同一30个算例--种子单元、现行完整多趟模型下产生一张三臂配对归因表：纯成本；冻结纯成本路线与车型、仅重新优化充电时刻；放开路线、车型与充电的成本加碳联合优化。表中必须给出后两臂相对纯成本的系统排放、运营成本、路线/车型改变数、实体车多趟数和逐车场EV上限利用率，并直接报告“全联合相对仅充电重排”的增量减排。该增量若稳定为正，且不再由单趟EV天花板机械限定，方能击败本攻击。

**(e) 证据现状与代价。** 不存在。现有30配对可以证明2.679%主要来自充电时移，却没有完整多趟下的三臂归因结果；保存解事后装车诊断也因返场补电接口漏账而停止，不能替代重新优化。代价档位：`需要重新搜索`。

## 4. 四承包商合作：平均节省33.018%，核仁240/240优于单干

**(a) 最强拒稿理由。** 33.018%和240/240完全依赖一套按“每条路线占一辆车”求出的15联盟特征函数，而900份联盟解未启用多趟且1909/1920个联盟车场--解单元的EV名额触顶；一旦使用论文声称的多趟可行域，每个联盟成本、核、核仁和参与结论都可能改变。

**(b) 仓库内部证据。** `baselines/china_e3_e7/e6_contractor_participation_20260801/formal_e6a_panel_20260801/report.md`给出60/60完整场景、900/900联盟结果、平均节省33.018%、范围28.442%--37.145%。`formal_e6s2_nucleolus_20260801/decision.json` 给出 `unit_count=60`、`member_rows=240`、`nucleolus_in_core_units=60`、`minimum_member_gain_over_standalone_cny=265.9977564702458`、`shapley_in_core_units=52`；该目录 `metadata.json` 的 `allocation_method="exact sequential linear-programming nucleolus"`。`docs/handoff/e2_e7_decision_source_execution_audit_20260801.md:100-110`明确记录核仁只是对900行联盟成本账本的后处理、全部900份解未启用多趟且1909/1920触顶。正文第1474--1485、1504行说明结果来自每场15个非空联盟；第1521--1525行还承认E3的36.477%与E6的33.018%来自同类四车场协同结构、只是基准不同，不能当作两次独立节省。

**(c) 目标期刊同类论文实际标准。** 饶卫振等（2019，DOI: 10.12011/1000-6788-2018-1668-18）在印刷页1528对四参与方逐一求解全部 `2^4-1=15` 个联盟的 `c(S)`，再计算核仁；页1531的表3同时报告精确/近似方法的运行时间与偏差，页1532继续用既有算例核对分配解。出处：[期刊官网](https://sysengi.cjoe.ac.cn/CN/10.12011/1000-6788-2018-1668-18)。该文的实际标准是分配结论必须建立在完整、可核验且与所述优化问题一致的联盟特征函数上；没有页码明文讨论多趟车辆，因此“必须在多趟可行域重算”作为一般编辑规则仍属**审稿人偏好，非硬标准**，但本文自身把多趟列为核心可行域后，现有 `c(S)` 与论文模型不一致是可直接核验的内部矛盾。

**(d) 能击败该理由的证据。** 60个场景在完整多趟模型下的900份联盟完整解及独立验解账本；由这900个新 `c(S)` 重新生成每场15联盟表、四家合作节省分布、精确核仁、核约束最大违反量和240个成员相对单干增益，并报告新旧特征函数逐联盟差值。只有当新账本仍给出60/60核内、240/240正增益及可复算的节省均值时，本攻击才被击败。

**(e) 证据现状与代价。** 不存在。仓库有900份单趟联盟解、对应联盟账本及核仁后处理，也有事后多趟装车诊断；后者并未在多趟搜索空间重新求解，且有3份电动车趟间补电冲突，不能替代新特征函数。代价档位：`需要重新搜索`。

## 额外一问：最致命的结构性问题

论文没有一个与总标题和创新清单一致的整体验证对象：第256--272行把动态订单、时变碳、多车场、混合车队、实体车多趟、成员结算和统一算法同时写成核心问题与贡献，第1540--1550行的结论却由三个静态、口径不同的机制实验拼接而成；第1521--1525行又自陈最大的36.477%与33.018%来自同类四车场结构而基准不同，且第1552--1553行把动态订单的正式机制检验留到未来。由此，稿件的中心研究问题没有被任何一个证据单元直接检验，模型、算法与三个头条数字不能组成一条可审查的主命题。
