## 1. 冻结候选：一台机制裁决 ALNS

候选不是把 HGS 与 ALNS 的最终答案事后拼接。官方 HGS-CVRP 只生成一份与
当前确定性起点真正不同的客户顺序；两份起点随后接受同一套路线内车型、
补能和低碳充电精算，再由完整 ReSETP 成本选择搜索盆地。盆地选择不读取
实例名称、规模标签或历史结果。

总完整候选预算记为 `B`。在冻结主门 `B=100` 时：

1. 当前 v7 的全燃油确定性起点是免费初始参考；
2. 官方 HGS 只生成一份替代顺序，映射回完整解后消耗 1 次候选评价；
3. 两份起点各接受相同的路线内车型、补能和低碳时刻精算；局部工作和
   HGS 原生算力单独记账；
4. 完整业务成本选择更合适的原始搜索盆地，平局固定选择当前 ALNS 起点；
5. 若选择 HGS 盆地，剩余 99 次评价交给一次不间断 ALNS，之后做一次
   免费终局机制收口；
6. 若选择当前 ALNS 盆地，先运行 68 次 ALNS，再做一次跨车场责任、
   车型与补能、低碳充电时刻的完整机制校正。校正确实改变解时，其进入
   后续搜索前必须消耗 1 次候选评价，第二段 ALNS 使用 30 次；校正严格
   不动作时不重复计费，第二段 ALNS 使用 31 次；
7. 终局机制收口只作最终参考复算，不进入后续搜索，因此不占搜索候选
   预算；所有局部精算、参考复算和 HGS 原生调用分别报告；
8. 最终输出保留所有已完整计分节点中的最好可行解，任何分支都不得强迫
   算法接受倒退。

主门的候选评价总账必须严格为：

```text
HGS 盆地：1 + 99 = 100
当前 ALNS 盆地且中段有改动：1 + 68 + 1 + 30 = 100
当前 ALNS 盆地且中段无改动：1 + 68 + 0 + 31 = 100
```

第二段是从机制校正点重新开始的短搜索，不得称为继承了第一段温度、
算子权重或随机状态的“连续搜索”。

## 2. 为什么这不是旧失败的重跑

- 不同于 v8：机制校正不是每隔固定次数机械调用；是否分段由完整业务成本
  选择的盆地决定，并且中段结果按 G0 规则计费。
- 不同于 v9：不是从同一起点跑多条短轨迹；两份起点来自当前确定性构造和
  固定官方 HGS-CVRP，客户顺序确实不同。
- 不同于路线池：不拆路线、不做集合拼装，也不把两台算法的终局答案混合。
- 不同于逐候选 normalizer：机制精算只用于一次盆地裁决、一个有条件的
  中段校正和最终收口，不在每个 ALNS 候选上偷偷增加完整评价。
- 不同于普通接力：HGS 起点更差时自动走当前 ALNS 旁路；HGS 起点在完整
  车型、补能和碳成本下更合适时才进入该盆地。

## 3. 小预算和失败关闭

- `B=0`：不调用 HGS、不运行 ALNS、不调用机制，返回当前全燃油锚点。
- `B=1`：只计费比较一份 HGS 替代起点，随后允许终局参考收口。
- `B=2` 或 `B=3`：选择盆地后只运行一段 ALNS，不启动中段校正。
- `B>=4` 且选择当前 ALNS 盆地：才允许两个非空搜索段和一次有条件计费的
  中段校正。
- HGS 安装哈希漂移、非对称距离矩阵、客户覆盖错误、解码后不可行或原生
  调用失败时整臂失败；不得静默退回纯 ALNS。

随机数派生、单线程环境、官方 HGS 提交、动态库哈希、算法源码、参数、
数据和三份受保护文件哈希都必须在成绩生成前写入 `blind_lock.json`。

## 4. D1 只能训练，不能验收

已见 D1 为 donor 03 的 `source_scale=25/50`。它只能用于设计与排错。
在该训练集上，冻结方向的先验信号是：

- 小题完整成本选择当前 ALNS 盆地；
- 大题完整成本选择官方 HGS 顺序盆地；
- 采用严格闭账后的 68/1/30 分段在小题保持此前约 `0.56%` 的 v7 改善；
- HGS 盆地的一段 99 次搜索在大题保持两位数 v7 改善信号。

这些数字不得写成新鲜确认、算法创新结论或论文结果。

## 5. D2 最低成本新鲜开发门

### 5.1 数据

先冻结两组互不重叠、尚未进入三班完整模型生成包的原始来源：
`source_scale=10` 固定使用 04/05/06，`source_scale=15` 固定使用
07/08/09。04--09 原始 Goeke 文件曾进入公开数据可行性登记，因此不能称为
全新原始数据；但仓库审计未发现它们被合成为三班 ReSETP 包或用于当前
候选的设计与成绩。它们统一标记
`NEW_COMPOSITE_BUNDLE_NOT_RAW_PRISTINE`，只能称为“新组合、新生成开发包”。
实例名必须包含实际客户数和车场数。

生成后、运行前只检查：两车场、CV/EV 两类车辆、非恒定碳序列、可移动的
充电时刻和至少一个完整复算可行的跨场服务候选都存在；清单必须保存具体
车辆、充电窗口、客户和替代车场见证，不能用“有两个场”代替。若任一题在成绩生成前不满足，按预先
顺序用 04/05/06 组的 `source_scale=20`、再用 07/08/09 组的
`source_scale=75` 替换；不得看算法成绩
后换题。

### 5.2 同批比较臂

每题、种子 1、`B=100`，按锁定哈希顺序运行：

1. 冻结的机制裁决双盆地 ALNS；
2. 当前 v7；
3. 当前纯 ALNS；
4. 官方 HGS 路线来源加同一 ReSETP 终局完成器；
5. 原装 N-Wouda ALNS 7.0.0 加同一 ReSETP 终局完成器；
6. 去掉机制裁决的消融：用未做车型、补能和低碳精算的原始完整成本选择
   两个盆地，其他预算与候选相同；
7. 去掉有条件中段校正的消融：机制裁决后把剩余 99 次评价交给一段 ALNS，
   最后仍做同一终局收口。

第 4 臂不得简称“官方 HGS 完整模型求解器”。原装 HGS-CVRP 不表达
ReSETP 的车型、充电、碳、公平和动态机制。

### 5.3 预注册通过标准

候选必须：

- 两题均可行，独立复算误差不超过 `1e-7`；
- 两题对 v7、当前纯 ALNS、HGS 路线来源加共同完成器和原装
  N-Wouda ALNS 7.0.0 加共同完成器都严格胜；
- 对四类强对手的两题中位改善分别不低于 `0.5%`；
- 对“去掉机制裁决”消融至少一题严格胜、另一题不退步，两题中位改善
  不低于 `0.5%`；
- 对“去掉中段校正”消融不得有超过 `0.25%` 的倒退；若没有严格增益，
  中段校正只能记为安全但未证贡献，不能写成主要创新；
- 每个带搜索的算法臂完整候选评价严格为 100；HGS 原生调用、路线局部
  代理、机制局部精算、参考复算和总墙钟分别闭账；
- 对每个实例，候选墙钟除以该实例四类强对手墙钟中位数的比值都不超过
  `1.25`；两题比值的中位数也不得超过 `1.25`。

全部满足才判 `GO_SMALL_MULTI_SEED_CONFIRMATION`。两题全部算法成本逐位
相同且完整解签名也相同时，
只能判 `INCONCLUSIVE_SATURATED_SMALL_D2`，候选与阈值保持不变并启用已锁定
且在首次出分前已经生成、验签的 20/75 备用档一次。只同成本但解签名不同
不得写成饱和。有可见提升空间却未过门时，判
`STOP_DUAL_BASIN_MECHANISM_ALNS_D2`；D2 可转训练材料，但不得调参后继续
把同一 D2 称为盲测。

本门通过仍不是阶段二或正式 E2。是否扩大到小规模多种子确认，由本阶段
证据再判断；任何正式实验必须另行取得用户批准。
