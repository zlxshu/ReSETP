# Duty-HGS 动态接线闭合记录（2026-08-07）

## 本轮做了什么

`USER DECISION`：用户批准继续查清正式开跑前的问题，并要求私有算例尽可能统一；只有数学或物理上证明无法统一时，才考虑拆分算例。本轮先闭合动态需求所需的算法接线，再进入统一算例探索；没有替用户确定最终算例、效应门槛或论文结论。

`FACT`：Duty 动态候选现在只重排触发时刻之后的任务；每个未来整日班表必须继续使用继承来的同一辆实体车，完整车队登记、车型和所属车场都不能被候选改写。已经执行或正在执行的路线与锁定充电动作合并回整日执行方案后，再走完整评价。实现见 `baselines/algorithm_prototypes/duty_hgs_20260807/duty_hgs/dynamic.py:30-78,90-170,195-273,329-402`，完整评价接线见 `baselines/algorithm_prototypes/duty_hgs_20260807/duty_hgs/evaluation.py:92-137,183-218,243-283,389-456`。

`FACT`：动态状态必须逐个登记当前可见客户的出现时刻；只要有效实例里出现晚于当前触发时刻的客户，构造候选和评价两处都会拒绝，防止算法偷看未来订单。实现见 `dynamic.py:38-61,125-130,173-192` 与 `evaluation.py:183-218`。

`CORRECTION`：静态方案转入动态日内续排时，首趟同日出车前充电已经生成在第 0 天，但旧证书重建仍可能写成第 -1 天。现已从实际充电动作保留日偏移，重复准备也不会改回旧值。修复见 `solver/src/setp_solver/search/multitrip_schedule.py:1939-2018,2066-2189`，回归测试见 `solver/tests/test_multitrip_schedule.py:301-337`。

`FACT`：真实 JJJ50 动态切点复验覆盖了精确车辆继承、晚到车辆拒绝、零电量且无充电时间拒绝、未到订单拒绝、跨切点非线性充电只记一次、延迟发车保留和实体车固定成本不重不漏。测试见 `baselines/algorithm_prototypes/duty_hgs_20260807/tests/test_dynamic_adapter.py:98-301`。相关原型测试、静态和动态多趟排程测试合计 81 项全部通过；Ruff 与 `git diff --check` 通过。

`ADVISORY`：Claude Opus 5 在两轮审查中先指出订单出现时刻、跨切点充电、发车时刻和车辆固定成本四个核验缺口；补齐源码和反例测试后，其最终意见是三条接线足以进入统一算例探索、没有代码级阻塞。该意见只作为顾问复核，不代替源码、测试或用户拍板。

`BOUNDARY`：本轮只证明动态接线能够忠实继承实时车辆、订单可见性和充电状态，不证明 Duty-HGS 优于 PyVRP，也不证明任何 China81 算例能同时产生五个良好效应。正式算例和正式实验仍未选定。
