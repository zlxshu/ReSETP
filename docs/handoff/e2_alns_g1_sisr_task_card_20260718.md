# Homberger G1 首个算法组件任务卡：SISR 连续客户串移除

状态：`APPROVED_FOR_G1_DEVELOPMENT_ONLY`。用户于 2026-07-18 批准阶段一算法开发，要求以论文和公开实现为依据、优先采用最快最短最低成本验证，非必要不启动全量算例。本任务不授权 Solomon 56 例、中国 81 例或 E1--E7 正式重跑，也不授权论文性能主张。

## 预期目标

验证一个单一、可证伪的机制：在当前连续 ALNS 的破坏算子集合中加入时间窗兼容的 SISR 连续客户串移除，能否比冻结基线更容易产生新的跨路线结构。首轮只移植破坏部分，不同时加入 blink 修复、车队最小化接受准则、SWAP*、种群或路线池，避免无法归因。

## 证据与针对性

项目既有负证据表明，旧路线消除、路线压缩和只重组已有路线块的路线池没有形成稳定收益；当前 `SWAP*-lite` 也只是原位置交换，不是真正 SWAP*。因此首要缺口是“制造此前不存在的连续路线片段与重新插入空间”，而不是继续调整选择器或接受准则。

Christiaens 与 Vanden Berghe（2020）的原始 SISR 论文把相邻客户串移除解释为空间松弛的来源，并在包含时间窗的问题上验证；Google OR-Tools 的公开接口给出建议值 `Lmax=10`、平均移除客户数 `10`、bypass factor `0.01`。Pajerský、Sobotka 与 Rudová（CPAIOR 2026）的 Apache-2.0 VRPTW 开源实现进一步给出车数优先阶段参数：最大串长 `10`、平均移除 `10`、分裂过程选择概率 `0.5`、分裂保留段参数 `0.01`。本任务按其 `vrptw` 分支提交 `857c8eeafd95cbdf8245620486d309369f1aab20` 重新实现，不复制外部源文件。

第二候选暂定为真正 SWAP*，依据 Vidal（2022）及 PyVRP 的 VRPTW 实现路线；它必须为交换客户分别寻找最佳重插位置，并用子序列预处理或粒度邻域控制成本。由于当前框架对完整候选逐个计分，先不施工，避免在首候选尚未给出信号前投入高成本重构。

## 冻结比较合同

- 源码起点：Git `94e776027392118bbf97799e585c7f483d754521`。
- 开发数据：只用已冻结且搜索侧不含 BKS 的 12 个 Homberger 200 客户 bundle。
- 冻结基线：连续 `_run_winner_kernel_loop` 加 `e2_alns_variant_flags()`；即已晋级的 true repair 与 adaptive q，关闭扫描、分阶段外壳、局部搜索、路线池、精英重启及其他实验组件。
- 候选：与基线完全相同，只令 `WinnerKernelConfig.include_sisr_string_removal=True`。
- 目标：先最少车辆、再最短双精度欧氏距离；逐例证明并使用 `big_M > (客户数 + 最大车辆数) × 最大边长`。
- 共同起点：不读取 BKS；按最早截止时间优先、同层按当前位置距离和客户编号破同值，逐路线顺序追加，并逐步检查容量、客户时间窗及返回车场时间。起点必须独立复算可行且不超过 50 辆，基线与候选复用同一序列。
- SISR 参数：最大串长 `10`、平均移除 `10`、分裂概率 `0.5`、保留段停止概率 `0.01`；本轮不得根据结果调整。
- 正式 G1 不变：12 例 × 3 种子 × 1600 次完整候选评价；零失败、平均配对改善为正、至少 24/36 不退化、最差退化不超过 2%、标准化时间开销不超过 25%。

## 最低成本执行梯级

1. 先做纯函数手算与确定性测试，确认每次只删客户、不重复、不跨出原路线片段规则。
2. 跑预算 `0/1/2/5`，要求 `evaluations=candidate_scores=target`、无 `target+1`、保存解独立复算可行。
3. 用预注册的两个异质实例 `C1_2_1` 与 `R1_2_8` 做小预算配对筛查；先用种子 1，若某实例的候选臂中 SISR 调用数为零，则只允许扩到正式 G1 已冻结的种子 1--3，运行顺序交叉，避免固定的冷热缓存顺序。零活性扩种不允许改参数、换实例或按胜负挑种子。
4. 小筛只允许机械淘汰：预算不闭合、结果不可行、某个预注册实例在种子 1--3 上仍然算子零活性，或确定性重放失败即停止。小筛的胜负不能晋级组件，也不能调参数。
5. 只有机械门通过且出现方向性改善信号，才启动完整 G1。若信号不足，保留负结果并先审查真正 SWAP*，不靠扩大预算或调整阈值救活 SISR。

## 边界约束

不得修改 `cost.py`、`check.py`、`search/evaluation.py`、模型约束、物理参数或正式 Solomon runner；SISR 默认关闭。不得读取 Solomon BKS、参考路线或中国正式结果。不得把微型筛查写成性能领先证据。任何新完整解评分必须进入 G0 已闭合的 candidate/reference/repair-delta 三本账。

## 验收标准

代码层要求：新增算子有独立测试、默认算子表无变化、启用时仅多出一个明确命名的算子、同种子重放一致、Ruff/pytest/diff/audit 通过。实验层要求：五记录面齐全，原始任务逐行保存，共同起点哈希一致，预算闭合，独立复算覆盖/容量/时间窗/车辆数/双精度距离一致，并明确给出 `PROMOTE_TO_FULL_G1`、`HOLD_FOR_REVIEW` 或 `KILL_COMPONENT`，不得用模糊表述代替门判。
