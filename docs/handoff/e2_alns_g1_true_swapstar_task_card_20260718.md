# Homberger G1 第二个算法组件任务卡：预算化真正 SWAP*

状态：`APPROVED_FOR_ISOLATED_G1_DEVELOPMENT_ONLY`。用户于 2026-07-18 批准阶段一算法开发，要求所有选择有论文、公开实现和当前瓶颈证据支撑，并以最快、最短、最低成本验证，非必要不启动全量算例。本任务不授权 Solomon 56 例、中国 81 例、E1--E7 正式重跑或论文性能主张。

## 触发证据与单一假设

首候选 SISR 的预登记微门已判 `KILL_COMPONENT_MECHANICAL_FAILURE`：两例、三种子、每臂 40 次完整评价均无可行性或记账失败，但 `R1_2_8` 三个候选臂的 SISR 调用数均为零。按首候选任务卡，不扩大预算、不改参数、不换选择器救活 SISR，转审第二候选。

本任务只检验一个假设：相较现有只在原位置交换客户的 `SWAP*-lite`，真正 SWAP* 为两名跨路线客户分别寻找自由重插位置，能否在相同的 5 次完整评价预算内，从同一个冻结 ALNS 检查点产生更好的可行解。

## 文献与公开实现边界

Vidal（2022，DOI `10.1016/j.cor.2021.105643`）定义了带自由重插的 SWAP*，并用预处理的三个最佳插入位置降低搜索代价。PyVRP v0.13.4 的 MIT 许可实现固定核验提交为 `18815548d04a90a0e5eea2a0bed53a81ea9d2d49`；其 `SwapStar` 明确保存每个“路线×客户”的三个最佳插入点，并以默认 `overlap_tolerance=0.05` 过滤角度不重叠的路线对。Wouda、Lan 与 Kool（2024，DOI `10.1287/ijoc.2023.0055`）说明 PyVRP 面向包含时间窗在内的富 VRP。

项目实现只借用邻域定义、三个最佳位置和路线重叠思想，重新编写 Python 代码，不复制外部 C++。所有候选仍经过 ReSETP 的统一可行性检查和 G0 完整候选计费边界；PyVRP/HGS 的内部目标、惩罚、迭代数和结果不得作为本项目证据。

## 冻结实现合同

- 只处理同车场、同车型的两条非空路线；跨车场责任、车型切换、SOC与充电机制留给后续复杂模型开发集。
- 路线对角度重叠阈值固定为 `0.05`；每个客户在目标路线删去对换客户后保留距离增量最小的三个插入位置。
- 先做容量过滤，再按双精度距离增量排序；只把距离代理严格下降的候选交给完整可行性与目标评分。
- 每个交给搜索选择的完整解必须调用 `score_search_candidate(..., channel="true_swapstar")`，进入 G0 的 candidate 账；预算耗尽前硬停止。
- 算子默认不接入 winner kernel。本轮先完成隔离实现、功能测试和边际价值门；通过后才另行登记正式接入点。

## 最低成本验证

1. 人工两路线微例证明自由重插位置可不同于原位置交换，且同一输入确定性一致。
2. 完整评价预算 `0/1/2/5` 分别运行，要求无 `target+1`、预算 0 不进入评分器、最终解独立可行。
3. 性能微门复用 `homberger_g1_sisr_micro_v2_20260718` 中未启用 SISR 的六个冻结 baseline-B40 解，不重复消耗前 40 次搜索。每个检查点分成：
   - `baseline_continue`：当前冻结 ALNS 再运行 5 次完整评价；
   - `candidate_true_swapstar`：真正 SWAP* 最多运行 5 次完整评价。
4. 实例固定为 `C1_2_1`、`R1_2_8`，种子固定为 1--3，共 6 个配对；两臂共同起点哈希必须一致。
5. 只有零失败、两类实例均有 SWAP* 完整评价、平均配对改善为正、至少 4/6 不退化、最差退化不超过 2%、标准化平均时间开销不超过 25%，才允许提交“接入完整 G1”的下一门。微门通过不等于 G1 通过。
