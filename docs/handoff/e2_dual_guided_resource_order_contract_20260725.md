# E2 强 HGS 深化失败复盘与唯一候选预登记

- 日期：2026-07-25
- 编号：`E2-DUAL-GUIDED-RESOURCE-ORDER-024`
- 状态：`REVIEW_COMPLETE__PREREGISTERED_G0__NO_IMPLEMENTATION_OR_RUN`
- 研发名称：双价格引导的资源耦合次序重构

## 1. 本轮结论

`HGS-ILS-XD` 已冻结，不调参数、不换题、不重跑。现有证据不支持再接一套通用
ILS、VNS 或 ALNS。唯一仍值得做最低成本证伪的是：

1. 先从现有路线池的线性松弛中读取客户覆盖、车场车型上限和共享充电时隙的对偶价格，
   找出当前解中最稀缺、最值得被重新安排的资源；
2. 只选择少量共同占用这些稀缺资源的路线对；
3. 对路线对运行带可移动分界的 Balas--Simonetti 型动态规划，同时改变两条路线内部
   客户次序和客户归属，而不是只移动原有分界；
4. 只把固定数量的最优结构候选交给共同完成器、`check_solution` 和
   `exact_china81_score`；严格改善后才接受，并把新路线放回路线池。

这是一项候选机制，不是已经成立的创新、性能结论或 SOTA 声明。它若不能在下述一次
小门中直接深化强 HGS 解，立即停止。

## 2. 当前失败的精确含义

### 2.1 最新 HGS→ILS 结果

`hgs_ils_cross_domain_20260725/g0_preflight_v1` 的六任务均按登记由 6 workers
完成，源码和预算无漂移，独立复算闭合。结果为：

- 完整模型接受的新解仅 2/6；
- 冷启动可行 1/3；
- 出现封存路线池外路线 2/3；
- 热启动改变客户相邻关系 1/3；
- 热启动严格改善 HGS-M 起点 0/3；
- 热启动优于同题冷启动 0/3。

珠三角 50 客户冷启动 ILS 能把较弱起点从 2753.4450635084863 降到
2617.3803933189574，但仍弱于 HGS-M 起点 2512.9322491171747；成渝 100 客户
唯一热启动可行新候选反而比起点高 12.679465311062813。

因此 ILS 不是完全没有搜索能力；它能修弱解，却不能深化强 HGS 解。最符合证据的解释
是两者主要搜索相近的普通搬移、交换和跨路线尾段邻域，强 HGS 已把这些区域挖深。
不得把失败归因于 128 次迭代、8 次完整评价或参数不足后继续救援。

## 3. 一手文献给出的设计依据与警告

1. Zhao、Archetti、Pham 和 Vidal 的 IRP 工作把针对耦合决策设计的动态规划大邻域
   嵌入 HGS，而不是再套一套通用算法；其关键是一次最优地重排一组相互关联的决策。
   DOI：`10.1016/j.ejor.2025.11.021`。
2. Dumez、Tilk、Irnich、Lehuédé 和 Péton 将 Balas--Simonetti 指数规模次序邻域
   以动态规划方式用于含时间窗和共享资源约束的广义 VRP，并与路线池重组配合。
   其消融也给出重要反例：当跨路线共享约束很多时，该精确邻域单独使用可能太慢，
   且只在路线长度约 6--20 时较有利。DOI：`10.1016/j.ejtl.2021.100040`。
3. Desaulniers、Errico、Irnich 和 Schneider 的 EVRPTW 精确算法证明，对偶价格和
   资源标签可以引导生成新的电动车可行路线；但完整精确法的规模有限，因此这里只借用
   “对偶价格指向缺失路线”的原则，不移植完整 branch-price-and-cut。
   DOI：`10.1287/opre.2016.1535`。
4. Froger、Jabali、Mendoza 和 Laporte 对有限充电桩 EVRP 采用路线生成器与全局组装器
   交互，说明共享充电容量不能只在路线局部处理；但其路线生成器仍是 ILS，因此本项目
   不复刻该 ILS，而让组装器的资源价格直接指导次序生成。DOI：
   `10.1287/trsc.2021.1111`。
5. Bruglieri、Pezzella、Pisacane 和 Suraci 的随机核搜索表明，在现实能耗 EVRPTW
   中只开放一小部分弧并求受限模型可以改变客户次序且控制规模；它支持“小核、受限
   精确重排”，不支持对 China81 直接运行全规模 MILP。DOI：
   `10.1016/j.cor.2023.106261`。

因此，本候选不是“动态规划一定有效”的乐观推断。文献同时给出正面机制和明确风险：
共享资源会使状态变大、精确邻域可能得不偿失。G0 必须同时验证质量、可行性和计算
代价。

## 4. 候选机制合同

### 4.1 对偶价格只用于选择和排序

在不运行新 HGS 的前提下，从该题封存 v7 路线池建立与现有组装器一致的线性松弛：
客户恰好覆盖一次，分车场分车型有限车队，逐半小时共享充电时隙。记录客户、车队和
充电时隙约束的对偶价格。对偶价格不得改写完整目标、成本参数或可行性定义。

客户覆盖对偶价格只用于复算每列的标准约化成本，不参与路线对排序，因为一个路线对
重排前后的客户并集不变，把客户价格相加不能区分两个次序。对每个“上限型”资源
约束 \(g\)（分车场分车型车位或共享充电时隙），固定用 HiGHS 返回的边际值
\(m_g\) 定义稀缺价格 \(s_g=\max(0,-m_g)\)。令 \(u_{rg}\) 为封存完整路线 \(r\)
占用资源 \(g\) 的数量，则无序路线对 \(\{r,q\}\) 的压力分数固定为

\[
P(r,q)=\sum_g s_g\{u_{rg}+u_{qg}+\min(u_{rg},u_{qg})\}.
\]

前两项偏向占用高价资源的路线，第三项额外强调两条路线对同一稀缺资源的直接竞争。
按 \(P(r,q)\) 从大到小只处理前两个不同路线对；并列按两条规范路线签名组成的字典序
排序。线性松弛固定使用 SciPy/HiGHS 当前封存版本和双单纯形法；若没有可用对偶值、
结果非最优或对偶复算不闭合，工程门直接 HALT，不用零值或经验权重替代。不得根据
候选完整成本换路线对。

### 4.2 次序与分界必须同时开放

每个路线对考虑两个拼接方向，动态规划位移上限固定 `k=4`。状态中必须包含客户覆盖、
载重和时间窗必要信息，并允许路线分界移动。动态规划内部排序目标固定使用 v7 的
`mechanism_ev` 路线代理成本之和；对偶价格只负责选择需要重排的路线对，不得直接
混入论文完整成本。输出必须至少改变一条路线内部客户相邻关系；只换车型、充电安排
或切分位置不算新结构。

动态规划最多保留四个不同结构候选/方向，共最多 16 个结构候选/题。完整完成只在动态
规划结束后进行；每个结构候选最多一次完整完成和精确评分。不得用重复候选、失败候选
或原解回放补足 16 次。

### 4.3 完整资源裁判

所有候选必须使用与 v7 相同的共同完成器，联合决定车场、车型、有限车队、充电地点、
充电量和充电时刻，并绑定同一城市、日期、半小时时段电价、碳强度和分城市柴油价。
随后运行完整 `check_solution` 与 `exact_china81_score`。只接受严格改善，容差
`1e-9`；否则返回原封存解。

新路线可在 G0 统计中保存，但 G0 不运行最终 SP 重组，避免把“次序生成是否有直接
价值”和“路线池组合是否有价值”混在一起。只有 G0 通过，后续同预算门才可检验
HGS、独立迭代版次序重构以及 HGS+次序重构。

### 5.2 预算与并行

- 六题各一个独立任务，最多 16 次不同完整候选评价；
- 每任务动态规划总状态上限 100000，墙钟 90 秒仅作安全上限；
- 六任务默认 6 workers，每进程及底层数值库锁 1 线程；
- 启动前零搜索资源门要求系统可用内存不低于 10%，六进程预计峰值合计不超过
  4096 MiB；不满足才回退 3 workers并记录原因；
- 运行前冻结题、witness、路线池、算法源码、完成器、检查器、成本、价格和碳强度
  文件哈希；运行后做独立 witness 复放。

该门最多 96 次完整候选评价，不重跑 HGS，不扫参数，不运行公开 benchmark。

### 5.3 通过与硬停止线

必须同时满足：

1. 六个起点和六个输出均完整可行，记录成本与独立复算逐位一致；
2. 至少 4/6 个强 HGS 起点被严格改善；
3. 至少 2/6 题的改善不低于 0.05%；
4. 至少 3 个被接受的解包含原 v7 五种子路线池外的新客户相邻关系；
5. 所有改善均由“内部次序改变 + 路线分界或归属改变”的候选产生；
6. 每题完整评价不超过 16、状态不超过 100000，无源码或输入漂移；
7. 算子墙钟中位数不超过对应封存 HGS-M 单次 CPU 的 25%，最大不超过 40%；
8. 六任务均按资源门选定的并发完成，异常为 0。
