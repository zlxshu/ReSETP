# E2 可行性引导大邻域搜索最低成本合同

日期：2026-07-25  
编号：`E2-FEASIBILITY-GUIDED-VNS-001`  
状态：`USER_APPROVED__G0_AND_DIRECT_BEHAVIOR_GATE_ONLY`

## 1. 设计依据

`TAILORED-DP-VNS` 首次行为门已停止。停止后的零目标诊断证明，强解附近并非没有
可行移动；失败来自“先按距离截短名单、后检查硬约束”。因此本轮不是扩大原短名单，
而是另立 `FEASIBILITY-GUIDED-EJECTION-VNS`（研发名）：移动在生成时就通过本题
路线资源和联合分配检查，完整模型只评价已经可完成的候选。

该算法的独立职责是深度改善一个完整可行解；未来若通过独立性能门，HGS 负责全局
种群探索，本算法负责硬约束感知的大邻域强化，改善后的完整解再返回 HGS。当前不
授权设计合作调度，不授权论文名称或 `1+1>2` 主张。

## 2. 固定算法骨架

新代码只允许放在
`baselines/algorithm_prototypes/feasibility_guided_ejection_vns_20260725/`，不得
修改首次失败候选或旧 `COOP-HGS-RR`。

每轮按固定次序执行五类邻域：

1. 可行性引导的单客户重插；
2. 可行性引导的客户交换；
3. 可行性引导的路线内 2-opt；
4. 可行性引导的跨路线 2-opt*；
5. 资源紧张连续块弹出—逐客户束搜索重建。

前四类移动先生成结构，再立即对受影响路线建立可行的车场—车型—充电选项；只有
存在联合有限车队和共享充电桩可行分配的结构，才进入候选集合。候选的预排序使用
同一条路线局部完整成本之和，不再使用纯距离作为唯一裁剪依据。连续块重建不能把
整个块机械插到一个位置；它必须逐客户尝试可行插入，并以固定束宽保留部分重建状态，
最终恢复每个客户恰好一次后再进入完整评价。

固定资源上限：

- 每个局部邻域最多检查 512 个不同结构，但按可行性检查结果选候选，不按前 10 个
  距离候选截断；
- 每个局部邻域最多保留 12 个联合分配可行结构；
- 连续块宽度为 2--4，最多使用 8 个结果盲起始块，每层束宽 8；
- 每个结构最多完整评价 2 个联合分配；
- 每题完整评价总上限 120；
- 严格改善容差 `1e-9`，接受该邻域完整评价后的最好严格改善解，随后从第一个邻域
  重新开始；不接受较差解，不随机改变邻域次序。

“最多检查 512 个结构”是防止生成器失控的安全上限，不是距离短名单。若达到上限仍
没有足够可行结构，必须如实记录，不得补随机候选或扩大上限。

## 3. 新开发输入的结果盲选择

新开发题从 v7 China81 的实例 ID 中先按固定结构层选择，不读取对应目标值：

- 京津冀 50 客户；
- 成渝 100 客户；
- 珠三角 200 客户。

每层对完整 `instance_id` 取 SHA-256，选择字典序最小的摘要。冻结结果为：

- `cn-jjj-50c-02-V2-LOCATIONS`；
- `cn-cy-100c-01-V2-LOCATIONS`；
- `cn-prd-200c-02-V2-LOCATIONS`。

题目冻结后，起点固定为该题 v7 五种子中 `MV-HGS-SP` 完整成本最小的封存 witness；
这只用于给独立算法设置最强已存起点，不改变实例选择。固定起点分别为 seed 1、
seed 3 和 seed 1。执行登记必须绑定题目文件、witness、对应任务行、算法源码、
解码器、检查器、成本与价格文件的 SHA-256。

## 4. G0：零完整目标工程门

G0 不读取候选完整目标值，也不运行 HGS、MIP 或正式搜索。必须证明：

1. 三个封存起点均由直接检查与精确复算确认零违约、成本逐位一致；
2. 五类邻域在三题合计均产生至少一个不同结构；
3. 前四类邻域在三题合计均找到至少一个联合分配可行结构；
4. 连续块重建至少完成一个覆盖不变、联合分配可行的完整结构；
5. 所有进入候选集合的结构都已有完整车场、车型和充电可行路径；
6. G0 的完整目标评价计数为 0；
7. 单元测试包含“前若干距离候选不可行、后续候选可行时不能被提前截掉”的回归。

任一项失败即判 `HALT_FGE_VNS_G0_WIRING_OR_FEASIBILITY`，不得启动行为门。

## 5. 保存强解直接改善门

G0 通过并冻结源码与输入后，三题可用 3 个独立单线程进程并行。行为门只运行新的
独立算法，不重跑 HGS。

必须同时满足：

1. 三个输出全部零违约，独立复算成本与记录值逐位一致；
2. 至少 2/3 个强起点被严格改善；
3. 至少一次严格改善来自 2-opt* 或连续块弹出—束搜索重建；
4. 五类邻域均被实际访问，完整评价总数逐题不超过 120；
5. 不完整候选进入完整评价数为 0，重复完整评价比例不高于 20%；
6. 每题报告结构检查数、可行结构数、完整评价数、各邻域改善次数、CPU、墙钟和峰值
   内存。

通过判 `PASS_FGE_VNS_DIRECT_IMPROVEMENT_GATE`；否则判
`STOP_FGE_VNS_NO_DIRECT_IMPROVEMENT_SIGNAL`。无论通过或停止，都不得在这三题上
调参、换 witness、换题、补种子或降低门槛。

通过只授权另立未见题的 A/B/A+B 小规模盲测；不授权 E3、正式 China81、公开
benchmark、论文优越性、BKS 或 SOTA。

## 7. 行为门打包中断与零搜索恢复

三道行为门计算全部结束、轨迹与最终 witness 全部写盘后，runner 在把内存汇总写入
`raw_runs.csv` 时因结果字典多出 `improvements_by_neighborhood` 字段而触发
`ValueError`。中断发生在算法结束之后、正式判定生成之前；现场版本化保存为
`direct_improvement_gate_v1_abort_packaging/`。不得重跑搜索，也不得读取目标结果后
修改算法或门槛。

在读取三题目标结果前，批准一次零搜索恢复：绑定原登记、三份轨迹、三份最终 witness
及打包异常现场的 SHA-256；只从封存起点和最终 witness 运行直接检查与精确复算，
从轨迹账本恢复完整评价数、重复数、邻域访问和改善来源，然后按本合同原性能门生成
v2 五件套。由于 v1 未在轨迹文件保存每任务用时和峰值内存，v2 必须明确记为
`NOT_RECOVERABLE_FROM_PERSISTED_ARTIFACTS`，不得伪造或把文件时间当作算法用时。
这两项不是本门 PASS 的阈值，但其缺失必须进入报告，并在未来 A/B/A+B 新门重新完整
记录。恢复器不得导入或调用搜索入口，搜索次数必须为 0。
