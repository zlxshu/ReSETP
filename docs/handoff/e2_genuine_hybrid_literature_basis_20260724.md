## 2. 文献共同指向的高性能结构

这些工作虽然问题不同，但共同点高度一致：

1. HGS 继续负责种群多样性、交叉和中小邻域局部改进；
2. 第二种搜索负责一次重构一整段或一整类耦合决策；
3. 给定上层客户顺序后，使用专门的快速解码、动态规划或路线评价函数完成下层决策；
4. 大多数廉价尝试先用安全下界和支配规则筛掉，只有少量候选进入完整核算；
5. 改进解重新进入种群，后续交叉继续利用，而不是只在终点比较；
6. HGS、第二种独立算法和二者混合体必须分别运行，才能证明混合增益。

因此，ReSETP 的性能核心不应是继续增加 HGS 视角，而应是开发自己的
“车场—车型—充电—时间”快速解码器。

## 3. ReSETP 的专用解码状态

对一条给定客户序列，解码状态至少包含：

- 当前车场与候选返场车场；
- 当前车辆类型、同车场剩余燃油车/电动车数量；
- 当前节点、时刻、载重、电池电量；
- 已产生的距离成本、固定车辆成本、燃油/电力成本和碳成本；
- 当前城市、日期与半小时档位；
- 已执行动态前缀的固定状态；
- 对尚未访问客户时间窗的可行余量。

支配规则必须保证：若两个状态到达同一客户位置，且一个状态在时间、剩余载重、剩余
电量、车队占用和累计成本上均不优，则可安全删除。跨城市、跨日期、跨车场或不同动态
状态的解码结果不得共用缓存。

为控制规模，第一版不做全局穷举。固定采用：

1. 上层 HGS 或破坏—修复给出有限客户序列；
2. 每条路线只保留少量不被支配的车场—车型状态；
3. EV 状态在价格/碳强度档位边界、最早可行发车和时间窗关键点生成充电/发车候选；
4. 用完整模型复核最终短名单；
5. 任一完整复核都进入统一预算账本。

## 4. 创新主张边界

若实现和实验通过，算法创新可以表述为：

“针对多车场燃油—电动混合车队在分时电价、分时碳强度和动态状态下的联合配送决策，
构建双层解表示与车场—车型—充电—时间快速解码，并把机制感知破坏—修复搜索与 HGS
进行双向协同。”

不能表述为：

- “首次把 HGS 与 ALNS 结合”；
- “三个 HGS 视角构成三算法融合”；
- “加入 MIP 即形成混合智能算法”；
- “使用更多算子所以更优”；
- 未通过公开资格门时宣称 BKS/SOTA。

## 5. 后续文献补充重点

继续检索只围绕当前实现缺口，不做泛读：

- 非线性/部分充电的固定路线快速评价与支配规则；
- 分时电价与分时碳强度联合充电调度；
- 多车场异质车队的跨场专用邻域；
- 动态 VRP 中已执行前缀的状态继承；
- 2025--2026 年公开 BKS 和可复现实验预算，用于最终 SOTA 资格核对。
