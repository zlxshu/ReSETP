## 1. 陈雨蝶等（2025）的实际算法，不按二手概括

原文算法为带变邻域搜索和动态灾变机制的多种群遗传算法 `MPGA-VNS`。其结构是：

1. 自然数染色体直接表示全部客户的访问次序；解码按载重划分小路线，再按就近原则
   分配出发/返回配送中心。
2. 一个主种群和多个属种群分别做轮盘赌、精英保留、改进两点交叉和两点互换变异。
3. 最好解连续不变达到阈值时，用随进度递减的灾变规模替换较差个体。
4. 主群与属群双向迁移优良个体。
5. 当遗传进度达到 `gen_GA_max × Ps` 且 GA 最好解改变时，以当前最好解为起点启动
   VNS。其五种路线内动作是 insert-1/2/3、exchange、reverse；四种路线间动作是
   shift(1,0)、shift(1,1)、swap、crossover。原文仿真实验取 `Ps=80%`。
6. 到 GA 最大代数时终止。VNS 是 GA 后期触发的深度局部优化，不是与 GA 独立并行
   后双向交换的第二套完整算法。

因此，陈文中客户次序会被遗传交叉、互换变异和 VNS 的全部路线内/间动作直接改变。
其 VNS 单独对照从随机解开始，而混合体的 VNS 从 MPGA 后期优良解开始；论文以时间
为横轴比较 GA、VNS、混合体。该设计的叙事逻辑是“全局种群搜索提供高质量起点，
后期 VNS 做深度局部搜索”，不是“两个独立 SOTA 求解器通过精确交换形成协同”。

原文按染色体解码、适应度和邻域可行性处理模型约束；没有另设独立精确评分器，没有
把代理目标候选逐个送回完整物理模型复核，也没有集合划分/路线池重组。

## 2. 与当前 `HGS-ILS-XD` 逐项比较

| 比较项 | 陈雨蝶等 `MPGA-VNS` | 当前 `HGS-ILS-XD` | 判断 |
|---|---|---|---|
| 主搜索结构 | 多个 GA 种群并行进化，后期对当前最好解触发 VNS | A=真实 HGS，B=独立 ILS；先做并行单算法对照，再检验 HGS 完整解顺序交给 ILS 深化 | 结构相近处是“强起点交给第二算法”，不能把顺序交接本身称为新 |
| A、B 能否独立运行 | GA、VNS可分别运行，但混合体中 VNS 是 GA 的后期局部阶段 | A、B 均为完整独立求解器；必须有 A/B/A+B 同预算对照 | 本项目对“独立组成算法”要求更严格 |
| 客户次序在哪里改变 | 交叉、互换变异、5种路线内和4种路线间 VNS | HGS 交叉/教育与 ILS 扰动/局部搜索各自改变；中点 MIP 不负责创造次序 | 两者都真正改变次序；区别在创造者和交换方式 |
| 完整评价时点 | 染色体解码后直接以模型总成本倒数为适应度；硬时间窗不满足适应度为0 | 搜索用机制代理；最多8个候选离线经共同完成、全局检查、精确评分；正式门按完整评价次数计预算 | 本项目的完整裁判更显式，但代价必须计入 |
| 路线池 | 无 | 中点和末尾拟用有限车队、共享桩约束的限时路线池 MIP | 与陈文不同；但路线池本身已有国际先例 |
| 信息流 | 多种群之间迁移；GA 单向给 VNS 高质量起点 | 基础门是 HGS 单向把完整可行解交给独立 ILS；只有该门通过后才考虑受限核验交换 | 当前基础结构与陈文同属顺序深化，差异主要在独立算法身份、完整核验和资源语义 |
| 资源处理 | 多中心、时变路网、多产品、多隔间、同时送取货、冷链和碳交易 | 多车场、燃油/电动车、有限车队、充电曲线、共享桩、城市/日期/半小时电价和碳、分城市柴油价 | 两者问题机制不同，不能直接移植可行性规则 |
| 计算公平 | 原文三算法迭代上限不同，以时间曲线和十次统计披露 | 主比较强制 A-long48/B-long48/`A→B`48 同完整评价预算，并披露墙钟 | 本项目门槛更严格；尚无结果 |

## 3. 与国际近邻方法的重合和差异

### Hiermann 等（2019）

该文针对燃油、插电混动和纯电混合车队，采用 HGA + 局部/大邻域搜索改变客户次序，
分层路线评价决定充电与能源使用，再用集合划分重组历史路线。它是当前候选最接近的
国际架构：次序搜索、丰富路线评价和路线池三层都已有先例。因此
“HGS/GA + 完整路线评价 + SP”不能作为本项目的新颖性。

本项目当前基础门先检验：独立 ILS 接手 HGS 的完整可行解后，能否在 China81
地域—时间—能源—碳—有限车队—共享桩语义下继续产生可验证改善，并按完整评价次数
与独立长跑、独立并行取优公平比较。该顺序交接有文献先例，不构成新颖性；只有基础门
通过后，另行提出并验证的资源耦合机制才可能形成研究贡献。

来源：Hiermann, Hartl, Puchinger, Vidal (2019), EJOR,
DOI `10.1016/j.ejor.2018.06.025`。

### Zheng、Liu 与 Ong（2024）

其 EVRP-TW-SPD 混合模因搜索在非电对应问题空间中暂时忽略电量约束以改变客户次序，
再通过充电站插入恢复完整 EV 可行性；无法恢复就停止。它与本项目“宽松搜索空间造
次序、完整模型恢复”的思想有明显重合。区别是本项目没有明确删除电量约束，而是让
ILS 在统一路线代理上搜索，再由 China81 完成器恢复车型与充电；若论文使用“跨域”
表述，必须引用并清楚说明这种重合，不能把已有思想重新命名为新。

来源：Zheng, Liu, Ong (2024), arXiv `2410.19580`。

### Zhao、Archetti、Pham 与 Vidal（2025）

该文在 HGS 内加入一个针对库存路径耦合关系定制的大邻域：一次最优移除和重插同一
零售商跨期全部访问，并用预处理与动态规划加速。它的关键不是“多加一个算法”，而是
把问题中最强耦合决定直接定义为一个可计算动作。

相比之下，当前 B 仍是通用 ILS；真正针对 China81 的部分主要在完成和完整评分，
而不是 ILS 的动作本身。因此当前候选在“问题定制搜索动作”上弱于该类国际工作。
若 G0/G1 连顺序交接的直接增益都不能证明，本候选不能仅凭组件齐全声称创新；即使
顺序交接通过，后续也仍须为本题的资源耦合提出并验证一个独特机制。

来源：Zhao, Archetti, Pham, Vidal (2025), arXiv `2506.03172`。

### AILS-II 与 PyVRP ILS

AILS-II 证明独立 ILS 在大规模经典 CVRP 上可以很强；仓库冻结的 PyVRP 0.13.4 ILS
也是真实独立算法，而不是 HGS 改名。但两者的公开证据都不覆盖 China81 的时间窗、
多车场、油电混合、有限车队和共享充电资源。它只能证明 B 的算法身份，不能证明 B
在本题上强，也不能自动构成新颖混合。

来源：Máximo, Cordeau, Nascimento (2024), INFORMS JOC,
DOI `10.1287/ijoc.2023.0106`；PyVRP 0.13.4 冻结源码。

## 4. 严格结论

`HGS-ILS-XD` 不能再以“双向交换”来回避用户真正提出的假设。陈文是多种群 GA
后期把优良解交给 VNS，本项目的基础门是 HGS 把完整可行解交给一套可独立运行的
ILS。两者都属于顺序深化，区别在于 B 是否为完整独立算法、是否经过 China81 完整
核验，以及是否按完整评价次数建立公平对照。这些区别仍不等于“已经创新”，更不等于
“更强”。

相对国际方法，HGS/ILS、完整路线评价、跨宽松空间恢复和路线池重组分别都有明确先例。
当前 G0/G1 只负责验证顺序交接是否有真实增量价值。若 G0 不能证明 ILS 接手 HGS
完整解后产生新的完整可行次序并继续改善，或 G1 不能在同预算下证明 `A→B` 至少两题
严格胜过较强单算法且零负，就应停止候选；不得把它包装为“强强联合”。只有这个基础
通过，才允许以既有失败和文献为依据另立一个问题定制机制，并单独证明其增益。

## 5. 是否追加陈文 VNS 动作

不追加。PyVRP 0.13.4 的官方默认 ILS 已启用 `Exchange10/20/11/21/22`、
`SwapTails` 和 `RelocateWithDepot`；源码还提供 `Exchange30--33`，但默认参数未启用。
这些动作已经覆盖陈文多数单客户、双客户搬移、交换与跨路线尾段交换。缺少的显式
三客户搬移和连续段反转也不能直接移植：本仓库此前的 `SEG-GEN-01`、
`TAILORED-DP-VNS` 和 `FEASIBILITY-GUIDED-EJECTION-VNS` 已分别检验过连续段搬移、
反转、2-opt/2-opt* 和资源修复，其中出现过无改善、完整可行性拒绝或 3.298--4.694
倍用时问题。

因此，把陈文 VNS 再作为第三组件加入，会重复当前 ILS 和已停止原型，属于机械叠加。
本轮保持官方 ILS 不裁剪、不加算子，先用冷启动与 HGS 热启动两条线直接检验“顺序
交接是否有效”。若该基础假设失败，停止候选；不得靠追加陈文动作救援。

本文档不包含任何性能结论。陈文报告值、公开 BKS、China81 结果和本候选未来结果必须
分别保留，只有匹配实例、起点、种子、评分和计算预算的实验才允许比较性能。
