# E2 15负恢复有界尝试收口

日期：2026-07-11  
最终判决：`E2_LOSS_RECOVERY_CLOSED_WITH_FROZEN_25W_5T_15L`

## 人话结论

我们确实认真救过这15负，不是一看难就放弃。但三条有依据的短门都没有证明能稳定减少负例：重启打断了大实例的连续搜索；真正LNS中段有平均改善，但只救回1组；按正式10%/80%/10%比例扩大LNS中段后，反而在50c和75c明显退化。

最后的整路块审计完全不跑新搜索，只用已保存的5种父解。6个开发负例全部都能拼出可行的混合路线，但没有一组比现有最好父解便宜0.25%，也没有多救回任何一负。这说明现在缺的不是“把已有好路线重新拼起来”，而是要产生现有解库里根本没有的新路线。为了15负再接一整套HGS种群搜索，工程代价大，而且当前没有headroom证据。

关闭前又对HGS-CVRP、PyVRP/SREX、混合车队HGA、多车场绿色VNS和仓库现有SWAP*-lite做了源码与文献复核。理论上并非绝对不可能继续改善，但下一级方法实际上是一条新求解器研发线，需要种群、真正SWAP*、路线消除、SREX修复和ReSETP充电物理适配。仓库现成SWAP*-lite既不能直接减少路线数，又通过`score_reference()`做不计入4000预算的完整解评分，不能当作公平捷径。详见`docs/handoff/e2_loss_recovery_literature_contingency_20260711.md`。

因此，E2算法恢复在这里止损。论文继续使用已冻结的正式结果：45组25胜5平15负，九档总成本领先LNS 6.845690%，配对平均/中位优势2.829832%/0.842029%。可以写“完整benchmark总体第一”，不能写“每一组都赢”。
