# E2 资源约束路线切分器最低成本合同

日期：2026-07-25  
编号：`E2-RC-EV-SPLIT-001`  
状态：`USER_APPROVED__G0_ENGINEERING_GATE_ONLY`

## 1. 为什么另立本候选

前两版独立改善算法均已按登记停止。第一版先按距离截断再检查可行性，0/3 改善；
第二版解决了可行候选生成，但在三个强起点上仅 1/3 出现
`4.55e-05%` 的微小改善，且改善来自 2-opt*，连续块重建没有贡献。两者共同说明：
在已经完成的路线附近继续增加局部移动，不足以形成与 HGS 互补的第二决策层。

仓库既有 A11 证据显示，客户顺序重排配合贪心解码在 4000 预算时有信号，但在
8000 预算时衰减；`algorithm_optimization_prd_20260718.md` 已把“顺序空间的最优
切分 + 群体多样性”列为最有依据、但尚未完成的候选。新增文献复核也表明，高性能
HGS 变体通常让一个问题专用子算法完整负责一个耦合决策层，而不是在成品解后再加
普通邻域。

因此本候选只回答一个工程问题：给定一个客户顺序，能否在同一过程中决定路线边界、
车场、燃油/电动车型、充电方案、有限车队和共享充电桩占用，并输出完整可行解。
当前不运行 HGS，不比较算法成绩，不授权论文、E3、BKS、SOTA 或 `1+1>2`。

## 2. 固定方法

研发名：`RESOURCE-CONSTRAINED EV-AWARE SPLIT`（RC-EV-Split）。

输入是客户恰好出现一次的顺序。程序枚举该顺序的连续片段。每个片段必须先通过同一
路线级硬约束检查，然后生成每个允许车场的燃油车方案，以及电动车的 integrated、
low-carbon、immediate 三种充电求解方案。

切分状态至少包含：已处理到的客户位置、各车场各车型已用车辆数、各充电站各半小时
时隙的已用充电位数、累计路线局部成本和可回溯的路线片段。状态扩展时必须同时满足
有限车队和共享充电桩上限。

只允许安全支配删除：在同一客户位置，如果状态 A 的成本不高于 B、每一类车辆使用
数均不多于 B、每个充电时隙占用均不多于 B，则 A 可删除 B。不得根据最终成绩设置
束宽或删状态。工程安全上限固定为：

- 单个位置最多 50,000 个未被支配状态；
- 全过程最多生成 500,000 个状态；
- 任一上限触发即 HALT，不得改成结果后束搜索；
- 片段长度只由最大载重和单调的路线级硬不可行性停止，不设结果导向长度；
- 输入解原有路线边界及车场/车型/充电方案必须作为保底路径注入，确保工程门至少能
  原样回放已知可行解。

如果后续为了规模使用有损截断，必须另立算法版本和性能合同，不能把本 G0 称为精确
切分。

## 4. G0：零候选完整目标工程门

全新输入按结果盲规则选择，排除前两版行为门和旧 G1 已使用的题。固定三层为：
京津冀 15 客户、珠三角 75 客户、成渝 150 客户；每层选择完整 instance ID 的
SHA-256 字典序最小者。题目冻结后，起点使用该题 v7 五种子中成本最低的封存
MV-HGS-SP witness。

G0 对每题只运行一次当前客户顺序的联合切分，不扰动顺序，不运行 HGS/ALNS/VNS/MIP。
必须同时满足：

1. 三个封存起点直接检查、精确复算均零违约且成本逐位一致；
2. 三题均形成至少一个非保底的连续片段方案；
3. 三题均找到从位置 0 到全部客户的资源可行切分路径；
4. 输出解通过完整 `check_solution` 和 `exact_china81_score`，客户各出现一次；
5. 输出不劣于注入的保底路径；若更优，只记工程观察，不形成算法效果结论；
6. 候选完整目标评价计数为 0；仅允许对封存起点和最终回放解各做一次独立验收；
7. 单元测试用穷举小例证明：无资源冲突时切分结果等于全枚举最优；支配删除不得删除
   未来可行的状态；有限车队和共享桩冲突必须被拒绝；
8. 任一位置状态数不超过 50,000，总生成状态不超过 500,000，峰值内存低于 4 GiB；
9. 全部源码、输入、输出和保护文件哈希闭合，AppleDouble 与缓存排除。

通过判 `PASS_RC_EV_SPLIT_G0_ENGINEERING`。状态爆炸、无完整路径、验解失败或保底
路径未能回放，判 `HALT_RC_EV_SPLIT_G0_STRUCTURE_OR_SCALE`。

### G0 v1 接线事故与 v2 边界

v1 在 0.6 秒内三题同类停止，尚未形成任何切分状态或候选结果。调用栈确认：枚举到
一个没有任何车场/车型方案的连续片段时，复用的路线方案函数抛出
`NoFeasibleAssignmentError`；适配器误把“跳过这个片段”解释成“整题失败”。

v2 只捕获这一种片段级异常并继续枚举其他终点。v1 输出、登记和调用栈原样保留；
题目、witness、客户顺序、状态支配、资源上限、路线方案生成、完整检查和全部停止门
不变。该修复发生在任何目标结果出现前，不构成结果后救援。

### G0 v2 最终结论

v2 判 `HALT_RC_EV_SPLIT_G0_STRUCTURE_OR_SCALE`。15 客户题完成，最多每位置 4 个
未被支配状态、共生成 229 个状态；75 与 150 客户题均触发预登记的 500,000 总状态
硬上限。三题候选完整目标评价合计为 0，失败不是算法成绩问题。

该结论淘汰“把有限车队和每个共享充电时隙都放入 Split 标签”的精确联合状态表示。
禁止提高 500,000 上限、改成结果后束宽或在相同题调参。若继续，必须换成不同架构：
路线级方案先形成列池，再由带客户覆盖、有限车队和充电时隙容量约束的限时 MIP 统一
组装；这与 Froger et al. (2022) 的路线生成—方案组装分解一致，也符合用户已批准的
D5 披露要求。

## 5. G0 后边界

G0 通过只证明这个新决策层真实存在且工程上可运行。下一步必须另立全新题的直接效果
门，比较同一客户顺序下旧贪心解码与 RC-EV-Split，并预注册改善覆盖率、路线数变化、
用时和状态规模。只有效果门通过，才允许把它接入 HGS，并设计纯 HGS、独立切分搜索、
HGS+切分的公平比较。
