# E2 路线列生成—限时 MIP 组装最低成本合同

日期：2026-07-25  
编号：`E2-RC-MIP-ASSEMBLY-001`  
状态：`USER_APPROVED__G0_ONLY`

## 1. 来源与旧方案差异

RC-EV-Split 已证明：把有限车队和全部共享充电时隙放入逐位置标签，在 75/150 客户
题上超过 500,000 状态，不可扩展。Froger et al. (2022) 对带容量充电站 EVRP 的
处理是把路线生成与全局方案组装分开，正好对应本项目的失败原因。

本候选不是旧 MV-HGS-SP 重命名。旧程序的列只来自 HGS 完整方案中已经形成的整条
路线；主问题只含客户覆盖和车队数量，未含共享充电站时隙容量，冲突依赖事后整解
检查。新候选对给定客户顺序枚举所有路线级可行的连续片段，并为每个片段形成不同
车场、车型和非线性充电方案列；主问题同时约束客户恰好覆盖一次、各车场各车型有限
车队和每个充电站每半小时的充电位容量。

## 2. G0 固定边界

独立目录：
`baselines/algorithm_prototypes/route_column_mip_assembly_20260725/`。

G0 只使用 RC-EV-Split 已冻结的三道工程题及相同封存顺序，不运行或扰动 HGS。
每个输入解的原路线作为保底列注入。路线列必须先过路线级硬约束；MIP 限时 10 秒，
使用 SciPy 1.16.3/HiGHS，报告 status、message、incumbent、dual bound、gap、
node count 和实测时间。

必须同时满足：

1. 三题都生成非保底连续片段列；
2. 三题 MIP 都返回整数 incumbent，客户覆盖、车队和充电时隙约束逐项闭合；
3. 组装解通过完整检查和精确评分，路线成本和整解成本闭合；
4. 保底列保证结果不劣于封存输入；任何改善只作工程观察；
5. 每题列数不超过 50,000，MIP 峰值内存低于 4 GiB；
6. 小型合成例与穷举结果一致，并包含“客户覆盖可行但共享桩冲突”的反例；
7. 不修改保护文件、旧封存数据、旧失败候选或主 TeX。

通过判 `PASS_ROUTE_COLUMN_MIP_G0_ENGINEERING`；否则判
`HALT_ROUTE_COLUMN_MIP_G0_STRUCTURE_OR_SCALE`。通过只授权另立全新题直接效果门，
不授权 HGS 接入、论文、E3、正式全量、BKS、SOTA 或 `1+1>2`。

## 3. G0 结果与直接效果门

G0 判 `PASS_ROUTE_COLUMN_MIP_G0_ENGINEERING`。15/75/150 客户题分别形成
159/1576/2278 列，MIP 均在 0.03 秒内证明最优，完整验解闭合；三题均与封存输入
持平。这只证明可扩展和约束正确。

获准的下一门使用三道全新结果盲题，每题汇集 v7 五个种子的 MV-HGS-SP 封存客户
顺序。固定比较：

- 父解：五个封存完整解中的最好者；
- 旧池：只允许选择五个父解中已经存在的整条路线；
- 新池：对五个顺序枚举全部路线级可行连续片段列，并含旧池全部路线。

同一 10 秒 MIP、同一客户/车队/共享桩约束和完整检查。通过必须同时满足：三题全部
可行；至少 2/3 题新池严格优于 `min(最好父解, 旧池)`；至少一次改善解选入父解中
不存在的新客户边界路线；新池不得在任何题更差；列数不超过 50,000。通过判
`PASS_ROUTE_COLUMN_MIP_DIRECT_HEADROOM`，否则判
`STOP_ROUTE_COLUMN_MIP_NO_DIRECT_HEADROOM`。通过仍只授权设计 HGS 接入门。

## 4. 直接效果门终态

三道冻结新题全部完成并由 HiGHS 证明最优，完整评价、有限车队和共享桩约束均闭合；
但新连续片段池严格改善为 0/3，且没有选择任何父解外的新客户边界，正式判
`STOP_ROUTE_COLUMN_MIP_NO_DIRECT_HEADROOM`。禁止在相同三题调整时限、列上限、
种子或顺序来源。

停止后零目标结构审计确认：路线本应为无序集合，`customer_order()` 却按文件中的
路线列表顺序压成单条长链，因此只有相邻路线能够跨边界重切。三题对父解内全部路线
对的覆盖率仅 50.0%、19.2% 和 6.0%。完整证据见
`docs/handoff/e2_route_column_direct_stop_root_cause_20260725.md`。下一候选另立
无序路线对精确重切合同，不修改本候选或重跑本门。
