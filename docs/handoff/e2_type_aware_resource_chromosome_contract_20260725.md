# E2 资源类型感知染色体候选：冻结最低成本合同

- 编号：`E2-TARC-001`
- 日期：2026-07-25
- 状态：`EVIDENCE_COMPLETE__ZERO_OBJECTIVE_GATE_AUTHORIZED`
- 保护备份：三视角 HGS、corrected China81 v7 及全部历史失败保持只读

## 1. 要解决的具体问题

当前 HGS 擅长搜索客户顺序，但“由哪个车场、哪种动力车辆服务”主要在路线形成后由
完成器决定。这样一来，即使某个“客户次序＋车场＋动力”的组合很好，普通交叉也只能
继承客户顺序，不能把资源归属一起传给子代。

本候选把每个客户基因写成：

`(customer_id, depot_id, powertrain)`，

其中 `powertrain ∈ {cv, ev}`。两个车场时最多只有四种资源标签。客户顺序和资源标签
在同一次交叉或变异中共同改变；解码器按标签保持相对次序并切分路线，有限车队、时间窗、
载重、SOC、非线性充电、共享桩、地域—日期—时段电价/碳强度继续由现有完整模型和
独立检查器裁判。

连续充电量、精确充电时刻和实体车编号不进入染色体，避免重开已经因状态爆炸停止的
全资源联合标签/JRC 路径。

## 2. 与封存失败的实质差异

- 不是 HGS 后接 ALNS/ILS/VNS；
- 不是固定客户次序后的 Split、重切或路线池重组；
- 不是先造候选、再由完整模型事后猜车场和车型；
- 不是把资源价格加入排序标签；
- 不是穷举 8 客户的车场、车型、次序和充电；
- 不是把当前代理误差换一个名字。

若实现退化为上述任一形式，立即判合同违约并停止。

## 3. 冻结输入选择

表示/性能小门只使用 corrected China81 v7 的三个未在既有候选文档中出现或出现次数
最低的算例，选择规则在实现和读取候选成本前固定：

1. 在 50、100、200 三个规模中分别统计实例 ID 在既有
   `baselines/algorithm_prototypes` 与 `docs/handoff` 算法候选文本中的出现次数；
2. 取出现次数最少者；
3. 并列按 `SHA-256(instance_id)` 字典序取第一。

冻结结果：

- `cn-prd-50c-02-V2-LOCATIONS`；
- `cn-jjj-100c-02-V2-LOCATIONS`；
- `cn-prd-200c-01-V2-LOCATIONS`。

父代固定为各题 v7 的 `HGS-M` seed 3 和 seed 4 witness。不得查看结果后换题、换父代、
换 seed 或补 seed。

## 4. T0：零目标表示与解码门

T0 不运行搜索，不比较成本优劣，完整候选评价预算为 0。

必须完成：

1. 六客户人工夹具中，对每个固定资源标签子序列穷举所有连续切分，与动态规划结果
   逐位相同；
2. 三题四类资源标签均可稳定编码；同一客户恰好出现一次；
3. 每个父代原路线切分必须属于解码器可枚举集合，不能因表示丢失；
4. 解码器状态只包含当前位置、该标签已用车辆数和当前路线的载重/代理时间，不得放入
   共享充电时隙、连续 SOC 或跨标签联合状态；
5. 200 客户题每个标签的状态数不超过 200,000，单父代零目标解码不超过 10 秒；
6. 六进程无实例启动冒烟必须报告唯一 runner 模块/文件身份；资源门安全后才可加载
   三个真实实例；
7. runner、合同、父代 witness、实例输入、完成器、检查器、评分器和保护文件哈希
   全部闭合。

任一失败判：
`STOP_TARC_REPRESENTATION_OR_DECODER_GATE`。

不得扩大状态、放宽时间、改变标签、改题或把精确资源状态重新塞进 DP 后救援。

## 5. G0：冻结六任务低成本因果门

仅 T0 全部通过才运行。使用 6 workers，每个“算例 × 臂”一个独立任务：

- `ORDER_ONLY`：父代客户顺序按同一顺序交叉产生子代；每个客户的
  “车场 × 动力”标签固定为较强父代中的标签，只允许客户次序改变；
- `ORDER_PLUS_TYPE`：使用同一父代和同一客户顺序交叉掩码；复制父代片段时同时
  复制其“车场 × 动力”标签，其余客户随另一父代的次序和标签填入，并由 T0
  解码器强制兑现。

两臂共同约束：

- 同一父代、随机种子、客户顺序交叉掩码、受限解码器、充电补全策略和候选数；
- 每题每臂最多 32 次完整候选评价；
- 不连续接受，不迭代成长期算法；每个候选相对同一父代对独立生成；
- 共同使用现有 China81 完成、完整物理模型、`exact_china81_score` 和独立检查；
- 缓存命中不计作新的完整评价，也不得用代理评价冒充完整预算；
- 每任务 90 秒安全上限，资源安全时固定 6 workers。

只有同时满足下列条件才判机制具备继续价值：

1. 六任务全部闭合，记为可行的候选全部独立检查 0 违约；
2. `ORDER_PLUS_TYPE` 在至少 2/3 题严格改善较强父代；
3. `ORDER_PLUS_TYPE` 在至少 2/3 题严格优于同预算 `ORDER_ONLY`，且三题零负；
4. 至少一题改善候选的资源标签组合不是共同完成器对同一客户顺序自动产生的组合，
   从而能把收益归因到共同遗传资源类型；
5. 两臂逐题完整评价数相同；
6. `ORDER_PLUS_TYPE / ORDER_ONLY` 墙钟比中位不超过 1.25、最大不超过 1.50。

通过判：
`PASS_TARC_LOW_COST_CAUSAL_GATE`。

任一条件失败判：
`STOP_TARC_NO_VERIFIED_JOINT_ORDER_RESOURCE_GAIN`。

停止后不得在三题上调交叉、标签变异率、候选数、时间、阈值、父代或 seed，也不得
换题重做同一个故事。

## 6. 通过后的边界

G0 通过只允许另立匹配完整评价预算的正式 A/A+T/A-long 小面板，并验证增益是否来自
资源类型共同遗传。它仍不授权：

- China81 全量；
- 公开 BKS/SOTA；
- “真混合”“1+1>2”或论文创新主张；
- E3--E7；
- 修改主 TeX。

只有后续公平门证明质量收益、计算代价和独立复算同时成立，才可决定是否把该机制
正式嵌入 HGS 并重跑 E2。
