# E2 资源类型感知染色体：证据审查与唯一候选结论

- 编号：`E2-TARC-EVIDENCE-001`
- 日期：2026-07-25
- 性质：只读文献、封存失败和正式 witness 证据审查
- 边界：不是算法成功、性能、BKS/SOTA、论文或 E3 证据

## 1. 结论

在保持全部既有失败方案最终停止的前提下，仍有且只有一个有一手文献支持、又没有被
本项目直接验证过的机制假设：

> HGS 个体不再只保存客户顺序，而是让每个客户同时携带低基数的
> “所属车场 × 燃油/电动车”资源类型；交叉和变异同时改变客户顺序与资源类型，
> 随后由受限解码器切分路线，完整 China81 模型仍作唯一裁判。

这项假设暂称“资源类型感知染色体”，名称不构成创新主张。它与把普通 ALNS、ILS、
VNS 或 MIP 接在 HGS 后面不同，也与固定客户顺序后再切路线、事后补车型/充电或只
改变代理评分不同。

## 2. 为什么只剩这一项

本项目已经封存下列路径，禁止调参、扩时、换题或改名复活：

- 通用 HGS+ALNS、ReMIX、MPILS-MVNS、HGS→ILS 顺序交接；
- 普通 relocate/swap/2-opt/连续段 VNS 与可行性引导重插；
- 固定客户顺序的 Split、路线对重切、路线池/路线列 MIP；
- 全资源联合标签、资源—时隙价格标签和对偶引导有限位移；
- 8 客户联合路线—充电精确邻域；
- 当前 HGS 代理误判教育。

这些结果共同说明：强 HGS 后面再接一个通用搜索器没有形成可追踪增益；固定客户顺序
后再重切没有余量；把全部资源放进标签或小邻域会状态爆炸；只让完整模型在末端重排
代理候选也没有找到被错杀的严格改善。

尚未直接覆盖的是：资源归属本身成为可遗传信息，并与客户顺序在同一次交叉中共同
传递。它不是“候选生成后再补资源”，也不是“两个完成解再拼一次”。

## 3. 一手文献依据

Mahmoudinazlou 与 Kwon 的 HGA-TAC 让染色体同时保存客户顺序和 truck/drone
服务类型，交叉和符号变异共同改变二者；动态规划只补剩余会合决定。作者在
TSPD/FSTSP 大规模公开面板上报告大量新最好解，并公开了实现。该工作证明
“低基数资源类型前移到遗传表示”可以形成高性能搜索，但其资源只有 truck/drone，
不覆盖本项目的多车场、有限异构车队和共享充电。

- 论文：Mahmoudinazlou, S., & Kwon, C. (2024),
  <https://doi.org/10.1016/j.ejor.2024.05.009>
- 作者代码：<https://github.com/Sasanm88/TSPDroneHGATAC.jl>

Rocha 与 Subramanian 在 HEV-TSPTW 的 HGS 中，让弧级燃油、充电、boost 和纯电
运行模式随客户次序共同参与交叉与局部评价。它支持“客户次序和能源模式不能完全
分开搜索”，但只处理单车单回路，没有车场、车型、充电站或共享资源。

- 论文：Rocha, L., & Subramanian, A. (2024),
  <https://doi.org/10.1016/j.cor.2023.106223>

Zhao、Archetti、Pham 与 Vidal 的 HGS-IRP 则证明，真正有效的 HGS 定制通常不是
外接一个通用算法，而是加入一个与问题结构绑定、能同时改变访问位置和资源决定的
专用操作。该工作的资源是跨期库存，不可直接移植，但设计原则一致。

- 预印本与官方代码：<https://arxiv.org/abs/2506.03172>，
  <https://github.com/vidalt/HGS-IRP>

这些文献只支持“值得做最低成本证伪”，不支持本项目已经创新或必然提升。

## 4. 与陈雨蝶等（2025）的边界

陈雨蝶、干宏程等的 MPGA-VNS 是以多种群遗传算法为主干，在搜索后期由新最好解触发
VNS 深化；它不是两个独立强算法在匹配预算下形成的严格协同。ReSETP 应学习其
“公开基准证明通用搜索能力、自建问题证明模型适配性、过程图解释搜索阶段”的展示
逻辑，不应照搬 GA→VNS 结构，更不能用不匹配初解和预算的 A/B/A+B 表代替因果消融。

- 陈雨蝶，干宏程，程亮，温金鹏（2025）：
  <https://doi.org/10.12011/SETP2024-2027>

## 5. corrected China81 v7 的直接活动证据

正式只读审计见：

`baselines/algorithm_prototypes/type_aware_resource_chromosome_20260725/`
`resource_activity_audit_v1/`

对 405 份封存 witness 的直接统计为：

- `HGS-M`：322/405 个解同时使用燃油车和电动车，193/405 个解至少使用三种
  “车场 × 动力”标签；电动车承担 7.8277% 客户和 10.4987% 路线；
- `MV-HGS-SP`：314/405 个解同时使用两类车，188/405 个解至少使用三种标签；
  电动车承担 7.1628% 客户和 9.6715% 路线；
- 两臂合计 997 次充电动作全部发生在车场，公共充电站动作是 0；954 次在第 0 秒
  开始，没有车辆发生多次充电。

因此，“车场 × 动力类型”在当前算例中不是完全死亡的变量，具备做低成本表示门的
最低条件；但公共站和沿途充电机制在当前正式解中没有活跃，不能把候选包装成
“共享公共充电优化算法”。电动车客户占比也只有约 7%--8%，所以候选很可能没有
足够性能余量，必须先小门证伪。
