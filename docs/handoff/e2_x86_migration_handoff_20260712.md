# E2 完成后转移到 X86 的交接清单

状态：准备中。E2 十种子矩阵完成并封存以前，不迁移、不在 X86 重跑同一批任务。

## 迁移目标

E2 正式收口后，把当前 ReSETP 项目和移动硬盘上的证据整体转移到与 `dr-x86` 同一台机器。X86 机器有 16 个逻辑线程、16GB 内存，作为后续 E3 及以后实验的开发和运行环境。

## 必须原样保留

- 当前分支 `codex/reporting-pipeline` 及其提交历史；
- E2 冻结提交、冻结 tag、合同 hash 和实例 manifest；
- `baselines/e2_alns/e2_final_10seed_20260711/` 全部原始结果、任务账本、解文件、复算表和 hash；
- E1、E3 和 80 kWh 对照证据，不得因为迁移被覆盖；
- `docs/handoff/`、`HANDOFF.md`、项目记忆、实验总计划和问题登记册；
- Python 版本、NumPy/SciPy 版本、求解器依赖、随机种子策略和实验环境声明；
- AppleDouble 排查结果和迁移前后的文件清单。

## 迁移前验收

迁移前必须先完成 E2 的 verify、F2 曲线、已批准的 8 项 16000 评价预检、基线参数附录、文档更新、提交、推送和封存 tag。迁移前再做一次只读核对：当前 checker 复算没有新增违规，810 行数量正确，预算都是4000，解文件和 hash 清单一致。

## X86 到位后的第一步

先不要直接开 E3 全量。按下面顺序做短检查：

1. 检查 Python、NumPy、SciPy、编译器和依赖版本；
2. 检查仓库提交、冻结 tag、实例和参数文件的 hash；
3. 用一个已经完成的 E2 任务做只读复算，确认成本、路线、违规数逐位一致；
4. 用一个极小的 E3 任务做入口和预算短门；
5. 确认 16GB 内存下的并行度，再从4 workers开始试，稳定后通常上限为8 workers；
6. 只有短门通过，才按 E3 合同启动新的实验。

## 并行规则

并行只表示同一项已批准实验内部的独立任务同时运行，不表示 E2、E3、动态、碳机制和其他研究线一起乱跑。每个任务必须独立落盘、可断点续跑；主进程、任务目录和 CSV 不能出现重复键。X86 初始建议8 workers，实际根据 CPU、内存、I/O 和任务失败率调整，不盲目拉满16线程。

## 禁止事项

- 不把 X86 的绝对成本和 M1 的正式表直接混在一起；
- 不因为换机器重跑 E2 并把新结果替换冻结结果；
- 不改 E2 的算法、预算、成本、物理约束、场景或评价器；
- 不在 E2 封存前提前启动 E3 全量；
- 不把 HGS、DR-ALNS 或后续碳算子提前塞回 E2；
- 不把机器更快误写成算法更好，论文仍以同一合同下的证据为准。

## 交接完成标志

X86 上的仓库、依赖、冻结 tag、E2 证据和只读复算均通过，且交接记录已追加到 `HANDOFF.md`。从这一刻起，后续实验以 X86 为主运行环境；M1 保留为证据备份，不再并行修改同一实验目录。
