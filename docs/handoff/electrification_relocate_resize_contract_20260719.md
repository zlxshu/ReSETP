# 燃油长路线减负—电动化联动搬移：阶段一隔离开发合同

状态：`PRE_REGISTERED_EXECUTION_RECOVERY_V2_ZERO_SEARCH_REPLAY_ONLY`

日期：2026-07-19

范围：只开发和验证一个跨路线机制算子。不得重跑已烧毁的历史优解池 P1，
不得启动新 ALNS、HGS、阶段二、正式算例或全量实验。

## 1. 病灶与算法故事

v7 已能在路线固定后选择燃油车/电动车、安排充电、调整充电时刻和跨车场责任，
但它不能为“差一点就能电动化”的燃油路线主动改变客户分组。历史优解池也只能
从 ALNS 已经走过的路线中挑选，不能创造这种新结构。

本候选只处理一个病灶：一条燃油路线因为一名客户或一小段相邻客户造成续航、
时间窗或载重压力，固定路线的车型—补能步骤无法把它改成电动车。算子把这段
客户搬到另一条有余量的路线，再同时重选两条路线的车型、充电和低碳时刻。
只有完整复算成本严格下降且燃油路线数至少减少一条，才接受；否则逐位保留
原 v7 解。

## 2. 已发表依据与自研边界

- Hiermann 等（2016），DOI `10.1016/j.ejor.2016.01.038`：E-FSMFTW
  同时处理客户路线、车型与充电；其 `Resize` 和 `RelocateAndResize`
  说明客户搬移应与受影响路线的车型重选联动。
- Hiermann 等（2019），DOI `10.1016/j.ejor.2018.06.025`：混合燃油、
  插混和纯电车队采用分层路线评价，在固定客户顺序上处理车辆与补能。
- Vidal 等（2014），*Implicit depot assignments and rotations in vehicle
  routing heuristics*，DOI `10.1016/j.ejor.2013.12.044`：在客户搬移和弧
  交换的同时联合评价车型和车场选择。
- Vidal 等（2014），*A unified solution framework for multi-attribute
  vehicle routing problems*，DOI `10.1016/j.ejor.2013.09.045`：通用路线
  搜索应把多属性问题的分配、顺序和路线评价放进有限的专用组件。
- Christiaens 与 Vanden Berghe（2020），DOI
  `10.1287/trsc.2019.0914`：相邻客户串可作为结构化路线改造单位。

本项目不复制上述受版权保护的源码，只按论文思想独立实现。已有的车型—补能、
碳择时、跨场责任和完整成本检查均为仓库内模块，不新增第三方软件许可。

已有文献包含“搬客户并换车型”，因此不能把跨路线搬移或车型重选本身声称为
原创。待验证的项目贡献是：用“燃油路线距离电动化还差多少”只触发少量搬移，
把 ReSETP 的多车场责任、车型、补能与时变碳统一放进受保护的完整判定，并把
“燃油路线数实际减少”设为接受硬条件。

## 3. 冻结算子

输入必须是一份已经由 v7 完整收尾且独立复算可行的解。每轮按以下固定规则：

1. 只把当前燃油路线作为来源；来源至少保留一名客户。
2. 只搬一名客户或两个相邻客户，保持片段内部顺序，不反转。
3. 目标为另一条已有路线；不新开路线，不调用第二条搜索。
4. 每个目标只保留距离增量最小的两个插入位置。
5. 两条受影响路线先用燃油车构成可行中性方案，再由同一个 v7 终局流程联合
   重选跨场责任、车型、充电和碳时刻。
6. 全部候选先用受影响路线的车型—补能局部成本预筛；最多保留 12 个不同搬法。
7. 最多对预筛前 3 个搬法运行完整终局流程和独立完整复算。
8. 只接受“完整成本严格下降且燃油路线数至少减少 1”的最佳候选；完全平局和
   任何非有限数都保留原解。
9. 最多执行 2 轮；第二轮只能从第一轮已接受的新解继续，同样受 12/3 上限约束。

### 3.1 行为门前归因加固（2026-07-19，未看结果）

静态红队指出，v7 终局流程本身也会搬客户；只看总成本和总燃油路线数，不能
证明收益来自本算子。因此在任何行为运行前追加以下更严格条件：

1. 每轮存在候选时，先把该轮原解单独再跑一次相同 v7 终局流程，作为“没有
   新搬移动作”的对照。它与候选调用分账，不占每轮 3 次候选上限。
2. 候选成品必须同时优于该轮原解和上述对照，且燃油路线数同时少于二者；
   否则不得接受。
3. 声称被减负的来源路线在该轮原解和无新动作对照中都必须仍是燃油车，在
   候选成品中必须变为电动车。
4. 中性方案必须逐路线证明只发生了登记的相邻片段搬移；完整终局后，片段
   必须仍按原顺序完整留在登记的目标路线，并从登记的来源路线消失。
5. “路线结构变化”只作上述搬移的证明字段，不另作可调接受门槛。

每轮最多新增 1 次无新动作对照，两轮最多 2 次；候选完整终局仍最多 6 次，
二者合计最多 8 次。任何对照、候选或非有限值不能闭合时，该候选或该轮
失败关闭并保留原解，不能用部分结果出分。

排序键冻结为：

`(局部预估增量, 来源路线, 目标路线, 片段长度, 片段起点, 插入位置, 方案完整内容哈希)`。

不得根据结果改变片段长度、12/3/2 上限、插入位置数、接受硬条件或题目。

## 4. 三本账与证明

分别记录：

- 枚举账：候选搬法数、可行中性方案数、被预筛数；
- 局部账：车型—补能路线局部评价、距离插入评价；
- 完整账：终局流程调用数、完整复算数、可行性检查数。

每个接受动作必须保存：原解、搬移后的中性方案、完整成品、来源/目标路线、
搬移客户、搬移前后车型、燃油路线数变化、完整成本增量和独立复算误差。
证明键使用保留列表顺序和完整浮点内容的 SHA-256；忽略列表顺序的语义哈希
另列，不得再混用。

三本账追加冻结：原解完整复算与可行性检查、中性候选构造与可行性检查、
每个候选的独立完整复算与可行性检查、每轮无新动作对照、最终独立复算与
可行性检查全部逐项计数；终局模块报告的完整路线搜索次数必须逐次汇总，
不能在外层写死为零。

行为门不得直接相信算子给出的“搬移成立、车型已变、成本已降”布尔字段。
它必须从每轮原解、中性方案、无新动作对照和成品四份快照重新抽取客户序列
与车型，重新计算哈希、完整成本、可行性和燃油路线数，再与逐次记录交叉核对。
每轮 3/1 和总计 6/2/8 上限也必须从实际终局记录分组重算，不能只读汇总值。
