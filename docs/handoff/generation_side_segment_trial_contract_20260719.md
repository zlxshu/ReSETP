## 1. 核验后的判断

Claude 的方向值得试，但“机制从未进入生成层”这句不成立。仓库已有多车场边界移除、跨场修复、碳感知移除/修复、机制感知初始化和连续搜索中的机制专家。它们有的确实改变路线成员，有的已经在等预算小试中失败。因此本试验不得重复“机制亲和初始化”，也不得把已有生成算子说成不存在。

真正尚未解决的缺口是：

1. 现有跨车场生成动作大量使用里程选择客户、里程选择插入位置，或只保留里程改善候选；
2. v7 的责任解码只枚举单客户交接和单客户互换，插入位置仍由里程筛出；
3. 连续机制专家虽进入主循环，但其多车场专家仍沿用上述候选生成，旧训练门严格胜为 0；
4. 因而仍可能漏掉“里程略差、完整业务成本更好”的成段责任调整。

本试验只检验这一处，不扩展成五个算子。

## 2. 候选算法

名称：**机制驱动的成段搬移—联合修复**。

通俗定义：如果一条路线连续带着一小段本应由另一个车场负责的客户，候选算法可以把整段搬回去；它不先问“里程是否更短”，而是直接比较搬家前后的完整业务成本。搬完后，用现有的车型、充电和低碳时刻模块完成路线。

冻结规则：

- 每段长度为 1–3 个连续客户；
- 只处理不同车场之间的路线；
- 优先处理当前由非归属车场服务、且目标路线属于其归属车场的连续段；
- 枚举目标路线全部插入位置，不按里程裁掉位置；
- 必要时允许双方各搬一小段，以保持容量和责任平衡；
- 候选先用受影响路线的完整本地业务成本比较；
- 只有选中的一个完整解进入共同的完整候选计分器并消耗 1 次搜索预算；
- 车型、充电和碳时刻完成不得消费隐藏的完整搜索评价；
- 每次完整记录：扫描段数、插入位置数、本地计价次数、可行性检查数、完整候选评价数、被里程规则拒绝但被本算法保留的候选数。

## 4. 两道门

### 门 A：行为与归因

在独立、非正式、多车场绑定夹具上必须同时满足：

1. 生成动作真实改变“哪些客户属于哪条路线”；
2. 至少一个被保留的候选里程变差，但完整业务成本变好；
3. 选中的解可行，独立完整复算闭合；
4. 同候选上限的里程版找不到该解，或明确把该解提前否决；
5. 完整搜索评价为 0 或 1，并与账本一致；
6. 非绑定夹具精确不动作；
7. 单元测试、重复运行和篡改测试全部通过。

任一失败：`STOP_SEGMENT_GENERATOR_BEHAVIOR`，不得进入门 B。

### 门 B：最小性能预警

仅门 A 通过后才创建结果盲开发题并运行。三臂为：

- 现有 v7 等价连续控制；
- 控制 + 成段生成候选；
- 控制 + 相同段长/候选上限、但按里程选择的删减版。

三臂必须同一序列化起点、同一随机种子、同一完整候选预算、同一终局完成器、独立复算。候选的机制动作也占完整候选预算，不得额外赠送。

最小预警门冻结为：

- 2 个结果盲开发题、每题 1 个种子、每臂 100 次完整候选评价；
- 候选对 v7：2/2 不退步且至少 1/2 严格胜；
- 候选对里程删减版：至少 1/2 严格胜；
- 至少一个题出现“里程会否决、机制保留、主搜索采纳”的完整链；
- 中位墙钟比不超过 1.25，最大墙钟比不超过 1.50；
- 所有预算、可行性、独立复算和输入/源码哈希闭合。

通过只意味着 `GO_THREE_SEED_DEVELOPMENT_WARNING`；不授权正式试验或阶段二。失败则 `STOP_SEGMENT_GENERATOR_NO_RESCUE`，冻结本候选，不在已见题上调参。

## 5. 来源依据与诚实边界

- Ropke 与 Pisinger（2006）：ALNS 通过多种破坏/修复邻域扩展可达解空间；不构成本候选必胜保证。
- Pisinger 与 Ropke（2007）：面向丰富车辆路径问题使用问题相关破坏/修复；支持“机制专用生成”，不支持“任意机制 badness 自动有效”的过强说法。
- Vidal 等（2014）：多属性车辆路径的高效联合评价与局部搜索框架；支持受影响路线的精细计价。
- Hiermann 等（2016）：车型、路线和充电联合优化；支持路线成员改变后重新完成车型/充电。
- Zhao 等（2025）：为业务耦合设计成组移除和重插动作；支持“成段/成组生成”而非单纯末端重排。

本合同只把这些文献当设计依据。它们没有证明 ReSETP 上的 `SEG-GEN-01` 会胜 v7、HGS 或 ALNS；胜负只由预注册门决定。
