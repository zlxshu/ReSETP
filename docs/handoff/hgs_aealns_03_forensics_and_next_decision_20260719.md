## 人话结论

这次不是判分出错，而是算法真的没有过关。新混合体在六道新鲜原始 Solomon 题上
对纯 HGS 为 2 胜、2 平、2 负。它在 R109 和 R208 上确实找到更短的同车辆数方案，
说明“用精英解分歧指导大改”不是空想；但在 RC105 上只保住共同初始解的 23 条路线，
纯 HGS 同时限做到 15 条路线。用户要求是公开题绝不输 HGS，所以候选必须停止。

## 直接死因

当前后悔修复的便宜排序只收到客户需求、车辆容量、距离矩阵和精英邻接信息：

1. 它没有时间窗输入，因而会生成紧时间窗下明显不可行的插入；
2. 普通精英分歧破坏允许新开路线，但插入排序没有计入新车固定成本或优先压车辆数；
3. 修复后虽然还会经过 PyVRP 局部搜索和共同惩罚成本检查，但这些碎片化中间解会
   改变 HGS 的随机消耗、子代和种群演化；
4. “单次只收共同惩罚成本改善”只能防止这一对子代直接倒退，不能保证同墙钟下
   整条 HGS 搜索轨迹不比纯 HGS 差。

新增的两个零搜索单元证据把前两点钉死：一个构造例中，距离代理会选择新开路线，
但一旦加入固定车辆成本，选择立即反转；另一个构造例中，不可在时间窗内到达的客户
仍会得到两个插入位置。这是设计缺陷取证，不是重新跑性能或在已见题上调参。

## 对 Claude 方案和 AILS-II 的吸收结论

Claude 关于 AILS-II 的 93/100 个 XL 初始 BKS和 0.07% 平均差数字有来源，但战场是
无时间窗 CVRP；挑战赛报告还明确说明 HGS-CVRP 原本只按至多约 1000 客户校准，
XL 比较没有为它重调参数。用 AILS-II 的 CVRP 表替代本论文 VRPTW 公开表，会变成
换问题获胜，不能支撑 ReSETP 公开算法结论。

“把专用 LNS 放进 HGS 循环”有 HGS-IRP 等论文结构依据，也被本轮两场胜局部分支持，
所以不是空穴来风。但接力、双起点、固定频率 SISR、项目 ALNS 教育器和本轮精英分歧
教育器已经连续显示：只换胶水方式没有可靠的零负保证。顾问判断 Codex 被
“继续把 ALNS 塞进 HGS”这条路径束缚，这一批证据支持该批评。

## 下一条有依据但尚未证明会赢的修正路线

如果用户仍批准一次新候选，必须另立 `EA-HYBRID-005`，不能复活或覆盖本候选。最小
设计变更不是调 `gamma`、移除量或频率，而是修安全语义：

1. 修复代理必须做最早到达时间窗检查，并把开新车固定成本和路线数放在距离之前；
2. 普通大改不得增加路线数；删路动作只能在修复后确实少一条路线时进入下一层；
3. 大改候选只有完整可行且按“车辆数优先、距离其次”严格优于原子代时，才有资格
   进入种群；
4. 大改使用独立随机流，不能通过额外局部搜索偷改 HGS 主随机流；
5. 先过零搜索行为门，再只允许一组从未用于前四批融合开发的原始 BKS 留出题；
   用户的硬门保持为 0 负且至少 2 个严格胜。

这条路线由本轮可定位缺陷直接推出，不是枚举算子或扫参数。诚实边界也必须保留：
这些护栏有望消除 RC105 式崩溃，但没有权威论文或现有数据能保证它一定严格胜 HGS；
在同墙钟下，额外动作仍会占用 HGS 时间。若下一道全新门仍失败，应停止公开 HGS
融合开发，把“公开严格胜 HGS 尚未做到”作为事实，而不是继续消耗留出题。
