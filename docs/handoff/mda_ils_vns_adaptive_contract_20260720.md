## 1. 目标和边界

用户最终要的是一套性能强、结构和故事清楚、公开题有竞争力、China81能胜母体且方便
后续E1--E7机制实验的算法。本门只回答一个更窄的问题：在已通过的PyVRP 0.13.4 ILS
加结果刷新式SwapStar母体上，加入来源明确的自适应扰动/接受控制，能否在不明显损失
吞吐的前提下继续提高未见多车场时间窗题质量。

本门不跑完整V13-28、不跑China81、不进入阶段二、不改论文TeX结论、不改正式
ReSETP求解器，不形成“达到BKS”或“最终算法完成”的主张。固定停滞C2路线保持STOP。

## 2. 设计依据

1. PyVRP 0.13.4 ILS和原生SwapStar是当前母体；基础门在未见B组三题×两种子×60秒
   上取得5胜0平1负，平均BKS gap改善0.393个百分点。
2. AILS-II官方论文与MIT代码快照说明，其自适应核心不是按固定停滞次数盲目加力，而是
   每隔`gamma`次用局部搜索后实际得到的结构距离反校扰动强度，并让期望距离随搜索进程
   从`dMax`收紧到`dMin`。官方默认`gamma=30, dMax=30, dMin=15`。
3. AILS-II的接受层按搜索进度把宽松系数从`etaMax`收紧到`etaMin`，阈值由近期候选
   均值和近期较好值共同决定。本项目只借思想和公开公式，自行实现，不复制Java代码。
4. 来源：
   - Máximo, Cordeau and Nascimento (2024), DOI
     `10.1287/ijoc.2023.0106`;
   - 官方INFORMS代码快照提交
     `4ff361153681635149e30305057251e9035ec6b7`，MIT；
   - PyVRP DOI `10.1287/ijoc.2023.0055`，本机版本0.13.4，MIT；
   - Vidal (2022) SwapStar，DOI `10.1016/j.cor.2021.105643`。

## 3. 冻结候选

所有候选都保留基础门的普通节点搜索和“只有初始解/刷新全局最好解才调用SwapStar”的
精修。仅以下控制层不同：

|配置|扰动距离目标|更新间隔|接受规则|
|---|---|---:|---|
|`foundation`|原装随机1--25|不适用|原装300长历史接受|
|`adaptive_d20_10`|20线性收紧到10|30|原装300长历史接受|
|`adaptive_d30_15`|30线性收紧到15|30|原装300长历史接受|
|`adaptive_da30_15`|30线性收紧到15|30|自适应近期阈值，`eta:1→0.01`|

自适应扰动使用预建离散强度
`{4,8,12,16,20,25,30,40}`，每30次根据
`新强度=旧强度×目标结构距离/实际平均结构距离`更新，并取最近的冻结档位。结构距离
按AILS-II口径改写为多车场版本：逐客户检查当前解的一条后继边在参考解中是否仍为该
客户的前驱或后继；若当前客户直接连任一车场而参考解不连任何车场，再加一。

为避免Python层逐次扫描全部客户重演候选1的吞吐事故，每个30次更新块只在第10、20、
30次记录真实结构距离，`实际平均结构距离`固定为这三次的算术平均。该稀疏抽样是
AILS-II反馈思想在本项目Python母体上的工程化改写；它在代码实现和任何性能结果之前
冻结，不得运行后更改抽样点。

不得在运行后增加档位、改`gamma`、改目标、改接受范围或加入新模块。

## 4. 接线与行为门

代码只放
`baselines/algorithm_prototypes/mda_ils_vns_20260720/`，不被正式runner导入。
先做以下检查：

1. `foundation`在5/100/1000固定迭代下与已通过基础门工作器逐位一致：最终解、
   迭代数和随机数状态相同；
2. 自适应距离在人工解对上由独立小函数复算一致；
3. 强度更新在实际距离高/低于目标时分别向下/向上移动，且不越冻结档位；
4. 关闭自适应时不维护每轮档案、不计算每轮完整签名；
5. Ruff、`py_compile`、定向测试和代码审计通过。

行为门失败只允许修实现错误，不得改第3节算法语义或参数。
