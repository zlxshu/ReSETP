# 机制计价的双路线重切：隔离开发合同

- 日期：2026-07-19
- 状态：`APPROVED_FOR_ISOLATED_DEVELOPMENT_ONLY`
- 用户授权：用户已授权自主规划和实现算法优化，但要求先用最低成本证据筛选；强效果成立前不进入阶段二、正式实验或全量算例。
- 候选身份：机制驱动ALNS中的一项自研局部搜索动作，不是HGS与ALNS的串联包装。

## 1. 这次只解决什么

已停止的“少量搬移”和“整路退役”都从已经形成的v7解出发，事后要求燃油路线减少。
最新证据中，唯一全电候选把燃油路线从1条降到0条，但成本由
`621.0831141941019`升至`685.7079097063714`；最低重整候选仍为
`661.4407527272798`。这说明现行成本下，燃油路线数量不是可以强制下降的目标，
而且逐客重插看不到两条路线应当怎样一起重新划界。

新候选只回答一个问题：

> 两条路线发生客户交换时，如果在重新划界的当下就把车场责任、燃油车/电动车、
> 补能和充电碳时机一起计价，能否找到“只看里程”的路线动作看不到的严格降成本方案？

它不要求燃油路线减少。车队构成只是完整成本优化的结果。

## 2. 为什么选它，而不重复旧路

1. 通用SISR加后悔修复已经在本仓库出现过机械失活，并在HGS子代教育门中只取得
   1/6双赢；直接重复不具备新信息量。
2. 对每个普通ALNS候选强制做全套机制完成，已在两道新题上相对v7倒退
   7.207%和5.416%；本候选只重算一对真正相关的路线，不重做整份方案。
3. Prins（2004）的Split说明“先给定客户序列、再按最小代价切成路线”是成熟骨架；
   Potvin和Rousseau（1995）的2-opt*说明可通过重新连接两条路线的边界进行成对改进；
   Vidal等（2014）说明多属性路径问题可共用搜索框架但使用属性专用评价组件；
   Hiermann等（2016）把ALNS、局部搜索和车型—补能标签求解嵌在同一混合启发式中。
4. 上述论文不包含ReSETP的车场、跨场费用、时变碳和完整排班语义。本项目只借成熟
   结构，逐段计价、保护接受和预算账均须自行实现并单独验证。

## 3. 冻结动作

运行器先从输入只生成一次第4节冻结的“原骨架机制完成”反事实；下列路线对选择、客户重切
和两臂比较均从该反事实出发。对其中一对非空路线A、B执行以下有界动作：

1. 删除车场端点和充电站，只保留两条路线现有客户顺序。
2. 构造`A+B`与`B+A`，并允许A、B各自正向或反向；最多8条唯一客户序列。
3. 在每条序列的客户之间切一刀，得到两个非空片段。路线数保持2，不做本轮已经失败的
   整路消除。
4. 两个片段继续占用原A、B的车场路线槽；切分方向允许客户在两车场之间重新归责。
5. 对每个切分同时计算两种分数。机制分数是两段路线局部成本之和：每段最多比较燃油车
   和电动车两种选择，电动车最多调用一次有界补能修复，局部成本计入当前车场、跨场服务、
   充电电价与充电碳成本。它只是有界的预排序近似值，不代表两条路线合在一起已经可行。
6. 里程分数只计算两段路程。完整臂按机制分数排序，删减臂按里程分数排序；为消除“完整版
   多算了一层”的算力差，两臂都计算并记录两种分数，但删减臂的机制分数只能在里程名次
   已冻结后写入审计账，禁止影响其选择。
7. 两臂共用完全相同的路线对、序列、切点、容量、时间窗、客户覆盖检查和确定性并列规则，
   候选集合及两种原始分数必须逐位相同；两臂只允许送入联合完成器的名次不同。
8. 每臂只把自己前4名送入同一个联合完成器。未选路线、未选路线的充电会话和客户骨架全部
   固定；完成器对两条新路线联合枚举最多4种燃油/电动车型组合，生成补能和有界充电时刻，
   再把两条路线放回完整方案，一起检查有限车队和共享充电位。行为门内，两条改动路线必须
   分配彼此不同且不与未改路线复用的实体车编号，使实体车衔接由构造保证；若有限车队没有
   两个空闲实体编号，该候选直接拒绝。两条路线分别
   可行但合在一起不可行的组合必须拒绝，不能用两段局部最小值代替联合可行性。
9. 每个送入联合完成器的切分至多形成4个完整方案复算，故每臂最多16个联合完整复算；
   最终至多提交1个严格降低统一完整成本的可行方案。不得要求燃油路线数、车型数或跨场
   客户数朝预设方向变化。
10. 充电开始时刻严禁做笛卡尔积。每个动作先从窗口端点、当前时刻、碳信号边界及“充电
    结束碰到边界”的时刻生成唯一列表；超过16个时，固定保留最早、最晚和当前时刻，再按
    排序后的剩余位置等距取满。先把至多8个动作各自的局部最优时刻一起装入，联合检查1次；
    若共享充电位冲突，则从原可行时刻表出发，按局部节省从大到小逐个尝试至多8次。这样
    每个车型组合最多形成1个最终时刻表、最多9次联合可行性检查，不存在`16^8`隐藏枚举。

默认上限冻结为：

| 项目 | 上限 |
|---|---:|
| 候选路线对 | 3 |
| 每对唯一客户序列 | 8 |
| 每条序列切点 | 16；超过时按首、尾和等距位置确定性抽取 |
| 每个切分的路线局部车型方案 | 每段2个、两段共4个 |
| 每个切分的电动车补能修复 | 每段1次、两段共2次 |
| 每个联合完成切分的车型组合 | 4 |
| 每个车型组合的充电动作 | 8 |
| 每个充电动作生成/保留的候选开始时刻 | 生成数如实记账；按第10项最多保留16 |
| 每个车型组合的联合可行性检查 | 9 |
| 每臂送入联合完成器的切分 | 4 |
| 每臂联合完整复算 | 16 |
| 接受方案的独立复算 | 1 |
| 共用反事实的联合完成切分 | 1 |
| 共用反事实的车型组合/联合完整复算 | 4/4 |
| 共用反事实的独立复算 | 1 |
| 单次调用接受动作 | 1 |
| 行为门调用轮数 | 1 |

候选路线对按以下无权重规则排序：先选存在车型不同、车场不同、充电或跨场服务的路线对，
再按两路线客户间最近距离，最后按原路线编号。不得在看过行为门结果后改变排序或上限。

## 4. 保护接受

一个候选只有同时满足下列条件才可接受：

- 统一完整成本严格低于原方案及“原骨架只做同一机制完成”的反事实方案；
- 完整成本与独立复算误差不超过`1e-7`；
- 两条路线客户边界真实改变，客户覆盖恰好一次，路线数保持不变；
- 时间窗、容量、有限车队、SOC、充电连续性、共享桩和参与条件零违规；行为门还须证明
  两条改动路线使用不同且未被其他路线占用的实体车编号；
- 未选中的路线及其充电会话与反事实方案在忽略规范化实体车编号后逐位一致；
- 完整完成器没有改变已冻结的客户骨架；
- 完整路线搜索评价为0；两种预排序分数、路线局部车型方案、补能修复、充电开始时刻、
  联合车型组合、联合可行性检查、联合完整复算和独立复算分别记账，任何一项超过第3节
  冻结上限即失败。

反事实方案必须在两臂运行前由运行器从同一输入只生成一次，且保持全部客户骨架不变。
完成器先计算每条路线的燃油/电动局部分数，再按以下固定顺序形成最多4个全局车型方案：
当前车型方案、各路线局部最便宜方案、从当前方案只改变一条路线的方案按预计降幅和路线
编号排序；逐位去重后截到4个，不得枚举其他组合。每个方案沿用第3节第10项的充电时刻规则；
全局充电动作超过8个时，只尝试局部预计节省最大的8个，其余动作保持原样。反事实最多做
4次联合完整复算和1次独立复算。随后冻结其方案哈希、成本、完成记录和独立复算记录，两臂
只能读取同一不可变对象，不能各自重算。
反事实的全部账单独列示，不得藏入任一臂或不计费。它只用于隔离归因，不能单独成为本算子
的输出。若没有合格的双路线重切候选，必须逐位返回输入。任何异常、非有限数、账本缺项
或哈希漂移均失败关闭。

## 5. 最低成本行为门

行为门不得使用已经反复看过的20客户题，也不得调用ALNS、HGS、winner或任何完整路线搜索。
先固定三个仓库内人工小夹具：

1. **机制绑定夹具**：两条路线重新划界后，完整机制计价臂必须得到可独立复算的严格成本
   改善，并严格优于只看里程的删减臂；至少一项车型、补能、碳时刻或跨场责任必须真实改变。
2. **不绑定夹具**：当前路线边界已经最优，两臂都必须原样返回，不得制造虚假改善。
3. **联合冲突负例**：至少有一个切分的两段路线分别可行，但两辆不同电动车在同一时段
   占用同一个单桩公共充电站，放回完整方案后触发共享桩冲突；联合完成器必须识别并拒绝。
   充电动作必须真实附着于各自路线，禁止用没有对应路线的游离动作制造冲突。

绑定夹具必须至少存在6个通过共同基础检查的不同切分。运行前由独立穷举复核器确认：
按统一完整成本计的最优切分不在里程前4名、但位于机制分数前4名；否则夹具无区分力，
行为门不得开始。求解模块不得写死预期客户序列；运行器须使用不调用候选排序代码的穷举
复核器，独立计算全部冻结切分，确认两种排序、联合可行性和最终成本。夹具只证明动作和
归因，不作为算法性能证据。

另以精算上限`0/1/2/4`验证无越界、无`target+1`、去重闭合和确定性；加入布尔冒充计数、
伪造完成记录、重复客户、丢客户、非配对路线漂移及复算成本篡改负例。运行器先只做
`--preflight-only`；代码、输入、阈值、测试和保护文件哈希提交冻结后，行为门只执行一次。

行为门的通过条件全部为机械条件：

- 机制绑定夹具完整臂严格胜输入、反事实和里程删减臂；
- 绑定动作非空且机制字段真实改变；
- 不绑定夹具两臂逐位不变；
- 联合冲突负例被拒绝，且账本明确记录“分别可行、联合不可行”；
- 全部复算、可行性、预算、去重、哈希和路线搜索零调用账闭合。

任一条件失败即
`STOP_MECHANISM_PRICED_PAIR_RESPLIT_BEHAVIOR`，不得调夹具、补候选、改上限或进入搜索门。

## 6. 行为门之后仍受限制

只有行为门机械通过，才可另立两道全新、结果盲小题的一种子极小搜索合同，比较：

- 当前v7；
- v7加机制计价双路线重切；
- 相同动作但只按里程预排序的删减臂。

当前权威`check_solution`只检查有限实体车数量，不检查同一实体车多趟任务的时间重叠；现有
严格多趟证书又不接受途中公共站补能。因此本行为门只证明“改动路线各占一辆不同实体车”
这一受限版本，不能声称已经验证可复用实体车的多趟衔接。进入任何极小搜索门前，新合同
必须二选一：继续保留独占实体车限制并如实报告适用范围；或先另立并通过公共站感知的多趟
衔接证书。不得用当前主检查器把未检查的多趟衔接写成已闭合。

后续比较必须同时过两把公平尺：

1. **同完整评价预算门**：同起点、同完整评价上限、同独立复算器；双路线重切两臂还须共用
   第3节全部内部上限并逐项报告代理和局部完成账。
2. **同墙钟门**：同机、同进程条件、同墙钟上限，所有算法均在“先碰到完整评价上限或墙钟
   上限”时立即停止；运行次序配对轮换，不能让固定先后顺序占便宜。

完整臂必须在两道新题的两把公平尺下都严格胜v7和删减臂，且没有名次反转、没有内部账
越界并真实触发机制绑定；否则立即停止，不补种子、不换题、不调参数。只有该极小门出现
强阳性，才允许另立公平的纯HGS、纯ALNS和v7比较合同。

本合同不授权修改
`solver/src/setp_solver/cost.py`、
`solver/src/setp_solver/check.py`、
`solver/src/setp_solver/search/evaluation.py`或正式`winner.py`，也不授权阶段二、
China81、正式E2、E2--E7重跑或全量benchmark。
