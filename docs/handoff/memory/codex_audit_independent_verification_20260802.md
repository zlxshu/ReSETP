## 3. 一条必须避免的错误推断

**不得声称“接通多趟能救 E5”。** 多趟重装诊断 992 份证书中仅 81 份出现单车 2 趟（上限即 2 趟），
4737 个 EV 趟中只有 3 笔趟间补电（8.168 / 12.180 / 17.835 kWh），**结束电量越过 85% 折点者为 0**。
且 `eq:trip_linkage` 的趟间补电窗口在车场侧，与 E5 的途中公共站机制不同侧。
手上证据不支持该论断；把它写进建议会让用户为错误理由付出一周算力。参见 [[mechanism-condition-absent-in-instances]]。

## 7. Codex 最终裁决：实验可信度与新会话入口（2026-08-02）

### 7.1 一句话结论

**数据记录与多数已保存数字大体可信；当前论文的实验合同不可信到可投稿程度。**
没有发现删除不利结果、按方向筛选、登记文件漂移或把诊断冒充正式结果的证据。真正的缺口是：
E2 的旧车型结果被并入现行车型叙述，E3/E4/E6 的一路一车结果被写成完整多趟模型结果。
前者是车型合同错配；后者因 EV 数量实际触顶而改变可行搜索空间，不能笼统降格为“只坏了标签”。

### 7.2 四层可信度必须分开

| 层次 | 当前判定 | 证据边界 |
|---|---|---|
| 文件与记录完整性 | 高 | 85 份清单登记 2365 个文件，缺失 0、哈希不一致 0；不利结果保留 |
| 保存解重新记账 | 大体通过 | 3015 份中 3009 份通过；6 份 E2 因旧/新电池合同不同停止 |
| 实验与论文模型一致性 | 不通过 | E2 车型合同不一致；E3/E4/E6 多趟声明与一路一车正式链冲突 |
| 投稿准备度 | 不通过 | E3 证据包不完整，E5/E7无正式效果，车型表仍有错误与“待补”字段 |

哈希一致只证明登记文件没有漂移；保存解重放只证明已有解的合法性和记账兼容，均不能证明搜索全局最优，
也不能替代 E3 缺失的完整 solution 与运行时 `china81.py` 哈希。

### 7.3 E3 车型证据的最终口径（取代“完全闭合”）

前述提交时间、E6 的 77.28 kWh 满充见证及八项共同哈希，足以形成“E3 使用现行 77.28 kWh 车型”的
**高可信事实判断**，可支持工作层面的 E2 旧车型 / E3--E6 现行车型分栏。
但 E3 正式包没有锁运行时 `china81.py`，也没有保存完整解；时间顺序不能排除当时未登记的工作树状态。
因此从投稿级溯源标准看，证据包仍未百分之百闭合，36.4773% 目前只能在聚合层核验。
若该数字作为正文主结果，应按原设计补一次保存完整解、运行时车型参数与源码哈希的重跑；这是证据修复，不是按结果调参。

### 7.5 多趟三方案的可信度边界

- `M1`：把论文和算法正式收窄为一车一趟，现有 E3/E4/E6 数字可保；E4 必须明确为 EV 车队上限 3 辆的受限情景。
- `M2`：保留完整多趟，先补 E4 连续电量接口并修 E6 三份冲突，再重跑 E3/E4/E6；结果方向和幅度未知。
- `M3`：只能诚实声明算法使用“按路线数计车”的受限搜索并量化事后可重装数量，不能证明完整多趟模型已被实验验证，
  也不能替代 E4 重计价和 E6 冲突修复。不得把 `M3`写成与 `M1/M2`等价的模型闭合。

现有 992 份多趟诊断还明确反对“接通多趟可以救 E5”：4737 个 EV 趟只有 3 笔趟间补电，
越过 85% 非线性折点者为 0，且趟间车场补电与 E5 的途中公共站机制不是同一对象。
