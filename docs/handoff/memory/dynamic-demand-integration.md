user 提出(2026-06-22):模型四要素 = 时变电网碳强度 + 动态需求 + 车场协同 + 收益公平。若**动态需求实验只"用全模型跑一遍"、不展示其余三要素真参与了动态路径决策**,则动态需求在文中割裂,审稿判"罗列堆砌/创新点不清"——正是 [[project-plan-overview]] 既定战略点名的真风险(审稿真风险=对手单薄/创新点不清,非赢得不够多)。

**Why:** 整合框架 > 功能清单;要素必须交互,否则四个机制像各自独立的勾选项。

**How to apply(后续 E7/T9 动态实验修改 + 撰写时落实):**
整合框架 = **把动态需求定位成"同时激活三机制的压力测试"**:每个新到需求都要在 协同+公平+碳时序 三重约束/目标下被吸收。需给三个交互证据(指标/案例),而非只"跑了动态":
1. **动态 × 协同**:新需求经跨车场(cross-site)被吸收的比例/案例;对比"无协同动态基线"——协同降低吸收动态需求的成本。
2. **动态 × 公平**:沿滚动时域**逐阶段**跟踪公平度量,证明新需求涌入下公平约束 θ 仍维持(动态威胁公平→机制保住它=最强整合故事);对比"公平盲动态基线"会让车场利润倾斜。
3. **动态 × 时变碳**:新需求再规划时考虑其 **EV 未来充电时点的电网碳**,把充电移到干净窗口/脏窗口改用 CV;对比"碳盲动态再路由"。

**两个层面都要查/落实:**
- 模型层:确认滚动再优化(`run_rolling_reoptimization`/E7)**每阶段解的是完整目标(协同+公平+碳)**,非简化贪心再路由。**待查 E7/dynamic 代码**。
- 展示层:E7/T9 报上面三个交互指标/案例,不能只"用全模型跑动态"。

**碳的微妙处(关联 [[figure-redesign-task]] 碳强度标定 / E4 碳敏感):** 动态×碳只有在解里**有 EV 在充电**时才可见;真实 UK 碳价(£50/t)下最优=全油车、无 EV → 该交互退化。故动态×碳的展示要么在有 EV 的碳区间体现,要么经 E4 碳敏感串起来。

**2026-07-01 规划状态: ACTIVE / 必须进入后续 E7-T9 规划。**
这不再只是"先记着"。后续任何正式动态需求实验或论文 T9 重写,必须先把下面三项写成验收门槛:
1. **动态×协同门槛:** 报告动态新增/变更需求中由非原车场服务、跨车场调拨或共享车辆池吸收的数量、比例和至少一个可解释案例;若协同关闭/独立车场基线存在,需给出成本或可行性差异。
2. **动态×公平门槛:** 每个滚动阶段报告车场收益、公平比或公平约束状态;若当前实现里 `min_fairness_ratio=off`,必须先标为未完成,不能把 T9 写成公平参与了动态决策。
3. **动态×时变碳门槛:** 报告动态重规划是否改变 EV/CV 分工、充电动作、充电时段平均碳强度或阶段新增碳排;若无 EV 充电或碳盲/碳感知对比不可见,必须诚实写成该交互在当前场景退化,不能只报告累计碳。

**停止条件:** 若 E7/T9 只能证明"动态事件进入求解器、路径冻结和状态继承可行",但不能证明上面三类交互,则动态需求只能作为接口/可行性实验,不能作为"动态需求与协同、公平、时变碳耦合"的论文贡献证据。
