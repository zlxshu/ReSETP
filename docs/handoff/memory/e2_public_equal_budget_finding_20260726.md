封存 P1 的"MV-HGS-SP 对 PyVRP-HGS 母体 264 胜 16 平 0 负"是**预算差撑出来的**。
该表的 `cpu_ratio` 为 1.47--2.00，即约 434 秒的算法比约 240 秒的母体。

等迭代（6200 代）对照，6 题 × seed1，三臂母体成本逐位配对：

```
hybrid   vs 等预算母体 : +0.0963%   （2 胜 4 负，hybrid 更差）
hybrid   vs 短预算母体 : -1.2411%   （封存表口径）
等预算母体 vs 短预算母体 : -1.3361%
```

母体仅凭获得同等预算即改善 1.34%，超过 hybrid 相对短预算母体的 1.24% 领先；同迭代
数下 hybrid 的 CPU 还略高（中位 1.04）。该口径对 hybrid 已属宽容——正式引擎按墙钟
停机，同墙钟下母体可跑更多代。

**D4 定稿（30 配对单元 = 6 题 × 5 种子）**：hybrid 18 胜 12 负，均值 Δ=−9.96、
95% 区间 [−23.6, +3.7] 跨零、Wilcoxon `p=0.2894`、符号检验 `p=0.3616`、合计 −0.1003%。
**等预算下融合结构与纯 PyVRP-HGS 无统计可区分差异。**封存表 +1.2411% 中约 92% 由预算
差解释，剩余不显著。D3 单种子曾读出相反方向（+0.0963%），两者均不显著，以 D4 为准。

**因此后续唯一诚实基准线是：在等迭代（并最终等墙钟）下真正赢过 PyVRP-HGS 母体。**
此前所有"相对母体的领先"须按此重算。

三个方向不是三件独立的事，而是同一结论的三个侧面：**在这批算例与该预算下，没有任何
东西比把预算直接花在 HGS 迭代上更划算。**另两个方向：

- **地理分解**：V13 算例无局部性。BKS 路线地理跨度中位 215、全区域跨度 282；纯地盘
  路线 0--3.3%；最近/次近车场争议度对"是否跨界"无预测力（等同随机抽取）。
- **喂饱路线池**：集合划分不是失效而是被饿死（PR17B 上 40 个解仅产出 38 条不同路线；
  池超 600 后按最便宜截断破坏划分可行性；12/12 次最终解均来自 HGS 轮）。把池子喂到
  6--8 倍后结果三胜三负、合计仅 −0.088%，按预注册规则关闭。

已闭合的两个前置项：BKS 来源为 Vidal 等（2013）自身最好值，对比集三家均未打破，
刷新 BKS 是真实未达成目标；`PyVRP-HGS` 命名正确（pyvrp 0.12.2 `GeneticAlgorithm`），
该待核项关闭。

内部贡献主张在等预算下不成立；与文献值的比较不因此失效但须披露预算与硬件。
