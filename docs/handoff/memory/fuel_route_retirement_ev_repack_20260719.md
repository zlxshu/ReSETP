# 燃油路线退役—电动重整：行为门与止损

- 日期：2026-07-19
- 状态：`STOP_FUEL_ROUTE_RETIREMENT_EV_REPACK_BEHAVIOR`
- 证据目录：`baselines/algorithm_prototypes/unified_mechanism_alns_20260719/fuel_route_retirement_ev_repack_behavior_gate/`
- 证据等级：只限开发阶段的零搜索行为验证，不是性能试验或论文结果。

## 为什么做

前一版只搬一两名客户，通用收尾会把搬移撤回。新候选因此把一条燃油路线整体拆回待安置区，用后悔插入重组；必要时先从另一条路线让出一名客户。客户骨架固定后，才联合选择车型、补能和碳时刻。方法依据和许可证边界登记在
`docs/handoff/algorithm_source_and_license_register_20260719.md`，核心来源为
Lim与Zhang（2007）、Nagata与Bräysy（2009）、Ropke与Pisinger（2006）、
Hiermann等（2016）及Vidal等（2014）。本项目依据论文思想独立实现，没有复制论文伪代码或无许可证源码，也不宣称法律意义上的clean-room。

## 冻结验证

预登记只允许一个20客户绑定场景和一个25客户全电对照，不调用ALNS、HGS或完整路线搜索。绑定题最多处理2条源路线、8个一级让位、10个预筛骨架和4个完整精算；无让位版本共用同一实现。候选必须同时严格降成本、减少至少1条燃油路线、不增加路线数、保持客户覆盖和固定骨架，否则不得接受。

13项测试、ruff、py_compile、账本篡改探针和独立代码审计先通过。实际绑定题形成9个唯一骨架，对前4个做完整精算：

| 候选 | 完整成本 | 燃油路线 | 是否退役源路线 |
|---|---:|---:|---|
| 1 | 661.4407527272798 | 1 | 否 |
| 2 | 748.7076232816380 | 1 | 是 |
| 3 | 685.7079097063714 | 0 | 是 |
| 4 | 694.8015206239123 | 1 | 否 |

源解成本为`621.0831141941019`、燃油路线1条、路线3条。因此即使候选3实现全电，仍比源解贵`64.6247955122695`；四个候选没有一个同时降成本和减少燃油路线，接受数为0。25客户全电对照候选、修复、精算、复算和接受均为0，完整解逐位不变。路线搜索评价为0。

## AppleDouble事故与恢复

唯一一次算法调用已完成两场景并写入`raw_runs.csv`，但移动硬盘随后生成`._*`旁文件，原封存程序按失败关闭并写入`execution_failure.json`。原事故6个文件及哈希先提交保留。恢复工具只读取原始两行和已保存解快照，重新检查可行性和成本，共做8次独立复算；它不调用候选生成、ALNS、HGS或winner。恢复后保留四份原包装文件副本、事故记录和原始CSV，并对13件最终制品重新验签。独立审计结果为13/13最终哈希、6/6事故哈希、4/4候选快照和燃油路线数全部一致，递归旁文件数为0。

## 裁决与后续边界

本候选停止。不得在同一20客户题上调参数、扩候选数或换接受规则救结果；不得运行D3、正式算法比较、全量benchmark或阶段二。

负结果的含义很具体：从已经形成的强v7解出发，事后强迫整条燃油路线退役，即使能得到全电结构，也需要先承受明显成本上升；当前“只接受一步严格改善”的外置修补跨不过这个过渡。它不证明电动化路线结构没有价值。若继续研发，必须另立合同，让车型、补能、车场和路线结构在搜索过程中共同形成，而不是在路线已定后再修补；先用零搜索不变量和新鲜小题的极小搜索门证伪，仍不得直接进入正式比较。
