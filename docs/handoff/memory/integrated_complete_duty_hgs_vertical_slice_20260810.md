# 统一完整 Duty-HGS 第一个可运行纵切（2026-08-10）

## 为什么改

旧“共用 HGS”仍把交叉和局部搜索写死为公开路线内核。私有候选先投影成简化路线，再由外层补充充电和机制；完整评价失败时还会退回简化路线分数。这使完整问题无法持续决定种群生存和父代选择。

## 已落地

- `IntegratedGeneticAlgorithm` 保留一套 HGS 控制，但允许问题适配器直接生成和修复完整候选。
- 私有种群直接存 `DutyIndividual`；指纹包含充电安排，多样性仍只看路线邻接。
- 缺客户或无完整评价的候选不入种群，不得用路线代理分数顶替。
- 静态和动态技术入口都调用 `run_integrated_problem_hgs`。
- 整趟交叉允许跨车型、跨车场转移任务，但不改实体车身份；同一交叉枚举全部合法接收车并用完整成本选择。
- 教育采用首个可靠改进，并按完整指纹与当前惩罚状态缓存教育结果。
- 运行时审计是否真正导入 `pyvrp`，不再把“同一 Python 环境安装了冻结对手”误当为依赖。

## 当前证据

- JJJ10、seed 11、10 轮技术试跑中，完整解与服务量不变，增量评价 5574→730，墙钟约 9.54 s→1.36 s。该对照来自临时技术目录，不是正式实验。

- 动态一轮：50/50 客户、13264/13264 需求、完整可行、已执行历史保持。
- `cost.py` / `check.py` / `search/evaluation.py` 未改。

## 当日后续纠正：只保留单链串行算法

用户明确否决多视角、双分支和算法并行设计，并要求半成品只做最低成本的快速否决，不再反复跑 28 例。活动公开算法因此收敛为一条链：交叉、原生局部改进、车型/车场与路线旋转联合改进、客户移动联合改进，最后只接纳一个子代。原子代与改进子代双收、客户改进只进最好解档案的设计均已删除。

车辆与客户改进各用独立随机流，只为避免二次局部搜索误耗主 HGS 的随机序列；算法控制、种群和子代仍各只有一套，不是并行算法。相关测试 41/41 通过。

串行版仅做两个 30 代公开探针：PR11A 为 7497→7481，客户步骤无额外改善；PR16A 为 15952→15950→15938，客户步骤在路线步骤后再降 12。两例客户数和需求量均完整。这只证明串行接线和两个部件能在真实公开算例上产生净改进，不代表总体性能。

客户移动随后改成先用便宜的原生增量成本排序，再按顺序做昂贵联合评价。PR16A 的最终成本和路线哈希不变，昂贵联合评价 36781→833、旋转评价 1666724→81319、客户部件墙钟 1.30454 s→0.261744 s；PR11A 的零客户增量反例仍完整查完并保持成本不变。该优化没有新增阈值或截断。

用户纠正前的三轮 28 例、100 代诊断原样保留，只用于查双收、替换和随机流串线，不再指导为半成品追加全量测试。下一步先在单个最小公开算例上定型和反证，过关后才逐级扩大；不得直接跳到 28 例或 20 分钟。

## 当日最终收口：底座可用，核心问题未解决

用户最终指出，本轮仍把接线、记账、充电候选和小规模试错当成算法突破，要求写入交接并告一段落。本轮停止，不继续实验、算法修改或 China81 调整。

当前串行公开版只有两个 seed 11、30 代探针：PR11A 相对复制底座改善 0.213419%，PR16A 改善 0.087763%。它们不是同墙钟多种子对照，不能证明当前版本相对冻结 HGS 存在性能优势；旧 fast-only 的 28 例结果也不能转移给当前算法。

私有 PRD50 三个 seed、各 3 代的最终机制精修相对路线版成本变化为 -0.006723%、0、0。只有 seed 1 接受一次时变碳充电，成本下降 0.129978、排放下降 1.732579 kg；其余两个 seed 没有接受问题机制动作。三个 seed 的 3 次交叉都得到 3 个可完整评价子代，但内部各有 95—115 个接收组合死于充电补全。这证明统一控制和完整评价确实跑通，也证明当前自研部件尚未形成稳定增量。

因此，这一节点的准确定位是“统一、可运行、可核账的算法底座”，不是已经成形的论文主算法。它相对冻结 HGS 的已知优势是完整问题处理和决策输出能力，不是已证明的公开求解性能。私有机制主要位于最终解精修，存在被审稿人视为“HGS 加末端修补”的风险。

Claude Opus 与 Codex 均反对当前进入 20 分钟或 28 例长跑。需要保留两项纠正：每代接纳一个子代是正常 HGS 种群流程，不等于单解搜索；Claude 提到的 0.5% 噪声线和 80% 失败集中线没有项目依据，不作为门槛。

当前没有运行中的算法或实验。若用户以后重新启动，代理建议先提出一个冻结 HGS 不能等价替代的串行核心搜索机制，并在施工前说清搜索困难、不可替代性和最小反例；这只是下一入口建议，不构成授权。
