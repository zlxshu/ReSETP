- 当前禁止：性能门、完整 28 题、China81、阶段二、论文优越性结论

## 1. 目标

保留第一候选已经出现的多车场连续段阳性信号，但修掉其高频 Python 包装和
“先跑母体、再追加专家”的结构。第二候选以 PyVRP 0.13.4 ILS 为唯一母体：

1. 普通时刻逐位沿用母体；
2. 只有发生预先定义的搜索事件时，才维护一个至多 8 个解的共享精英库；
3. 触发增强时，用有界的多车场/时间窗连续段扰动替换母体本轮原生扰动；
4. 扰动后的解交给同一套 PyVRP C++ 局部搜索精修；
5. 五类 ReSETP 机制始终登记在算法中。公开原题没有电动、充电、碳、公平或动态
   字段时，对应机制自然留下“不适用”记录，不设置人工关闭开关。

这仍是一套完整算法，不因公开题缺少部分业务字段而变成另一套算法。

## 2. 对 Claude 原方案的保留与校正

### 2.1 原样保留的主方向

- PyVRP 0.13.4 ILS 作为强母体；
- 多车场连续段扰动、三视角精英记忆和五机制常驻；
- 事件驱动而非每轮维护；
- 专用扰动替换而非追加母体扰动；
- 独立随机流、最好解保护、有界候选账；
- 先过最低成本工程门，再决定是否允许性能短门。

### 2.2 必须校正的四点

第一，第一候选 PR11A 的 0.521% 改善来自单题单种子的完整组合，不能据此声称
“专用动作的真实收益大于 0.521% 再加回 17%--22% 的迭代损失”。17%--22% 是
少跑的迭代比例，不是可线性相加的成本收益；档案、跨语言包装和搜索轨迹变化也没有
被单独归因。

第二，AILS-II 支持“根据搜索反馈调节扰动强度和接受行为”的方向，但当前查到的
原论文和官方源码不是“连续失败后固定执行 1、2、3 个客户段”这条规则。本项目可以
试 1--3 段分级，但必须写成本项目设计，不能冒充 AILS-II 原规则。C2-R1 先实现
反馈控制接口，G0 不冻结正式性能参数。

第三，PyVRP 0.13.4 没有现成的“替换扰动且回报 ILS 接受事件”回调。为真实获得
接受事件并保留原接受规则，本候选迁入并修改上游很小的 Python ILS 循环；C++
局部搜索、成本评价器和可行性语义不改。迁入文件必须附上 MIT 版权、许可证、
上游版本和原文件 SHA-256。

第四，China81 的 `SEG-GEN-02` 依赖本项目完整解、客户责任、车型、补能和碳时刻，
不能原样用于 V13 公开题。公开题算子只借用其“64 个源段、每段 6 个位置、48 次
路线级检查、12 次完整评价”的有界筛选思想；排序只能使用 V13 原始的车场、距离、
载重、车辆和时间窗数据，禁止虚构“客户归属车场”或新增业务罚项。

## 3. 算法故事

通俗说，这台机器分五步工作：

1. **母体一直跑**：PyVRP ILS 负责主要搜索。
2. **三种眼光记好解**：同一个小型精英库分别按总质量、车场用法和路线差异看解，
   不是每轮维护三个庞大种群。
3. **卡住时换一种跳法**：用跨车场连续客户段搬移或互换，替换母体本轮普通扰动。
4. **跳完马上精修**：仍由 PyVRP 原有 C++ 局部搜索收尾。
5. **完整模型由机制专家接管**：以后进入 China81 时，同一调度骨架再让车型充电、
   碳择时、公平和动态专家按真实字段工作；公开题缺字段时它们自然不动作。

它对应陈雨蝶式叙事，但不是照抄：强母体负责广搜，三视角精英库负责多样性，
反馈式扰动负责脱离停滞，母体局部搜索负责后期精修，ReSETP 机制专家负责本文模型。

## 5. G0 四道工程门

### G0-A：母体复刻逐位一致

在 PR11A、seed 1、固定 5/1000/5000 次迭代下，对比上游
`IteratedLocalSearch` 与迁入循环的纯母体模式。最终解、逐迭代成本记录、母体随机数
状态、迭代数必须全部相同。任一不同即停止，不准进入后续门。

### G0-B：开销拆账

固定 5000 次迭代，交错运行以下三臂：

1. 上游母体；
2. 迁入循环但没有事件钩子；
3. 迁入循环加常驻机制登记和事件式精英库，但不触发专用扰动。

至少 5 个重复，报告中位墙钟比。第三臂相对母体中位开销目标不超过 2%。若超过，
只允许根据分项计时删除明确累赘，不允许借此跑性能题或调搜索参数。

### G0-C：替换动作与预算账

在人工多车场时间窗夹具上强制一次触发，必须同时满足：

- 专用连续段确实改变客户所在车场并保持完整可行；
- 本轮原生扰动调用为 0，零扰动局部精修调用为 1；
- 总源段不超过 64、每源段位置短名单不超过 6、路线级检查不超过 48、完整评价
  不超过 12；
- 里程只能作为次级排序信息，不能一票否决车场结构改善。

### G0-D：语义与许可

- 五机制在算法登记中始终存在；
- V13 缺失字段只能记录自然不适用；
- 公开题算子没有虚构客户责任、碳、电价、公平或动态字段；
- 迁入源码附 MIT 全文、上游文件哈希和修改说明；
- 新代码、合同和证据全部位于 ReSETP 仓库。

## 6. G0 后的停止点

G0 通过也只表示“母体没有被接坏、开销病灶已拆清、替换式动作是真的、语义和许可
合规”，不表示算法更强。G0 收口后必须停下向用户复盘；PR11B/PR17B/PR21B 的
首次性能短门、PR16A/PR24B 确认门、扩种子、完整 28 题和 China81 均需另批。

已暴露的 PR11A/PR17A/PR21A 只能用于工程归因，不再用于 C2 的性能调参。若后续
获批，第一次性能判读使用仍未被第一候选看过的 B 题；确认题继续封存。
