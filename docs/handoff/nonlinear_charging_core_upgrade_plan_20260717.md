# 非线性充电核心模型升级实施方案

状态：2026-07-17 依据正式固定方案复算冻结；仅制定补丁和重跑顺序，尚未修改E7保护源或共享求解器。

## 1. 为什么必须升级

零搜索固定方案复算不是“证明非线性更精细”的装饰实验。主曲线`NL90_mild`下，`L->NL-E/C`已有168个seed--day方案不可行、14个方向反转；压力曲线`NL80_stress`相应为476和28。不可行动作全部集中在日内相邻趟次之间，首趟前整夜充电在重新择时后均可行。因此，现有线性模型系统性高估了部分趟间可补电量，并可能改变时变碳强度的结论方向，已触发合同中的核心升级门。

本次升级的目标不是增加一个复杂机制，而是恢复三项最基本的一致性：排班可行性必须使用与SOC一致的充电时长；分时排放必须按真实分段功率分配电量；算法评分、最终检查和执行证书必须调用同一物理内核。

## 2. 唯一数学内核

求解器新增唯一的累计充电时间函数$\xi(b)$及其逆函数，不在排班、成本、检查和动态模块分别重写公式。对容量$B$、SOC断点$0=z_0<\cdots<z_L=1$、额定功率$P$和相对功率$r_\ell$，定义

\[
\xi(b)=\sum_{\ell=1}^{L}
\frac{3600}{P r_\ell}
\left[\min\{b,Bz_\ell\}-Bz_{\ell-1}\right]_+ .
\]

从$b^-$充至$b^+$的持续时间为$\xi(b^+)-\xi(b^-)$。给定可用时长$g$，从电量$b$最多可充至

\[
H(b,g)=\min\{B,\xi^{-1}(\xi(b)+g)\}.
\]

对同一实体车的趟次链，设第$j$趟耗电$e_j$、趟间可充时长$g_j$，从末趟向前递推最小发车电量：

\[
R_m=e_m,\qquad
R_j=e_j+\xi^{-1}\!\left([\xi(R_{j+1})-g_j]_+\right),\quad j=m-1,\ldots,1.
\]

该式是现有线性递推$R_j=e_j+[R_{j+1}-Pg_j/3600]_+$的严格推广；当所有相对功率均为1时必须逐位退化为旧式。趟间充电从上一趟剩余电量$c_j=R_j-e_j$充至$R_{j+1}$，时长为$\xi(R_{j+1})-\xi(c_j)$。

## 3. 数据和方案口径

三个情景必须同时保留：`L100_control`为$(0,1)$、相对功率$(1)$的退化对照；`NL90_mild`为$(0,0.9,1)$、$(1,0.5)$的正文主曲线；`NL80_stress`为$(0,0.8,0.9,1)$、$(1,0.5,0.25)$的压力曲线。它们是归一形状情景，不冒充特定车辆实测标定。

同一情景内，车场和公共站使用相同归一形状、分别按22 kW和节点额定功率缩放。这样$\xi_s$仍随充电技术$s$变化，同时避免在没有车辆—充电器匹配实测数据时伪造两套曲线。后续若获得匹配实测曲线，只能新增预注册外部有效性情景，不能替换本次冻结曲线。

## 4. 代码改造边界

### 4.1 物理与解结构

1. 将已经过数学测试的纯函数接口迁入`solver/src/setp_solver/charging_curve.py`，定义不可变的`ChargingCurveSpec`和按容量、额定功率缩放的曲线对象；基线目录只能调用求解器内核，不能反向成为生产依赖。
2. `PriceParameters`增加`charging_curve_id`、SOC断点和相对功率元组。常功率对照显式设置`L100_control`，不能以缺省空值悄悄回退。
3. `ChargingAction`在末尾增加`start_energy_kwh`、`end_energy_kwh`和`charging_curve_id`。旧JSON允许只读兼容，但任何新正式运行的正电量动作缺少这三项都应失败，不能用总电量和持续时间猜测分段功率。

### 4.2 成本、排放与可行性

1. `cost.py`保留现有均匀分配函数只供`L100_control`和历史重放；新增按动作SOC区间逐段积分的唯一接口。电量必须满足$\sum_t y_{qt}=Y_q$，占用时间必须等于$\xi(b^+)-\xi(b^-)$。
2. `check.py`同时验证SOC边界、动作电量差、曲线持续时间、路线时钟、精确半开区间并发和48槽容量。`energy\le P\Delta`只能作必要条件，不能替代曲线等式。
3. `profit.py`、执行记账哈希和所有解序列化把新增动作字段纳入闭合，防止相同总电量但不同SOC区间被误判为同一方案。

### 4.3 路径充电修复与碳感知择时

1. `support/charging.py`在每次充电前显式维护到站电量，按$b^-\to b^+$生成动作；公共站插入、车场首趟前充电和固定路径重放共用同一持续时间函数。
2. `support/carbon_charging.py`的候选点由“时段边界及边界减总时长”推广为“时段边界减每个充电阶段相对起点”。分时电量按阶段功率积分，不能再均匀分摊总电量。
3. 路径改变后必须重新构造SOC账本和充电阶段；不得仅复用旧动作的`occupancy_minutes`。

### 4.4 多趟排班和动态继承

1. `search/multitrip_schedule.py`把所有$Pg/3600$可补电量和$3600Y/P$时长替换为$H(b,g)$、$\xi(b^+)-\xi(b^-)$及第2节的后向递推。首次分配实体车时，也须按当前剩余电量和趟间时长判断可达发车电量。
2. `validate_multitrip_certificate()`、`certificate_charging_actions()`与`certificate_execution.py`按证书记载的起止电量复算持续时间；证书需要冻结曲线ID和曲线参数哈希，而不能只冻结额定功率。
3. `dynamic_multitrip_schedule.py`和E7状态继承使用同一曲线。冻结动作保留其已执行SOC阶段；未来动作可重排开始时刻，但不得把非线性动作重新解释为恒功率动作。

## 5. 必须修改和必须保持不变的接口

预计直接修改的核心文件为`solution.py`、`prices.py`、`cost.py`、`check.py`、`profit.py`、`support/charging.py`、`support/carbon_charging.py`、`multitrip_schedule.py`、`dynamic_multitrip_schedule.py`、`certificate_execution.py`、`execution_accounting.py`及对应序列化入口。所有直接出现`energy/power`、`gap*power`或均匀分配$y=Yg/\Delta$的正式调用点须逐项分类，不能只改论文公式。

必须保持不变的研究合同包括：客户、距离、需求、时间窗、车辆容量、碳强度、价格、配额、公平阈值、动态事件流、评价器的非充电成本项和对比算法预算。非线性升级不得借机改路线数据或删除难例。

## 6. Python数学与回归门

每次更改公式、曲线参数、SOC字段或持续时间接口后，至少运行以下检查：

1. 断点单调、累计时间连续、逆函数左右闭合、功率正且不递增；
2. 任意跨断点动作的电量与时间守恒，以及常功率逐位退化；
3. 候选点枚举与稠密网格/一维精确搜索一致；
4. 第2节后向递推与极小趟次链的穷举或动态规划一致；
5. 旧线性封存方案在`L100_control`下成本、排放、排班和哈希语义不漂移；
6. `NL90_mild`能逐位复现本轮固定方案复算的持续时间与分时电量；
7. 新正式解的所有正电量动作均带起止SOC和曲线ID，旧格式只允许历史只读重放；
8. 完整求解后的独立评价器重新核对SOC、时间窗、趟间衔接、充电桩并发、成本和排放。

任何一项失败都停止正式搜索。数学测试通过不等于论文结果成立。

## 7. 与ALNS预算和公开基准的串联顺序

1. 先等待当前E7由hooks完成，并严格走十步收口；在此之前不修改保护源。
2. 实施ALNS评价预算G0，使每次完整候选评分与预算一一对应。
3. 实施本方案的非线性物理内核和回归门，形成一个统一代码版本。
4. 在不含充电的12个Homberger开发实例上改进ALNS结构；这条开发线不用于估计非线性参数。
5. 冻结唯一算法版本后，在Solomon 56例上做560次最终外部测试。公开测试不调参，车辆数优先、距离次优，CPU/RT/Tbest/Runs按同机合同报告。
6. 使用同一最终版本执行`NL->NL`，统一重跑受影响的E2--E7、两条非线性曲线和中国TVCI/价格情景。不得拼接线性旧算法、非线性新算法或不同评价预算的结果。

非线性曲线计算属于一次候选评价内部的物理计算，不单独增加“评价次数”；但候选因充电不可行而早停时仍算一次已尝试候选，防止算法通过廉价失败绕开G0预算。

## 8. 实验与论文接入门

重跑必须至少形成以下对比：`L100_control`对`NL90_mild`识别线性简化影响；`NL90_mild`对`NL80_stress`识别曲线敏感性；尽早充电对碳感知充电识别TVCI作用；固定责任对协同责任识别空间重组；静态对动态滚动重规划识别状态继承。重点报告日内趟间不可行是否被改变路径、车型或车辆链修复，以及这种修复的成本—排放代价。

论文模型章在代码和数学门通过后再把$\xi_s(b)$、分段电量积分和约束集中写入，不预先把公式写成既成事实。每次公式或符号变化重跑Python数学审计、符号审计、两层模型审计和真实PDF编译。摘要和结论不得使用当前固定方案的可行子集均值作为最终数字；最终主张只取自`NL->NL`封存证据。
