# 4.1 最终解分析展品合同

状态：2026-07-17 预注册；最终算法版本冻结前只确定选择规则、字段和验证门，不生成路线结果，不挑选表现最好种子。

## 1. 目的与主算例

“最终解分析”只回答一个问题：本文两层模型最终形成的客户服务、配送路径、实体车辆多趟衔接和充电安排，在一个读者可以完整检查的代表性算例中究竟是什么样。

主算例固定为自建网络`N114`、地理聚集责任、随机种子1、完整静态模型。选择理由仅为它是预注册网络序列中的首个50客户实例，能够在正文有限版面内展示完整路线与实体车排班；选择不依据算法成本、协同节省、排放或图形美观程度。最终算法若换代，同一实例、同一责任、同一种子按新冻结版本重跑；旧版本结果保留但不得与新版本展品拼接。

若该固定单元因最终模型合同本身不可行，正文不得换成有利实例。应先用独立检查器确认是模型不可行还是算法在预算内未找到可行解：前者如实将“最终解分析”改为不可行边界案例并另用极小实例解释结构，后者则保留失败并由同一预注册规则指定的下一实例`N221`、同责任、同种子仅作可视化补充，不能把失败从结果中删除。

## 2. 必须来自同一保存解的展品

正文采用一图一表，避免把同一数字重复画成多种图形。

图为最终路线与客户责任图。它显示两个车场、客户原责任、最终服务车场、燃油车和电动车路线、充电站以及跨场客户。颜色用于区分主要类别，同时以线型、标记和填充作第二编码；坐标轴必须给出距离尺度和单位。图形外壳、字体、字号、线宽、图例和留白按已确定的同类VRP母版完整复刻，不自行增加流程框、装饰箭头或大段文字。

表为实体车辆—趟次—充电排班表。每行是一辆实体车的一趟，至少包含车辆编号、车型、所属车场、趟次序号、服务客户序列、出发/返回时刻、出发/返回SOC、下一趟前充电起止时刻与电量、行驶距离和本趟运营成本。表尾给出实体车数、配送趟数、跨场客户数、总距离、燃油量、购电量、直接排放、购电间接排放、运营成本、碳结算成本和总目标值；单位置于列题，数字精度按正文统一合同。

客户与配送中心基础数据不全部塞入路线表。正文另保留一张紧凑的主算例参数表，列出两个车场位置、车辆数与容量、客户数、需求范围、时间窗范围、充电站数量及功率、油价、电价和碳价；50个客户逐点坐标、需求和时间窗若无法在正文三线表中清晰显示，则以可复现数据文件和生成规则引用，不新增附录，也不压缩到不可读字号。

## 3. 数据与生成器合同

生成器暂定为：

`baselines/paper_story/build_final_solution_exhibit_20260717.py`

它只接受以下显式输入：冻结实例bundle、最终算法合同、保存解、保存解证书、独立评价器版本和视觉母版配置。输出暂定为：

- `generated_figures/final_solution_routes.pdf`；
- `generated_tables/final_solution_schedule.tex`；
- `generated_tables/final_solution_case_parameters.tex`；
- `generated_tables/final_solution_interpretation.tex`；
- `generated_tables/final_solution_evidence_manifest.json`。

manifest至少绑定实例、责任条件、种子、算法版本、运行合同、保存解、独立证书、生成器和四件读者展品的SHA-256；四件展品必须原子发布，manifest最后写入。主TeX只有在四件展品加manifest齐全时才显示“最终解分析”，缺一时不能留下空标题或内部占位语。

## 4. 独立复算门

生成前必须由与求解器不同的读取路径完成下列检查：客户恰好服务一次；各趟从正确车场出发并回场；实体车趟次不重叠；车辆容量、时间窗和服务时间传播合法；EV能量传播、SOC边界、充电窗口和共享桩并发合法；已发生费用与排放没有重复结算；表中总量与各趟分量闭合；保存解目标值与独立复算一致。

任何一项失败，生成器只能返回HALT并保留诊断，不得画图、补数或以求解器自报`feasible`替代独立证书。若公式、符号或充电物理在生成前发生变化，必须先通过Python数学审计、两层模型门和相应行为测试。

## 5. 正文分析节奏

文字严格采用“方案结构—关键数字—机制解释—适用边界”四层。先说明客户和实体车如何组织，再报告最能解释结果的两至四个量，随后把成本/排放变化追溯到里程、车型、充电或跨场服务，最后说明该单例不能代表跨实例统计规律。不得逐行复述表格，不得用“路径规划合理”“结果验证有效性”等空泛判断，也不得从一例推断普遍管理结论。

算法Benchmark、组件消融和最终解分析各自回答不同问题：公开Benchmark检验通用VRPTW求解能力；自有模型消融解释算法结构；最终解分析解释完整模型的运营含义。三者不能共用一张表或互相替代。
