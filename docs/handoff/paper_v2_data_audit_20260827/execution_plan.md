## 零、必须长期遵守的用户工作习惯

这些不是本项目的临时要求，而是用户近两周反复强调、适用于所有项目的长期工作方式。接手 AI 不得要求用户再次复述。

1. AI 先查仓库、原始资料、既有决定和近期对话，把问题查到能够形成真实选项，再来请用户拍板。
2. 用户只做选择题或判断题，不做简答题。任何需要用户决定的事项，都必须提供二至四个互斥且完整的选项，并写清依据、实际结果、改动量、风险和 AI 的推荐；用户只需回复 A／B／C／D 或“通过／不通过”。
3. 如果证据还不足以形成真实选项，AI 继续调查并报告“目前还不具备决策条件”，不得让用户替 AI 想方案、列参数、定图形或补研究设计。
4. 同一层级的决定一次性收齐。普通查证、整理、机械修改和既定方案的实现由 AI 自主完成，不反复请示。
5. 用户已经明确决定的事项保持有效；除非用户主动重提，或新证据证明旧决定依据有误，否则不得重新提问。
6. 对用户使用自然、平实的中文。禁止 AI 腔、大厂风、互联网黑话、内部代号和没有同行依据的自造词。
7. 不为显得严谨而增加复杂流程、技术核账、门槛、阈值、公式、表格或文件。只做当前目标所需的最小工作。
8. 本轮以及后续工作均不进行或要求文件技术指纹核验。来源核对改用原始文件路径、内容、时间、运行记录、结果明细和可复算过程。
9. AI 的建议、Claude 的意见和旧计划都不能冒充用户决定。涉及研究含义、模型目标、正式参数、主要比较、图表最终形态和核心结论时，选择权留给用户。

若本计划后文出现与本节冲突的旧写法，以本节为准并立即改正。

## 八、工作包三：引言、文献真实性与全文语言

### 当前问题

- 引言中的文献可能不存在、信息不准或与论文不匹配。
- 段落像文献罗列，缺少递进、并列和过渡关系。
- 当前稿逐段模仿陈雨蝶，存在过度相似和拼贴风险。
- 全文充满 AI 式解释、防御、抽象名词和自造术语。

### 文献真实性审计

对引言和文献比较表中的每个引用建立一行：

| 字段 | 内容 |
|---|---|
| BibTeX 键 | 论文中的引用键 |
| 书目信息 | 作者、题目、期刊、年份、卷期、页码、DOI |
| 是否真实存在 | 官方页面或原文 PDF |
| 当前论文声称 | 引言或表格中的具体说法 |
| 原文证据 | 页码、章节、公式、表图 |
| 是否支持当前声称 | 支持／部分支持／不支持／无法取得全文 |
| 与本文关系 | 直接相关／背景／方法迁移／不相关 |
| 处置建议 | 保留、改写、换源或删除 |

不得只凭标题、摘要或搜索片段判断。

### 引言逻辑审计

先画出当前每段的功能，再对照目标期刊。需要查清的逻辑链包括：

1. 现实背景为何导向混合车队和多车场协同问题。
2. 时变电价、时变碳强度、非线性充电与路线决策怎样发生联系。
3. 动态需求为什么是本问题的组成部分，而不是额外拼接。
4. 已有研究分别解决了什么，还缺少什么。
5. 本文到底解决哪一个完整问题，贡献分别落在模型、算法和实验的哪里。

不得预先认定这五步就是最终段落顺序。最终顺序由同刊证据和本文真实内容共同确定。

1. 对比陈雨蝶、陈婉茹及其他母版，定位连续表达、句式骨架和段落节奏过度相似处。

## 十七、用户决策必须怎样出题

这一节约束执行方怎样把问题加工成用户能直接选择的方案。这里列的是出题规则，不是把一串尚未查清的问题交给用户。

### 17.1 什么时候才可以请用户决定

只有同时满足以下条件，才可以提交选择题：

1. 相关仓库文件、原始文献、数据、代码、结果和既有决定已经查过。
2. 已经分清哪些是事实、哪些仍未知、哪些只是 AI 建议。
3. 确实存在两个以上会改变论文含义、证据、成本或最终形态的可行方案。
4. 每个方案都已经补成可以直接执行的完整方案，不留预算、参数、结构、措辞或图形让用户填空。
5. AI 能基于证据给出推荐，并说清推荐可能失败在哪里。

任何一项不满足，就继续调查或制作候选，不得向用户提问。

### 17.2 每张选择卡的固定内容

每张选择卡只解决一个同层级决定，并按以下顺序写：

1. **现在要决定什么**：一句自然中文。
2. **已经确认的事实**：只列直接证据支持的内容。
3. **为什么现在必须决定**：不决定会卡住哪一步；如果不影响继续查证，就暂不提问。
4. **A／B／C／D 完整选项**：二至四个，互不重叠，每个都说明怎么做、依据、改动量、预计结果、风险、耗时或算力。
5. **AI 推荐**：明确推荐哪一项及原因；推荐不等于用户决定。
6. **回复格式**：只允许“A”“B”“C”“D”或“通过／不通过”。

禁止出现“你想怎么写”“你觉得放哪里”“要跑多少种子”“选哪些参数”“图应该长什么样”“还有什么要求”等简答题。

### 17.3 统一决策包的组成

以下内容不是分多轮向用户零散提问的“批次”，而是同一份最终决策包的组成部分。执行方必须先把所有仍需决定的卡片、证据、实际预览和推荐全部准备齐，再一次性交给用户；不得先交结构卡、以后再补图表卡或实验卡。

#### 准备工作：AI 自主完成，不打断用户

- 稿件身份、未提交改动和现行决定核对。
- 同刊结构与图表先例检索。
- 引用真实性、公式来源、数据来源、代码接线和结果包核验。
- 图表与正文关系、收敛异常和语言问题诊断。

这些属于查证工作，不需要用户先拍板。

#### 已关闭事项：稿件底座

用户已经选定 docs/paper_v2/paper_main.tex 和同目录 PDF 作为正式底座。执行方直接沿该底座工作，不再提交选择卡。

#### 决策包组成一：结构与写法

- 摘要：展示二至三个真实结构骨架。
- 引言：展示二至四个完整逻辑骨架及对应贡献表达。
- 模型与算法：展示完整目录对照，不只问“要不要补”。
- 符号：展示正文表、附录表、随公式解释三种实际样张。

用户面对的是已经准备好的候选，不是抽象名词。

#### 决策包组成二：图表形态

每张图表先完成数据和代码核验，再提供二至三个可见预览。每个预览写清使用什么真实数据、与同刊先例的关系、读者能看出什么、会丢失什么。用户只选择预览 A／B／C；不得让用户口述坐标轴、图元、行列和排版。

#### 决策包组成三：科学结论

对公开算例、协同、公平分配和动态需求分别提交完整选择卡。每项同时给出对应的摘要句、正文句和结语句，让用户直接比较“重跑／降格／撤下”实际会把论文变成什么样。

#### 决策包组成四：实验合同

只对用户已选择继续的实验提交二至四份完整合同。执行方先填好输入、对照、种子、预算、机器、预计耗时、失败保留方式和适用结论，并标出推荐。用户只选合同，不负责设计合同。

### 17.5 当前真正需要用户拍板的事项

截至 2026-08-27，稿件底座、全文来源和过期退役注释都已经闭合，不再属于用户决定。

模型主口径也已经由较晚的用户决定闭合，不能再重开：P44 已定主文采用“运营成本＋碳价折算成本”的单一货币目标，成本和实际排放在结果中分列报告；P100 又把双目标分析定为低优先级附属内容，仅在主线完成且故事确有需要时再补。因此，当前执行方应按这个口径核对公式、代码和表格，不再要求用户在“单目标／双目标”之间重复选择。用户本轮关于成本和排放不应混成难读表格的意见，先按**结果呈现分列**处理，不自动解释为重开目标函数。

1. **章节和符号呈现**：摘要、引言、模型、算法以及符号说明，在已有完整骨架时让用户选择。

种子、预算、命令、文件路径、数据核对、文献真假、公式来源、收敛异常原因和普通排版均不是让用户从头决定的事项；这些由 AI 先完成。

#### 选择卡 S1：摘要采用哪种结构

**现在要决定什么**：摘要按什么顺序组织，解决当前“信息很多但不吸引人、像 AI 罗列”的问题。

**已经确认的事实**：

- 当前摘要依次写现实矛盾、模型、算法部件、六类实验和三组详细数字，信息完整但主次不够突出。
- 陈雨蝶等（2025）的摘要采用“现实背景与困难—模型—成本口径—算法—实验维度—应用价值”的顺序，基本不在摘要中堆详细数值。
- 本文目前不能把公开算法优越性放在摘要中心，因为公开算例只完成一轮，收敛图也尚未核验。

**为什么现在必须决定**：摘要骨架会决定后续保留哪些结果、怎样重写引言开头和结语；不先定骨架，三处容易继续各说各话。

**A｜问题与发现导向（推荐）**

- 顺序：现实矛盾 → 现有研究缺口 → 模型与研究对象 → 求解方法 → 两至三项最可靠发现 → 企业与政府含义。

- 预计结果：读者先知道“为什么值得研究”，再看到本文解决了什么和发现了什么；允许保留少量关键数字。
- 风险：必须先完成结果证据分级，否则关键发现仍可能因实验处置而替换。

**B｜同刊母版导向**

- 顺序：行业背景与双重挑战 → 复杂现实因素 → 模型 → 目标函数 → 算法 → 实验维度 → 概括性价值。
- 改动量：较小，最接近陈雨蝶等（2025）的摘要布局。
- 预计结果：期刊风格稳妥、结构熟悉，不依赖大量数字。
- 风险：本文因素较多，若压缩不好仍会像功能清单，论文自身最鲜明的问题可能不突出。

**C｜方法与验证导向**

- 顺序：研究问题 → 数学模型 → 算法结构 → 公开算例 → 机制实验 → 主要结论。

- 预计结果：更像算法论文，便于突出求解方法。
- 风险：公开性能与收敛证据目前不够，现阶段采用容易形成超出证据的算法主张。

**AI 推荐**：A。它比照抄母版更能突出本文的真实矛盾，又不会像 C 那样提前宣称尚未证实的算法优势。

**为什么现在必须决定**：引用核验完成后，文献必须按一个明确逻辑重新归位；没有骨架就只能继续按原顺序修补。

**A｜三条研究线后统一收束（推荐）**

- 预计结果：最接近同刊常见写法，也能把“几篇研究线如何结合成本文”交代清楚。

- 改动量：较大，需重写多数过渡句并重新安排文献。
- 预计结果：故事性和递进感更强，读者更容易理解各机制为什么同时出现。
- 风险：与同刊母版的传统分类综述距离更大，若文献支撑不足容易把代理推理写成领域共识。

- 改动量：最大，接近重新写引言。
- 预计结果：研究问题与贡献一一对应，逻辑最显式。
- 风险：容易形成机械的“三问三答”，文字处理不好仍会显得模板化、AI 化。

**AI 推荐**：A。它在同刊惯例、改动量和逻辑清晰度之间最稳妥；执行时用 B 的“决策链”只负责段落过渡，不另造一套结构。

#### 选择卡 S3：模型章怎样以完整模型收尾

**现在要决定什么**：第二章的公式和子模型按什么顺序出现，以及可疑的成本分配公式放在哪里。

**已经确认的事实**：

- 成员成本分配属于联合方案形成后的结算步骤，不是车辆路径主目标本身；其来源和放置位置仍需单独核验。
- 用户已明确要求模型章以完整列式和逐项解释收尾，公式只做符合行业惯例的最小必要调整。

**为什么现在必须决定**：公式来源审计和符号删减都依赖章节顺序；不先选结构，无法判断一个公式是必要、重复还是放错位置。

**A｜基础关系在前，完整模型收尾（推荐）**

- 顺序：问题描述与假设 → 符号 → 车辆能耗与充电排放 → 动态状态与已发生量 → 成本构成 → 完整目标函数和约束。
- 成本分配：从主模型中移出，来源核验通过后放到协同收益分析或单独的事后分配方法中。
- 改动量：中等，以移动、合并和改标题为主，不主动改变数学含义。
- 预计结果：读者先理解各项量怎样计算，最后看到完整模型；符合用户要求的收尾方式。
- 风险：移动公式时必须逐项复核前后引用，不能机械剪贴。

**B｜成本目标在前，各物理子模型随后补充**

- 顺序：问题描述与假设 → 符号 → 目标函数及成本分项 → 能耗、充电和动态子模型 → 约束汇总。
- 成本分配：作为成本目标后的补充结算关系保留。
- 改动量：较小，接近现稿。
- 预计结果：读者较早知道优化目标。
- 风险：目标先引用尚未定义的能耗和排放量；事后分配仍容易与路径模型混在一起。

**C｜静态主模型与动态扩展分开**

- 顺序：问题与符号 → 静态能耗、成本和完整模型 → 动态状态继承扩展 → 事后成员结算。
- 改动量：较大，需要清楚区分静态变量、阶段变量和累计量。
- 预计结果：静态与动态边界最清楚。
- 风险：容易重复公式并拉长第二章，也不满足“整章以统一完整模型收尾”的原始偏好。

**AI 推荐**：A。它直接解决重复标题、公式定义倒置和事后分配位置可疑三个问题，同时保持模型含义不变。

**统一决策表字段**：`S3-A`、`S3-B` 或 `S3-C`。

#### 选择卡 S4：算法章拆成多少个必要小节

**现在要决定什么**：算法章继续保持两节，还是按真实代码部件拆成可复核的小节。

**已经确认的事实**：

- 当前代码至少分开实现初始解、搜索动作、完整评价、排班修复、充电处理、种群管理、停止条件和动态状态处理；现稿两节中的六个文字步骤不能让这些代码责任一一对应。

**为什么现在必须决定**：章节骨架决定代码审计产物怎样落入论文，也决定流程图需要展示到什么粒度。

**A｜保留两节，强化算法步骤**

- 改动量：小，最接近陈雨蝶等（2025）。
- 预计结果：篇幅紧凑。
- 风险：真实算法责任仍挤在一个小节中，读者难以核对完整评价、排班充电和动态处理的边界。

- 预计结果：完整但不过细，流程图、代码和正文可以逐项对应。

**C｜像陈婉茹等（2023）一样逐部件细拆**

- 改动量：大，算法章会显著增长。
- 预计结果：部件最详细。

**AI 推荐**：B。它不是按母版机械凑节数，而是按当前代码的真实责任边界拆分；比 A 可核验，比 C 克制。

#### 选择卡 S5：符号说明采用哪种呈现方式

**现在要决定什么**：符号表保留到什么范围，怎样避免既堆满所有中间量又遗漏关键决策变量。

**已经确认的事实**：

- 当前符号表同时容纳集合、参数、模式量、成本量和后续报告量，读者难以区分哪些直接进入模型。
- 陈婉茹等（2023）只在主表列主要参数和决策变量，计算过程中使用的其他量在公式上下文说明。
- 最终字母、上下标和单位仍须逐项对照原始公式、代码及领域论文；本卡只决定呈现范围。

**为什么现在必须决定**：符号审计需要一个明确保留标准，否则执行方无法判断“必要”具体指什么。

**A｜主符号表＋公式旁解释（推荐）**

- 主表只保留集合与索引、外生参数、正式决策变量和跨多组公式反复使用的状态量。
- 只在单个公式中使用的中间量、成本分项和报告指标在公式前后解释，不进入主表。
- 改动量：中等，需要逐项分类和删并。
- 预计结果：主表足够完整但不会堆满临时量，最接近同刊做法。
- 风险：分类必须以最终模型为准，模型结构未定前不能提前删除。

**B｜集合、参数、变量分成三张表**

- 所有正式符号保留，但按类型拆表；中间量仍在正文说明。
- 改动量：中等，版面占用更大。
- 预计结果：查找最方便，适合符号数量很多的模型。
- 风险：三张表可能打断正文并增加留白，与用户要求的紧凑版面冲突。

**C｜取消总符号表，全部随公式解释**

- 每个符号首次出现时直接定义，不设集中表。
- 改动量：大，需要重写公式前后文字。
- 预计结果：读者按顺序阅读时较自然。
- 风险：复杂模型中查找困难，跨页重复符号容易不一致。

**AI 推荐**：A。它同时满足行业惯例、必要性和版面紧凑三个要求。

**统一决策表字段**：`S5-A`、`S5-B` 或 `S5-C`。
