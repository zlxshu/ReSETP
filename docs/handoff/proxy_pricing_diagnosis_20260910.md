# 路径搜索电动车代理电价的两处失真（2026-09-10，Claude 顺线索查到底）

## 背景
用户 09-10 拍板：论文不固定车队；内生车队下"兼顾两者"须在四种充电安排中总成本、总碳排同时最低；为此改的客观条件本身就是研究成果。
09-10 上午发现：午谷×碳价1.0 内生批里"只看碳"电动车最多（均 4.8 辆）、碳排最低，但其首趟前充电实付单价最高（1.355 元/kWh，含碳），
而"兼顾"实付最低（1.110）。路径搜索看到的代理电价却是 只看碳 0.873 < 兼顾 0.917 < 只看电价 0.968 < 即充 1.191。

## 查清的原因（离线探针 `solver/reports/proxy_feasible_probe_20260910/offline_proxy_probe.py`，不求解）
1. **窗口开启时刻各批不一致。** 即充/兼顾取自 09-06 网格批，每跑用自己初始种群的中位返场时刻（即充 15:49、兼顾 16:20）；
   只看电价/只看碳取自 09-09 批，运行器 09-08 起默认改为全批共用常数 15:47（`--proxy-estimate-source reference`）。
   午谷日历里 15:30→16:00→17:00 的碳强度 121→196→395 g/kWh 陡升，兼顾因开启晚 33 分钟被按 16:00 行计价
   （0.836+0.269=1.105），只看碳按 15:30 行计价（0.836+0.183=1.019）。四臂同用 15:47 时，只看碳与兼顾代理逐字段相同。
2. **单行计价、不查时长。** 代理只取窗口内一行的电价与碳强度，参考充电 2032 秒跨行；且只看碳的实付高是因为
   它一律在各车实际返场时立即充（15:30–19:00 不等），晚返的车落入 17:00 后的尖峰（1.149+0.4≈1.55）；
   代理用一个中位开启时刻算不出这一层。

## 施工（默认关、逐位不变）
- `kernel_proposals.py`：新增 `proxy_feasible_slots_only`（引擎参数→构造函数→`_rebuilt_shift_aware_ev_unit_costs`）。
  开时：候选起点=各行在窗内的首个瞬时（含开启瞬时），只留 起点+参考时长≤发车 的候选，按参考时长跨行时间加权的
  电价/碳强度用本臂的键选最小；元数据多两个字段 `priced_start_second`、`reference_charge_seconds`。
  参考时长 = `_curve_for_prices` 曲线上从 0 充到 `reference_trip_energy_kwh` 的秒数（2031.7 s）。
- 运行器：`--proxy-feasible-slots`，元数据 `route_engine_wiring.proxy_feasible_slots_only`。
- 证据：开关关闭时四臂（各自落盘的开启时刻）代理与 metadata 逐字段一致；`test_policy_aware_shift_proxy.py` 与
  `test_problem_hgs_ev_charge_time_and_lock_pins.py` 50 项通过。

## 短跑结果（15:38 完成）与结构性结论
见 `solver/reports/charging_arrangements_midday_P1.0_proxyfix_probe_20260910/README.md`。要点：代理修正生效但判据未达成
（兼顾 2733.79/129.13；只看碳 2757.42/75.83；只看电价 2755.66/118.10；即充 2825.66/165.55）。
碳价 1.0 车队在刀刃上（兼顾计时下 4/5/6 辆总成本差 +0.2%/+0.6%）；离线换碳价重算：≥1.5 全电才成为兼顾的成本最优，2.0 时有 20 元余量。
同一方案上只看碳计时恒比兼顾少约 2.75 kg、贵 7–10 元，且只看碳比兼顾更早全电——"兼顾在四种安排中双严格最低"结构上不可期望；
可期望的是"碳价 ≥2.0 时兼顾总成本最低且全电、碳排与只看碳差 4.6%"。待用户在此基础上决定。
