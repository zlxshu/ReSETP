# PyVRP V13 原装母体时间—质量曲线合同

状态：`APPROVED_DIAGNOSTIC_ONLY`

## 目的

只回答一个问题：当前 PyVRP 0.13.4 ILS 在 V13 多车场时间窗公开题上距离
BKS 约 2%--4%，主要是因为此前只给了 8.5 秒，还是因为该母体在这批题上很快
进入平台。

本门不开发算法、不调参数、不比较 C2、不形成正式公开表。

## 冻结输入

- 算例：`PR11B`、`PR17B`、`PR21B`；
- 算法：原装 PyVRP 0.13.4 ILS，`SolveParams()` 默认参数；
- 种子：1；
- 单线程；
- 时间：8.5、60、300 秒；
- 目标值：PyVRP `round_func="exact"` 的整数目标，BKS 使用冻结比较基础中的
  当前可验路线证书值。

三题均属于既有公开开发块，不消耗确认题。三个时间点从既有短门扩到分钟级和五分钟级，
用于观察数量级增加时间后的边际变化；本门不把五分钟冒充正式一小时预算。

## 判读

先验不设置“必须进入 1%”或“必须关闭 50% 差距”等人为阈值。逐题记录：

1. 8.5→60 秒是否严格改善；
2. 60→300 秒是否继续严格改善；
3. 两段分别关闭了多少 BKS 差距；
4. 300 秒仍余多少 BKS 差距。

机器只给三类描述性结论：

- `TIME_CONTINUES_HELPING_ALL_THREE`：三题在两个时间段都严格改善；
- `PLATEAU_SIGNAL_AT_FIVE_MINUTES`：至少两题在 60→300 秒没有严格改善；
- `MIXED_TIME_HEADROOM_SIGNAL`：其余情况。

这些标签只决定下一项研究：

- 持续改善：允许另拟“强母体配置/长预算”合同；
- 平台信号：优先海选更适合 V13 的成熟母体；
- 混合：按题型拆因，不直接跑完整 28 题。

无论哪一类，都不得据此声称新算法优于 PyVRP、达到 BKS 或可进入 China81。

## 完整性

九个解必须完整、可行并通过独立验解。产出
`metadata.json`、`raw_runs.csv`、`decision.json`、`artifact_hashes.json`、
`report.md`及逐次运行 JSON。任何解无效则结论为
`HALT_INVALID_TIME_QUALITY_DIAGNOSTIC`。

## 边界

不修改正式 solver、成本、检查器、评价器、模型、论文 TeX 或默认参数；不运行
China81、完整 V13-28、确认题、C2、阶段二或参数扫描。
