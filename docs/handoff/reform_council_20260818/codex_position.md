# 独立结论

可以在未来 3 天内正式开始填数，但不可能在 3 天内完成全部正式数据。

当前真正的病，不是缺少一个“神奇算子”，而是长期把四件不同的事绑成了一件事：

1. 底座能不能正确运行；
2. 机制是否真的被触发；
3. 对照是否回答了正确问题；
4. 算法是否足够强。

于是任何一处出错，大家都继续“修算法”；算法修快了，实验仍然没有可填数据。

`CORRECTION`：当前总入口说“成本分项、公开表能填”，其中公开表已经被 8 月 18 日新证据推翻。公开侧只测了 2/28 题，优势从 10 秒到 30 秒分别缩水 91.1% 和 98.8%，正式胜负仍是 `UNKNOWN`。目前真正可以直接整理的只有参数、算例特征和成本分项。[当前总入口](</Volumes/移动硬盘（512G）/ReSETP/docs/handoff/CURRENT_PROJECT_CONTEXT.md:36>)、[新摸底](</Volumes/移动硬盘（512G）/ReSETP/solver/reports/probe_all_mechanisms_20260818/report.md:25>)

历史上的 E3、E5、E7 其实已经三次重复同一种错误：

- E3 要测客户责任错配，但旧算例错配率按构造就是 0/150。

## 二、用户可能还没充分看到的问题

1. **统一算例存在“挑中冠军”的乐观偏差。** 当前算例从 1378 个车场对中按一阶协同收益排名选出，43.66% 只是正式优化前的构造式估计。它可以作为刻意保留作用空间的解释性算例，不能再称“典型情况”或把该幅度外推。[P65](</Volumes/移动硬盘（512G）/ReSETP/docs/paper_gci_dmm_vrp_20260804/pending_decisions.md:723>)

2. **混合车队被公平实验错误绑架。** P28 要求最终算法定稿后，单干各跑 10 种子取最好；但混合车队载具又在运行前强制索要 P28 清单。这是人为循环，不是科学依赖。[P28](</Volumes/移动硬盘（512G）/ReSETP/docs/paper_gci_dmm_vrp_20260804/pending_decisions.md:42>)、[摸底报告](</Volumes/移动硬盘（512G）/ReSETP/solver/reports/probe_all_mechanisms_20260818/report.md:89>)

3. **批准的图与计划运行的扫描不一致。** 混合车队图已定横轴为碳价，但旧算法计划却把“EV 溢价扫描 40 次”列为该图的必需数据。固定 50 元溢价、扫描碳价才直接填图；溢价扫描最多是后续敏感性，不应占三天关键路径。[P59](</Volumes/移动硬盘（512G）/ReSETP/docs/paper_gci_dmm_vrp_20260804/pending_decisions.md:565>)、[旧八行计划](</Volumes/移动硬盘（512G）/ReSETP/docs/handoff/algorithm_phase_prd_20260817.md:212>)

4. **决定登记本身已经漂移。** P51 在前文已明确“三个尺度全报”，后文却仍写“待决”；P39 的双目标与后来 P43-H 的单一货币主叙事也没有正式合并。不同代理据此会造出不同算法和不同数据。[已定 P51](</Volumes/移动硬盘（512G）/ReSETP/docs/paper_gci_dmm_vrp_20260804/pending_decisions.md:304>)、[残留旧 P51](</Volumes/移动硬盘（512G）/ReSETP/docs/paper_gci_dmm_vrp_20260804/pending_decisions.md:678>)

5. **“完整实验包”仍可能科学上是空的。** 新验收器解决了失败冒充完成，却没有替代“处理因素真的发生”的检查。组件提案为 0、关闭臂没关掉、两臂服务对象不同，都必须由各实验自己的读数判断。

## 三、算法侧的新路线

`DECISION`：今后不再建设“大而全的 ReSETP 算法平台”。只保留：

- 成熟 HGS 负责种群、选择、罚分、交叉、局部搜索和停止；
- 项目代码只负责四个不可外包的短接口：完整 Duty 真值、路线—车型—充电联动、企业单干子问题、动态状态继承；
- 每个实验只开启直接参与该问题的部件；
- 每个问题部件必须留下“动作前—部件直接产物—修复后—完整评价后”四个读数，避免把通用局部搜索的功劳记给前面的复杂算子；
- 没有证据证明“现有搜索无法产生某类必要动作”时，不再加新算子。

## 四、八行图表逐行处方

| 图表行 | 正式处方 | 结果不好时的诚实答案 |
|---|---|---|
| ① 时变碳 | 三臂同批重优化；同时报充电账、全系统排放、货币总账；碳价点由事前算出的翻转区间决定。 | 低碳价下行为不变就是政策阈值结论，不再调算法救它。 |
| ② 混合车队 | 固定已批准的 50 元/EV·日溢价，以碳价为横轴，报 CV/EV 数量、成本、直接与间接排放；不等待正式公平基准。 | 合理碳价区间内不换型，就报告切换阈值在区间外。 |
| ③ 多企业协同 | 真正对照必须是 A 单干＋B 单干与联合优化；废除 `cross_depot off` 伪对照。 | 若收益主要只在这个刻意选出的算例上大，就写成作用条件案例，不写普遍幅度。 |
| ④ 实体车多趟 | 不另造开/关实验；从每个正式解直接汇总实体车数、趟数分布、趟间 SOC 和回场衔接。 | 没有多趟就只是模型能力未被本算例使用，不强造效应。 |
| ⑤ 成本/参数/算例表 | 现在即可冻结来源和单位；正式参考解补八项成本分解、客户与需求服务量。 | 无需等待算法“赢”。 |
| ⑥ 动态需求 | 修完动态切点 SOC 后，用同一事件流配对“滚动重优化”和“机械在线”；每决策点预算由收敛轨迹标定。 | 两臂服务量不同就分别报服务与成本，不比较一个漂亮的成本百分比。 |
| ⑦ 公平分配 | 用当前主算法生成 P28 单干值；主表先采用一种固定分法，列单干成本、分摊成本、节约量和比例。 | 上层“让算法挑分法”没有稳定增量，就回到用户已预留的保守方案。 |
| ⑧ 公开对比 | 私有问题部件全部休眠；同批、同预算、同服务量比较冻结母体和已发表方法。短墙钟结果不得外推。 | 打平只能证明基础能力合格；是否必须领先，由用户重新决定。 |

非线性充电不占独立主实验：当前最诚实的结果就是“曲线核已经进入实解，但统一算例未达到 85% 拐点”。它承担模型保真，不承担制造节能百分比。

## 六、三天能做到什么

`FACT`：旧计划仅三族私有扫描就有 110 次搜索，按当时每次 986.35 秒估算约 30.14 机时；公开 28 题若按“每题10种子、每次20分钟”计算，单独就是 93.3 机时。最新 P79 又要求预算重新由收敛曲线确定，所以真实总量仍未知。[机时估算](</Volumes/移动硬盘（512G）/ReSETP/docs/handoff/CURRENT_PROJECT_CONTEXT.md:448>)、[P79](</Volumes/移动硬盘（512G）/ReSETP/docs/paper_gci_dmm_vrp_20260804/pending_decisions.md:1294>)

因此：

- 第 1 天：不干扰 `walk_first`；它结束后只核四个当前代入口——静态、单干/联合、混合车队、动态。每个一颗种子，只确认语义、服务量和组件激活。
- 第 2 天：在最终代码上做收敛标定；同时冻结三个用户选择、正式种子清单、扫描点和每行输出列。
- 第 3 天：正式启动第一批 10 种子数据，并直接填参数/算例表；首批静态解同时产生成本分项和多趟描述。协同、碳价和动态随后按同一冻结版本进入队列。

结论是：**三天内正式开填可行；三天内把八行全部填完不可行。** 如果第 1 天发现 `walk_first` 只是“能写包”，却仍存在伪关闭、零提案或动态状态错误，就应延后正式启动，而不是把摸底数改名为正式数。
