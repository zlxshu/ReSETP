# ReMIX V13 六题开发门尸检与停止决定

- 编号：`REMIX-V13-DEV-FORENSICS-001`
- 日期：2026-07-19
- 权威判定：`STOP_CURRENT_REMIX_V13_CANDIDATE_ALL_LOSS`
- 适用候选：HGS 供料 + ILS 供料 + 路线交换 + 有界拆解重建 + PyVRP
  局部搜索 + 精确路线会审
- 不授权：确认块、封存块、28 题正式表、China81、阶段二、参数救援或论文优胜结论

## 1. 一句话结论

比较基础、版本接线、预算记账和独立验解都成功了；算法性能失败了。完整 ReMIX 在
六道结果盲开发题上对当场较强的可运行核心为 `0 胜、0 平、6 负`，因此当前候选
必须停止，不能把运行器写出的 `HOLD_MIXED` 解释成“有好有坏”。

`HOLD_MIXED` 是汇总脚本的标签设计错误：合同中的该标签原本指“有胜有负”，而本次
没有任何胜或平。原证据目录保持只读，不改写历史 `decision.json`；本报告给出权威
语义更正。

## 3. 失败不是验解事故，而是预算架构错了

独立 ILS 每题获得 8.5 秒内部搜索。ReMIX 为了给其他工种留时间，把 ILS 缩到
约 6.19--7.01 秒，又加入一份“只求到首个可行解”的 HGS、五轮路线交换—拆解重建—
局部搜索和一次精确路线会审。

结果很清楚：

1. HGS 首个可行解六题都远差于 ReMIX 内部 ILS，未产生一个新的全局最好解；
2. 五轮路线交换、拆解重建和重复局部搜索在五题上没有改变最终最好解；
3. PR11A 的精确路线会审把缩短版 ILS 从 6,868,085 改到 6,862,989，内部改善
   约 0.074%，但仍差于完整预算 ILS 的 6,849,667；
4. PR21A 会审虽然选了 HGS 和 ILS 两个来源，最终目标仍等于缩短版 ILS；
5. 其余四题会审只选 ILS 路线，最终也等于缩短版 ILS。

所以不是“融合差一点”，而是其他模块拿走了真正强核心的时间，却没有偿还这笔时间。
这也说明“模块确实被调用”“路线池确实混了来源”都不能替代性能贡献。

## 4. 当前候选立即删除的部分

本公开 V13 路径上停止使用：

- HGS 首可行供料线；
- 每题固定执行五轮的多父代路线交换；
- 与 ILS 已有搜索重复、却没有产生新最好解的外置拆解重建和局部搜索；
- 结束时无条件运行的精确路线会审。

代码和失败证据保留用于审计，不删除文件、不改写结果。这里的“删除”是指下一候选
不得继续带着这些无净贡献层运行。

## 5. 下一候选只有一个有直接证据支持的方向

若用户复盘后仍批准继续，下一候选应是“ILS 主循环里的 ALNS 式大扰动”，而不是再
并排启动一台 HGS 或在末尾追加一串模块：

1. PyVRP 0.13.4 ILS 继续取得完整、相同的主搜索预算；
2. 多车场连续段重组和时间窗张力修复只作为 ILS 原有扰动中的一种替代选择；
3. 只在停滞时替换一次原有扰动，不增加额外搜索阶段；
4. 复用 ILS 已有的局部搜索，不再外置重复精修；
5. 所有动作共享当前最好解、同一个随机流入口、同一个时间截止点和同一检查器；
6. 精确路线会审只有在能替代等价时间的原有搜索、并证明边际收益覆盖耗时后才可重提，
   当前不作为常开模块。

这仍是“成熟 ILS + ALNS 大邻域 + 多车场/时间窗专用动作”的深度混合，但它把融合
放进同一个循环，不再让装饰层抢核心时间。依据不是枚举猜测，而是本门六题的统一死因：
所有题都由 ILS 最强，所有损失都伴随 ILS 预算被削减，外置层五题零偿还。

建议下一候选编号为 `REMIX-ILS-INLOOP-002`。本报告只冻结方向，不批准实现或运行。
若执行，仍用六题开发块、seed 1、单线程和同一端到端截止；不得扫参数。它只有在六题
逐题严格胜完整预算 ILS、零负、全部独立有效时才取得确认块申请资格。若再次出现任一
负或没有严格胜，则关闭“公开题逐题击败最强开源核心”的当前研发路线，不得靠延时、
换题、增加种子或平均数救援。

## 6. 顾问意见及我的判断

终端 Claude 因会话额度已用尽，未形成意见，不能把它写成支持或反对。

DeepCode 的最终判断与本尸检的主要死因一致：削短 ILS 后，HGS 首解和四个增强层
没有补回损失；应删除零贡献层。它建议让 ILS 满额运行后再做“零成本事后路线池”。
我不接受“零成本”这个前提：MILP 会审有实际墙钟和 CPU 成本，若对手也在同一截止
时间内继续搜索，这段时间必须记账。PR11A 的 0.074% 内部改善说明路线池不是完全
无用，但尚不足以成为下一主结构；它只能在等时替换实验中重新证明自己。

本轮也暴露了我此前的执念：过度追求“多核心、多个高级模块同时出现”，把算法故事
做成了工种清单，却没有先保护最强核心的有效时间。证据已经否定这套执念。用户的宏观
目标没有变化；变化的是实现方式——下一次必须先让每一秒搜索都产生边际价值，再谈
算法名称是否高级。
