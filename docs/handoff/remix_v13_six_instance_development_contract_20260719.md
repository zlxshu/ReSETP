## 1. 要实现的算法

开发候选不是“把两个程序首尾接起来”，而是一套共享路线库和共同验解器的多算法
系统：

1. PyVRP `0.12.2` 的 HGS 负责群体进化、交叉和多样性；
2. PyVRP `0.13.4` 的 ILS 负责独立扰动和快速局部强化；
3. 本项目有界拆解重建负责针对多车场归属和时间窗张力做大改；
4. 多父代路线交换把不同搜索产生的整段路线放进同一个后代；
5. PyVRP 正式邻域搜索负责把新结构磨细；
6. SciPy 精确路线会审从各来源路线中选择一套完整方案。

HGS 和 ILS 都保留自己的独立随机流，但输出统一转成 PyVRP `0.13.4` 路线对象。
所有候选共用同一 V13 原题、`round_func="exact"`、车辆上限和独立检查器。任何
第三方核心只通过已登记公开接口调用，版本、许可证和引用继续锁定。

这是“异构多核心 + 问题机制大动作 + 精确重组”的混合算法。是否保留六个工种，
由本合同的逐题结果决定；没有贡献的工种必须删除，不能因名称高级而保留。

## 2. 为什么先加 HGS 供料线

PR17A 行为门已经证明 ILS、拆解重建、邻域精修和路线会审可以真实互相供料。但它
没有证明同一种 ILS 的三个小岛足以覆盖 HGS 的群体搜索盆地。

仓库已冻结 PyVRP `0.12.2`：它确实是带群体、交叉和可行/不可行管理的 HGS；
过去的失败只否定“ALNS 暖启动后交给 HGS”“每个后代强塞通用教育器”等具体拼法，
没有检验“让 HGS 作为独立路线供应者，再由共同路线库择优采用”。因此本候选只把
HGS 作为平等供料线，不修改其源码，也不强迫它接受 ALNS 后代。

正式开发前只允许一个零性能接线检查：HGS 在 PR17A 产生一份完整可行路线清单，
由 0.13.4 重建后距离、客户覆盖、车场车辆数和独立检查全部一致。该门失败则不带
HGS 进入六题，且必须把原因写清。

## 3. 开发题与对手

六题是结果盲冻结的：

`PR11A / PR11B / PR17A / PR17B / PR21A / PR21B`

它们覆盖 4、6、12 个车场和 A/B 两类，同时取各层最小规模控制成本。

每题只跑三条可执行臂：

1. 纯 PyVRP `0.12.2` HGS；
2. 纯 PyVRP `0.13.4` ILS；
3. 完整 ReMIX。

每题另列当前可验 BKS、VCGP、MDFIHA 和 MDFIHA-ETGA 的冻结逐题值，但这些论文值
不冒充同机运行。开发阶段的“最强可执行对手”是同题同机 HGS 与 ILS 中较好的一个；
“绝对目标”是当前可验 BKS。

## 4. 最低成本预算

- 随机种子：`1`；
- 单线程；
- 每臂端到端墙钟上限：`10` 秒；
- ReMIX 的 10 秒包括 HGS/ILS 供料、格式转换、拆解重建、邻域精修、路线会审和
  最终验解，不把任一部分藏到账外；
- 每个外部臂也从读题开始计时，到最终验解结束；
- 每题按 HGS、ILS、ReMIX 的轮换顺序执行，避免固定热机顺序；
- 记录墙钟、CPU 时间、HGS 代数、ILS 迭代、路线检查、完整插入检查、邻域调用、
  MILP 调用和独立复算次数。

ReMIX 内部不做参数网格。冻结调度为：

1. HGS 和 ILS 各取得一个可行供应解；
2. 两个供应解和当前全局最好进入共同路线库；
3. 剩余时间依次循环
   `多父代路线交换 -> 多车场/时间窗拆解重建 -> 邻域精修 -> 入库`；
4. 只在结束前调用一次路线会审；
5. 最终返回整个过程中最好且独立可行的解。

若十秒不足以完成一次完整循环，直接记执行失败，不临时延长。

## 5. 二值判定，不用平均数掩盖逐题失败

### `STRONG_GO_REMIX_V13_DEV`

同时满足：

1. 六题全部完整、可行、独立复算通过；
2. ReMIX 在六题上都严格低于同题较好的 HGS/ILS；
3. 没有预算漏记、取整差异或多核偷算；
4. 至少一个 ReMIX 最终解真实采用两个以上算法来源的路线；
5. 任一低于当前 BKS 的解均保存路线证书并二次独立复算。

这才是用户“最强可执行算法逐题输给我”在开发块上的完整达成。通过只允许撰写确认
块合同，不自动开放确认块。

### `PROMISING_BUT_NOT_TARGET`

ReMIX 六题均不差于最强可执行对手，且至少一题严格更好，但没有做到 6/6 严格胜。
这说明结构有价值，却还没达到用户目标。只允许一次基于调用贡献账的结构删改：
删除零贡献工种或修复明确的供料瓶颈；不允许扫参数。

### `HOLD_MIXED`

有胜有负、无完整 6/6 保底。停止扩题，按每个工种的“供料、被选中、带来新最好”
三本账判断是算力分配问题还是结构问题。不能用平均改进解释为通过。

### `FAIL_INTEGRITY`

出现不可行、客户重复/遗漏、车辆超限、输入/取整不同、超时未收口、保护文件变化
或账目不闭合，立即停。

## 6. BKS 口径

当前 BKS 是带路线证书的公开目标，不是一个可执行算法。ReMIX 只有在目标值严格
更低、路线完整公开、官方与独立检查器都通过时，才记
`NEW_PUBLIC_BKS_CANDIDATE`。

开发题上的新值仍是开发发现，不能用同一题再做无偏确认。最终“成为新 BKS”的主张
必须来自确认块或封存块，或在论文中明确标注为开发发现。

China81 尚无外部 BKS。它的 v0/更新规则继续使用
`algorithm_comparison_foundation_v3_20260719.md` 第 9 节，当前不运行。

## 7. 与陈雨蝶式验证表的关系

六题开发账不是论文主表。候选冻结后，论文结构仍是：

- 公开 28 题只列外部有资格强手、BKS 和完整 ReMIX；
- PR17A 代表题列 HGS/ILS 母体、独立拆解精修和完整 ReMIX，解释混合血缘；
- China81 只列公共完成器下的母体、独立机制 ALNS 和完整 ReMIX。

这样公开题证明竞争力，代表题解释算法结构，China81 证明完整模型求解能力；不把
所有零件铺成一张无重点的大表。
