## 1. 完成判定原则

总目标只有在下表所有必需项均为“已证明”时才完成。“代码已写”“测试未报错”“目录存在”“结果方向合理”均不等于已证明。E7 相关项只能由 hooks 完成事件后形成的正式五记录面、独立复算和最终审计证明；对话代理不得轮询正式目录来提前改变状态。

## 3. hooks事件后的唯一收口顺序

1. 接收 hooks 的完成或异常事件。异常时保留现场并按其状态停止；完成时才读取正式 `decision.json`、`artifact_hashes.json` 和五记录面。
2. 对正式E7五记录面执行清单与任务矩阵检查，并运行`baselines/e7_dynamic/audit_e7_external_pause_timing_20260716.py`。2026-07-18经用户批准的v2规则废止“耗时达到13934秒即污染”的错误绝对门，改为精确任务—阶段逐对验收：父系清洁复现相对误差不超过5%；子系须移除正向且在暂停时长10%带宽内聚类的共同偏移；九项检查点、非计时载荷、事件哈希和历史包不变性全部验签。任一身份、哈希或配对模式不符仍HALT。
3. 确认正式重放目录不存在或为空后，运行 `baselines/e7_dynamic/e7_multiday_zero_search_replay_20260715.py`，生成28日电网日零路径搜索重放五记录面；若目录非空，保留现场并停止，不让旧干运行或失败残留混入正式清单。
4. 运行 `baselines/e7_dynamic/audit_e7_replay_invariants_20260715.py`，生成独立重放不变量五记录面。
5. 确认独立总审计目录不存在或为空后，运行 `baselines/e7_dynamic/audit_e7_multinetwork_formal_20260715.py`，生成独立总审计五记录面；脚本对非空旧目录硬拒绝覆盖。
6. 运行 `baselines/paper_story/build_20260715_formal_evidence.py`，从封存源重建E7七件论文展品并最后发布`e7_dynamic_paper_evidence_manifest.json`；不得人工改写生成文件来改变方向，七件展品和manifest缺一均视为未就绪。随后运行零搜索`baselines/e7_dynamic/build_e7_steps_1_to_6_attestation_20260717.py --publish`，只从正式120任务、28日重放、重放不变量、独立总审计和论文展品manifest五套封存面生成`e7_steps_1_to_6_attestation_20260717.json`；任一哈希、计数、暂停时效、零搜索字段、搜索合同或展品来源不闭合时只返回HALT且不得创建或覆盖证明。该证明只授权步骤7以后的G0和外部强基线准备，不代表十步总收口完成。
7. E7证据只先作“当前算法版本收口”，不立即锁稿。Solomon 56例的SINTEF零搜索BKS复算、无BKS搜索bundle和CPU口径审计已经通过；E7释放共享内核后先复核保护哈希。随后必须先闭合ALNS预算G0：当前权威判定为`HALT_ALNS_BUDGET_CLOSURE_REQUIRED`，31个评分调用点中5个已计费、24个仍阻断；静态无BLOCK和零/极小预算行为门全部通过前，禁止Homberger开发搜索和Solomon正式胜负测试。既有DIMACS/CVRPLIB只作回退或补充证据，不与SINTEF主表混用。
8. G0通过后，算法大修只能在非Solomon开发集完成，并在看到Solomon最终结果前冻结单一版本。随后以SINTEF分层口径运行Solomon正式多种子主基准，全部失败、超时、波动、车辆数劣势和不利Gap原样保留；PyVRP/HGS按同机单线程墙钟时间作外部强基线，内部ALNS/LNS及消融按相同完整评价预算比较。正式表分别报告CPU、RT、Tbest、Runs及硬件/线程合同，不以PassMark换算支持异机算法优越性。若测试失败，不得回看测试集调参后覆盖原结果。
9. 若E2触发算法换代，步骤1--6生成的旧E7证据仅作旧版本完整性记录，不得进入新版本论文。逐项列出E2--E7中受源码变更影响的证据，按同一新版本重跑，并重复E7十步证据收口；禁止混用新旧结果。若未触发，则保留现有算法和E7证据。
10. 在确定最终算法版本后，根据生成证据终修正文衔接和管理启示；中英文摘要、结果解释和结论的定量句由生成文件承担，不重复手工抄数。同步更新HANDOFF、总memory、动态memory和PRD memory，重新编译并检查实际输入时序、日志、A4页、正文提取与代表页视觉。最后运行不带`--allow-pending-e7`的故事审计、E7/论文定向回归、必要全量回归、`git diff --check`和保护源零漂移检查。只有全部命令各自成功且矩阵所有项均已证明，才允许报告总目标完成。

## 4. 明确禁止的捷径

不得把预检结果替代正式结果；不得因正式方向不理想删除失败流、换实例、调种子或扩大预算；不得把840行重放称为路径—充电联合优化；不得把滚动阶段当独立样本；不得只看净收益而隐藏收入、成本和服务量；不得以pending故事审计、局部测试或PDF可打开作为全目标完成证明；不得在正式E7完成前写入最终收口标记。
