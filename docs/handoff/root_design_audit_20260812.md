## 一、Claude 初审

### R1【根伤候选】60 kW 可能瓦解我自己立的"多窗口联合择时"贡献叙事

- `FACT` 链条：算法贡献叙事（台账 §22/§23）建立在"**22 kW 下任何单一窗口装不下全日电量 → 充电必须跨全部停留段联合择时**"之上；随后 P43-I 依实证把功率改为 **60 kW**。
- `FACT`（算术）：60 kW 下午休可充 ≈ (2 h − 装货 0.72 h) × 60 ≈ **76.8 kWh**，而车辆日需 **45–74 kWh**——**单靠午休一个窗口可能就够了**。
- `INFERENCE`：若成立，"联合多窗口"的必要性消失，`prev_night` 修的主角地位不保；时变碳故事简化为"午休充（平价 0.79＋全天最清洁）vs 收车即充（峰价 1.33＋较脏）"。**效应仍在（钱 −20.7%／碳 −50.8%），但机制深度变浅**——卖点从"算法必须联合择时"退为"利用运营停留的择时"。
- **这是我自己造成的矛盾**：叙事是 22 kW 时立的，参数是我后来按证据改的，两者从未对表。
- 须验证（红队量化项 Q1）：逐见证车（含 3 趟车的趟间停留与装货占用）复算 60 kW 下"仅午休"覆盖率；若覆盖，主贡献叙事改写候选＝"多趟结构创造清洁停留窗 × 择时策略利用之"（仍是多趟×时变碳耦合，不再依赖 prev_night 当主角；prev_night 保留给 22 kW 情景与超长日里程）。

### R2【根伤候选】"本体 B0"从未被定义——整张消融表的分母悬空

- 所有"超过本体"的主张都需要一个 B0。**内核-only 不是合法 B0**——它不认识车型、充电、多趟、车场归属，解不了本问题。
- 现状：历史实验的 F00 是"两个零件都关"，但其余通道、充电策略、归属规则各在什么状态**从未作为"本体"被声明**。B0 不定，每个"改进 %"都没有分母——**这正是"根上错了后续全错"会真实发生的地方**。
- 提案（待红队攻）：**B0 ＝ 完整模型 ＋ 最朴素默认策略的合法求解器**：路线搜索 ON、客户固定归最近场、车队构成用初始启发式、asap 充电、趟次按构造、换型/跨场/公平/择时全关。可辩护为"标准 HGS 适配到本模型"。消融＝B0 → 逐通道加，终点＝实战全开。

### R3【设计缺口】协同与公平缺"制度对照"——算子开关 ≠ 制度比较

- 历史教训（记忆在案）：王勇 43.2% 收益来自**车队池化**；旧 E3 只测客户重指派 → 1.48%。
- "合作比单干强"需要的对照是**单干基线＝两场各用自己的客户与车队独立求解（两次独立运行）**，对照**合作＝联合求解**；利润分配用 `profit.py` 现成账本。公平实验＝分配规则对照，效应＝公平度指标＋"不因公平而退化"的成本。
- 现状：V3 算例下这两个实验的对照臂设计**文档不存在**。DepotSplit 开关只能测"算子值多少"，测不了"制度值多少"。缺口必须补设计（不改代码）。

### R4【设计缺口】动态实验的机械在线基线（P38 已定方向）未接 V3

- 旧脚本在旧冻结产物上报 `charging action curve id disagrees`，从未按 V3＋60 kW 重接。
- 待任务 A（动态插入算子）落地后一并定设计：对照＝机械规则（新单插入最近可行车末尾、不重优化），本文＝触发式重优化＋待命充电内生选择（P34）。

### R5【架构风险】"每移动全评价"的搜索强度天花板——经验问题，有现成缓解路径

- `FACT`：F11（仅 2 通道）3.28 秒/循环；实战全开后提案量将数倍增长，循环时间可能回到 6–15 秒。私有侧收敛需要几百循环（未证）。
- 缓解路径（文献常规，且不违反"全评价决定每次接受"的既有承诺）：**代理分数只做候选排序与剪枝，接受仍由全评价判**。不预先施工——任务 B 给出全开循环秒数、任务 D 给出收敛所需循环数，两数相乘即可行性判决；过慢再上。

### R6【可能自愈】代理电价 43% 错配在 60 kW 下或已自动消失

- `FACT`：分时类别价在48个等时长积分行上的全日均值 0.7902 ≈ 午休平段 0.7921。若 60 kW 下充电集中于午休，**代理均价几乎恰好等于实付**。
- 须复算确认（红队 Q2）；确认则 §12 的 shift-profile 改造正式降级为不做。

### R7【小项清单】（交红队逐条核）

1. 上午/下午 1:2 分配规则的任意性是否影响结论稳健性；
2. **体积比载重更紧**（约 80 m³ ÷ 7.2 ＝ 11.1 趟 > 12223 kg ÷ 1735 ＝ 7.0 趟）——文档叙述以载重为主是否误导；
3. 2 车场对"多车场协同"叙事是否过小（150c 是否该上 3 场）；
4. 动态率 10/50＝20% 在 DVRP 文献常规区间的位置；
5. asap 作为"企业现行做法"基线的可辩护性与引用；
6. `depot_collaboration` 通道与新 DepotSplit 的功能重叠如何在消融中分开归因。


### R8【根伤候选·新】混合车队的溢价选值经不起有罪推断

- `FACT`：EV 日固定溢价取 **50 元**（陈婉茹 2023 建模值，目标期刊内先例）。但本项目自己的取证报告（`depot_charging_power_evidence` 同轮的 `instance_rebuild_literature`）实测中国现实溢价为 **13.26–46.97 元/日，全部低于 50**。
- 有罪推断：**我们恰好选了让混合车队出现的那个值**——溢价低于临界带下界则纯电全赢、混合消失。审稿人一问"为什么不用实证区间的值"，混合车队一章即塌。
- 翻案条件：把选值改成**阈值分析**（扫 13／25／47／50 元，报告混合车队在哪些溢价下存续、纯电在哪些溢价下回归）——这正是 Hiermann 2019 的做法，把"选值嫌疑"变成"管理启示"。**主文口径仍可用 50（期刊内先例），但必须带阈值表**。

### R9【已翻案·新】公平机制的作用条件在 V3 上实测存在

- `FACT`（2026-08-12 复算）：两场单干收入 广州 1749.31 元（36 单、9238 kg）vs 佛山 565.24 元（14 单、2985 kg），**收入比 3.09:1，大场占 76%**。
- 与 E5 死局（两臂逐会话完全相同、机制作用条件不存在）不同，V3 的利润不对称真实存在——公平分配第一次有东西可分。
- 仍缺：分配规则对照的实验设计（θ 扫描或对比分配方案），与 R3 的制度对照一起补。

### R10【设计缺口·新】非线性充电没有"效应呈现"设计

- 用户要求"非线性充电要比机械的线性充电更仿真"——仿真度主张也需要**对照**才能呈现：线性假设 vs 非线性实测下，充电时长被低估多少、导致多少趟间衔接失败或成本低估。
- `FACT`：60 kW 曲线在 SOC 85% 后功率衰减（P35 登记曲线 0.85/0.95 拐点）；多趟趟间补电时间紧张时非线性才 binding——V3 恰好有 5 辆多趟车。
- 现状：**"线性 vs 非线性"对照臂从未设计**。翻案条件：加一个线性充电影子臂（同功率恒定），报告两者在趟间补电时长与可行性上的分歧。

### 3.2 我被红队驳倒的清单（如实记录）

1. **R6"代理电价自愈"——驳倒**。11:00–12:00 是峰段 1.327 非平段；顺时因果下上午电量须在首趟前充（谷电），全车队加权实付 0.620 vs 代理 0.790，**低估 21.6%**。shift-profile 代理修正**重新上桌**。

3. **"均值÷标准误≥2 ≈ p<0.05"——小样本不成立**：n=5 时 p≈0.116、n=10 时 p≈0.0766。改为报精确 p 值与自由度的配对检验。
4. **"容量不紧"（台账缺陷4）——错**：只算了载重漏了体积；体积下界 13 趟，见证 14 趟，**体积很紧**。副作用是好消息：体积紧使多趟成为结构必需，多趟机制的地基更硬。
5. **asap＝"企业现行做法"——无观测证据**，改称"收车即充的机械基线"。

### 3.3 R1 的裁定（部分成立，叙事收窄而非摧毁）

## §四 追加根伤 G8：充电可行性走硬拒绝而非罚分，与 HGS 基座范式冲突（2026-08-12 深夜）

### 证据（代码级 `FACT`）

`education.py:204-238` 的候选评价链：

```
move.apply() → raw
  → charging_prescreen.screen(...)      失败 → CandidateStatus.REJECTED_CHARGING（硬拒，不评价）
  → repair_changed_duties(...)          抛 TypeError/ValueError → REJECTED_CHARGING（硬拒，不评价）
  → 存活者才进 evaluator.evaluate()
```

`schedule_coordinator` 分支（`education.py:133-160`）同理：`coordinated.status != FEASIBLE` 即硬拒。

**充电违约在任何路径上都不进罚分成本，只做二值过滤。**

### 与基座范式的冲突

PyVRP 0.12.2 / Vidal HGS 的核心设计：载重超限与时间窗违反**不拒绝**，进罚分成本（`penalized_cost`），罚分系数按可行率自适应；种群同时维护可行与不可行个体，靠穿越不可行区抵达更好的可行解。

我们在充电这一维单方面关闭了该机制。后果实测：68211 提案中 60606（88.9%）在评价前被过滤；`duty_crossover` 被过滤 98.7%，**遗传算法的主引擎实际只有 1.3% 的通过率**。

### 分级修法（按代价从低到高，等诊断数据定夺）

1. **配置层**（零代码）：充电窗口由 `prev_night` 改 `full_gap`，放开可充时段。若松弛复检显示大批候选翻可行，停滞即为配置产物，本条即完整修法。
2. **算子层**：让交叉／多趟在重组时保持充电自洽（丙的修法），不产生注定被拒的后代。不动受保护文件。
3. **架构层**：把充电违约改为罚分维度（配缺电量惩罚与自适应系数），使搜索可穿越充电不可行区。**须改 `search/evaluation.py`——受保护文件，须先报批**。文献支持充分（Schneider et al. 2014 EJOR、Vidal HGS 的可行/不可行双种群），但工作量与风险最大。

### 纪律

在 `charging_rejection_diagnosis_20260812` 的四项结果回来之前，**不得动手改任何一层**。若结论是甲（算例确实能量紧），第 1、2 层仍值得做（罚分穿越对搜索有独立价值），但预期收益要下调，且要同时检查算例的能量裕度设定是否合理。

### G8 的文献裁定：架构选择错了，且有现成的正确做法

**权威文献**：金东遥, 刘敏, 朱烨娜, 赵肄江.《基于混合遗传搜索求解载重约束的电动车辆路径问题》. 系统仿真学报, 2024, 36(11): 2528-2541. DOI 10.16182/j.issn1004731x.joss.23-0863. Zotero item key `YSXHRSJT`.
选它的理由：同为 HGS 基座、同为电动车辆路径、中文顶刊、2024 年、并对标 Vidal (2022) HGS 与 IEEE WCCI2020 EVRP 竞赛前三名。与本项目架构同型度最高。

**该文的处理方式（原文事实）**：

1. **双层染色体**：上层染色体存满足**载重**约束的 CVRP 路线，下层染色体存满足**电量**约束的 FRVCP 方案。原文：「仅在上层染色体上进行交叉与局部搜索，在下层染色体上进行个体适应值的评估与父本选择。」
   → **交叉与邻域搜索完全不受电量约束干扰**；电量在路线定下来之后作为子问题**求解**。
2. **电量是被"解"的，不是被"检"的**：BC（基于回溯的充电策略）通过回溯寻找增加距离最小的插站位置，**总能产出电量可行的路径**（算法 2 输入「电量不可行路径」，输出「电量可行路径」）。
3. **可行/不可行双子种群**：原文「因为复杂优化问题的最优解或近似最优解有可能停留在可行空间与不可行空间的边界附近，所以 BHGS 初始化了两个种群，分别为可行解子种群和不可行解子种群」。
4. **不可行解不淘汰，走罚分＋概率修复**：罚分代价 φ(r) = d(r) + ω·max{0, c(r) − C}，惩罚系数按 Vidal et al. (2012) OR 60(3) 动态调整；邻域搜索后仍不可行的个体**以 50% 概率**修复，修复时**把惩罚系数放大 10 倍**。

**与本项目的对照**：

| | BHGS（文献） | 本项目现状 |
|---|---|---|
| 电量约束的地位 | 待求解的子问题 | 淘汰路线的过滤器 |
| 交叉是否受电量影响 | **否**（只在上层染色体） | **是**（98.7% 被拒） |
| 电量不可行个体 | 进不可行子种群，罚分＋50% 修复 | **直接丢弃** |
| 充电子程序的契约 | 总是产出可行方案 | 可以抛异常导致整个候选作废 |
| 种群参数 | μ=25, λ=40, n_Elite=4, n_Closest=5 | `copied_hgs_defaults` **完全一致** ✅ |

**判定**：G8 成立，且性质是**架构选择错误**而非实现缺陷。本项目把 Vidal HGS 赖以工作的「穿越不可行区」机制在电量这一维单方面关闭了，同时又没有像 BHGS 那样把电量降级为可解子问题——**两条路都没走，落在中间最差的位置**：既不能穿越，又要为每个候选付完整充电修复的代价。

**修法（照 BHGS，不自创）**：
- **首选**：把充电从"候选过滤器"改为"评价阶段求解的子问题"——搜索/交叉在 duty 层不再因充电失败而丢弃候选；充电修复失败时不丢弃，而是给出缺电量并计入罚分，进不可行子种群。
- 需要动 `search/evaluation.py`（受保护文件）才能加缺电罚分维度 → **须先报批**。
- 若报批未过，退而求其次：让充电修复在失败时返回"最好努力方案＋缺口量"而非抛异常，缺口按现有罚分口径折算（不改受保护文件），先验证收益。
