# 4.4.2 原因诊断验收

日期：2026-09-08（本轮验收）  
范围：只核对既有 `fixed_plan_retime_20260910` 与 `timing_80`，没有启动随机搜索，没有修改生产源码或论文。

## 验收结论

`FACT`：`fixed_plan_retime_20260910` 收齐了 120 份来源方案并尝试了 480 次重排；120 份按条件分为北京×0.2 40份、午谷×0.2 20份、北京×1.0 20份、午谷×1.0 40份。按来源方案自己的规则重放为 120/120 数值一致，脚本列出的车数、距离、固定成本、里程成本和燃油成本也保持一致。四规则都得到可行结果的只有 116 份。

`FACT`：这份重排并没有冻结时钟。脚本把每辆车交给 `repair_changed_duties` 全量修复；修复器重新构造车场充电动作，并把充电结束时刻加入发车下界，随后重新计算该趟回场时刻。对应源码是 `fixed_plan_retime.py:94-104`、`charging.py:2333-2367`、`charging.py:2480-2521`。因此它冻结了客户次序、车辆身份和趟次结构；在116份四规则均可行方案中，充电场次、总电量、逐场电量和占用时长也碰巧保持一致，但充电开始时刻和后续趟次时钟会改变。它不能称为“只改充电时刻且时钟冻结”的反事实。

`FACT`：`timing_80` 才冻结原方案的路线、车辆、逐场充电量、占用时长、SOC字段和 `trip_clock`，只在每场原固定窗口内选择新开始时刻；公共站会话不动。现有结果为80个来源、320次评价、`failures=[]`。它只覆盖北京×0.2和午谷×1.0各40份，没有覆盖另外两个条件。

`FACT`：`timing_80` 的自身规则复现并非80/80全通过。即充、只看碳、兼顾三类各20份都复现；20份只看电价来源在固定时钟下重新择时后，总成本/总排放偏差范围约为 -0.185 至 +2.368。原因是同电费候选之间的择时次序会改变排放；因此“原规则复现真实”目前只能对整车修复口径成立，不能推广到严格固定时钟口径。

## 四份不可行的决定性核验

四份均来自：

- `solver/reports/grid2x2_v3_20260906/beijing/P=1.0/MT-HGS/run_03/best_solution.json`
- `solver/reports/grid2x2_v3_20260906/beijing/P=1.0/MT-HGS/run_06/best_solution.json`
- `solver/reports/grid2x2_v3_20260906/beijing/P=1.0/MT-HGS/run_07/best_solution.json`
- `solver/reports/grid2x2_v3_20260906/beijing/P=1.0/MT-HGS/run_10/best_solution.json`

`FACT`：它们不是“原开始时刻也不可行”。四份原即充方案均通过正式评价；`timing_80` 在固定原时钟内对四规则重排也全部成功。失败只发生在整车修复器按新规则逐趟重建时。

`FACT`：以 `run_06` 的 `EV_D_OSM_WAY_1071205721_2` 为最小复现：原第三次充电从 52081.837 秒开始，按原时序计算的最晚开始为 52193.299 秒，尚有约111.46秒余量。只看电价规则先把第二次充电推迟，第二趟回场随之变为 52312.066 秒；修复第三次充电时得到窗口 `[52312.066, 52193.299]`，最早开始比最晚开始晚约118.77秒，于是抛出 `no feasible depot charging window`。另外三份触发同类错误，涉及 `EV_D_OSM_WAY_1071205721_3` 或 `_2`。

`INFERENCE`：直接原因是修复器逐趟贪心选择当前规则下的开始时刻，却没有为后续紧窗口保留余量，也没有在后续失败时回退到上一场的较早候选。原可行开始时刻和 `timing_80` 的320次成功构成反例，说明这是现有模型允许、当前修复实现没有利用的调时空间，不能把四份剔除解释为规则本身不可行。

`UNKNOWN`：本轮按主代理要求停止，没有继续枚举四份中每个失败策略的所有候选组合，也没有修改或验证回溯修复。

## “窗口锁”“价格锁”和碳价0.76的口径

`FACT`：严格固定时钟的 `timing_80` 中，“窗口不可达差”定义为：同一方案采用只看碳规则后的充电排放，减去“全部既定电量都按全天最低碳强度0.1541充电”的理论值。北京×0.2均值为17.791 kg，午谷×1.0均值为18.730 kg。它是当前80份有限方案、固定电量和固定时钟下的端点差，不是模型全局上限。

`FACT`：“价格保留差”定义为：同一方案兼顾规则的充电排放减去只看碳规则的充电排放。严格固定时钟下，北京×0.2均值为18.086 kg，午谷×1.0均值为7.148 kg。因此“价格锁16–18 kg”只近似描述低碳价条件，不能代表午谷×1.0，更不能写成普遍常数。

`FACT`：短报告中的2.05元/kg和4.16元/kg，是两个端点的“平均电费增量÷平均减排量”；它们不是逐场边际曲线，也不是规则翻转的临界碳价。

`FACT`：0.76来自旧诊断脚本把“窗口内最便宜候选”和“窗口内最净候选”作端点比较后得到的电量加权25%分位。精确到会话，0.76266对应 `EV_D_OSM_WAY_1003511503_1` 的首趟前46.936 kWh充电：只看电价来源的 `run_01/02/06/07/08/10`，以及兼顾来源的 `run_03/04/05/06/07/08`。这些会话的前一日窗口起点约15:37，最便宜候选为06:00（0.563元/kWh、0.585 kg/kWh），最净候选为前一日回场时刻（0.836元/kWh、约0.227 kg/kWh）。另有16:43回场的一场约为0.788。故0.76是特定会话簇的端点比值，不能武断写成“17点界”。

## 样本剔除与分解边界

`FACT`：北京×1.0官方10次均值差（兼顾−即充）是 -5.975 kg；短报告的 -9.993 kg来自剔除4份即充来源后，只用16份四规则均可行方案重算，不能替代官方差。

`FACT`：午谷×1.0中，兼顾−只看碳的官方差为成本 -23.136元、排放 +20.511 kg。以“只看碳方案先换成兼顾规则”为路径，可写成调时 +6.925 kg、余项 +13.586 kg；换一条合法顺序，以“兼顾方案先按只看碳规则结算”为路径，则是方案项 +13.893 kg、调时项 +6.619 kg。成本分解也随顺序从 `-20.834 + -2.302` 变成 `-0.995 + -22.141`。这些是路径依赖的恒等分解，不是唯一因果归属。

`INFERENCE`：13.6 kg对应的成本余项只有约2.30元，足以说明这些已找到方案在目标值上很接近，不能单独证明“抽签”。政策改变搜索目标，充电规则也会通过逐趟时序、代理评价和搜索反馈影响最终路线与车队；现有数据尚未把这些反馈排除。

`FACT`：所谓“低于1.05车队稳定、高于1.12纯电”来自有限重优化解池的下包络。该池样本数量和来源不均，而且只对池内已找到方案取最好值。其自身还在0.689、0.974和1.124附近出现池内方案/构型切换，所以“低于1.05稳定为某一车队”的概括过强；1.124以上纯电也只是该有限池中的赢家，不是全局证明。

## 供主代理选择的下一步

`INFERENCE`：4.4.2现在可以安全写成：固定路线/车队/电量/原时钟时，窗口不可达差在两个已核条件约17.8–18.7 kg；价格造成的剩余差随碳价和日历从18.1降到7.15 kg。0.76只属于一组早回场会话，2.05/4.16只是端点平均比值。不要使用剔除后的北京×1.0官方差，也不要把单一路径分解写成唯一因果。

`INFERENCE`：两份1油5电候选可用于比较“本臂最低成本方案”和“相对均值成本近似持平、排放更低的折中方案”。四份失败证明跨趟充电修复需要可行性回退；修复后的最小验证是四份方案在四规则下均能找到至少原可行时钟，并保持路线、车队、逐场电量和服务量不变。现有证据没有证明修复该处会使午谷×1.0选择1油5电，也没有证明它能实现四臂比较中的成本与排放双低。

`UNKNOWN`：是否把4.4.3改为固定车队比较、候选池热启动，或继续比较内生车队政策结果，属于主代理/用户后续选择；本报告不替其决定。现有证据不要求立即改变碳价、补贴、班次或电池参数。
