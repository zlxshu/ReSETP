## 一、为什么是它（证据，不是判断）

- `FACT`：Simensen, Hasle & Stålhane (2022), *Journal of Heuristics* 28:653–697，第 666 页表 1 —— 在 Vidal 现代 HGS 的 education 之后接入 SISR 的破坏重建，同实现同预算下终值 gap 由 **0.1879 → 0.1714**、过程平均 gap 由 **0.3061 → 0.2810**。这是严格消融（只开关这一个零件）。
- `FACT`：同文 p.666 图 5 —— R&R 约占最佳配置 CPU 的 35%，原局部搜索约 55%。即它是**吃预算的**，必须计净值。
- `FACT`：同文表 2（p.668）—— 删掉 M3/M2/M7/M4 四个经典邻域反而更好。**配套动作是删邻域，不是加邻域。**
- `FACT`：Christiaens & Vanden Berghe (2020), *Transportation Science* 54:417–433 —— SISR 原文；技术报告表 3（p.18）参数实验：平均删约 5 个客户不足、20 个过度破坏，最大串长超过 10 无进一步收益。
- `INFERENCE`：本项目今晚的三个失败方向（每移动精算充电、频繁车型重分配、堆叠邻域）在文献中均有直接反证（Montoya 2017 / Hiermann 2016；Penna 2019 表 5–6；Simensen 表 2）。SISR 是反过来的一类：低频、大幅、跨盆地。

## 二、零件定义（先在公开侧实现，再考虑私有侧）

**为什么先公开侧**：SISR 的证据全部来自纯路线问题（CVRP）；公开 28 题正是纯路线问题，迁移无前提缺失。私有侧涉及多趟、SOC、充电，破坏重建后的可行性修复要复杂得多，属第二步。

### 2.1 破坏：相邻串移除（Adjacent String Removal）

1. 随机选一个种子客户 c。
2. 取 c 的若干空间近邻所在的**不同路线**，每条路线删除一段**连续的**客户串（串必须包含该路线中离 c 最近的那个客户）。
3. 串长与路线数按原文参数化（见 §三）。
4. 被删客户进入待插入池。

### 2.2 重建：带跳过的贪婪插入（Greedy Insertion with Blinks）

1. 待插入池按一个随机选中的排序规则排列（原文给四种：随机、需求降序、离车场远者优先、离车场近者优先）。
2. 逐个客户扫描所有可行插入位，按插入代价升序考察；**每考察一个位置，以概率 β 跳过它**（blink），不跳过则就地插入。
3. 全部插回后得到新解。

### 2.3 接入点

- 位置：HGS 的 education 之后（即现有路线局部搜索跑完之后），对该子代再做一次 R&R，然后再入群。
- 接受：沿用现有种群的接受逻辑（罚分成本＋可行性），**不引入独立的模拟退火接受准则**——原文 SISR 用 SA，但 Simensen 版把它接在 HGS 里时保留了 HGS 的种群机制。若要引入 SA，须单独消融并报批。
- **本零件只在公开适配器上启用**；私有适配器保持不变，直到公开侧证明有效。

## 三、参数（全部来自文献，不得按结果倒选）

## 四、配套动作：删邻域（同批做，单独消融）

Simensen 表 2 显示删掉部分经典邻域反而更好。本项目公开侧当前的邻域集合见 `kernel_proposals.py` 的 `node_ops` / `route_ops`。施工时**不要一次删**，而是：先只加 SISR、测；再逐个尝试关闭与 SISR 功能重叠的邻域、各自测。每次一个开关。

## 五、验收与预注册否证条件

- **测法**：公开侧，同种子配对，固定墙钟（不是固定代数），A 组＝现状，B 组＝现状＋SISR。先在 3–5 道题上做单种子方向性判断，方向一致再扩种子。
- **必报**：完成客户数与需求量、真尺子可行性、完成代数、time-to-best、SISR 占用 CPU 比例、最终成本配对差。
- **否证条件（预注册）**：
  1. 若同墙钟下 B 组配对成本差与 0 无法区分，则该零件在本项目无增量；
  2. 若 B 组因 SISR 占用预算导致完成代数大幅下降且最终成本更差，则按净值判负，不得只报"它找到了更好的中间解"；
  3. 若 B 组产生不可行解或服务不完整，直接作废，不得以成本下降抵消。
- 三条任一触发，如实记录并停止该方向，不加预算、不换口径救结果。
