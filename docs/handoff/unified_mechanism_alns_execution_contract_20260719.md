# 机制贯穿式 ALNS：隔离开发合同（2026-07-19）

状态：`APPROVED_ISOLATED_DEVELOPMENT_ONLY`

本合同只授权阶段一中的隔离算法开发。它不授权阶段二、不授权正式 E2--E7
试验、不授权修改模型语义，也不授权修改三份受保护文件：

- `solver/src/setp_solver/cost.py`
- `solver/src/setp_solver/check.py`
- `solver/src/setp_solver/search/evaluation.py`

## 1. 要解决的真实问题

当前 v7 的长处是：路线搜索结束后，车型与充电、低碳充电时刻和跨车场责任
三个专用模块能够单调改进完整解。当前 v7 的短处是：搜索只从一份确定性初解
出发，机制模块又主要位于搜索结束后。v9 虽然运行四条短轨迹，但四条轨迹仍从
同一份确定性初解出发，因此它没有检验“真正不同的强初解是否有用”。

第一轮只检验这个根因，不把 HGS、ALNS、路线池或终局多跑选优再次硬接。

## 2. 最终架构方向

最终算法仍是一台 ALNS，而不是几台算法跑完后拼结果。它包含四层：

1. **多样强初解层**：同时构造纯路由强起点和机制感知起点，按质量与结构差异
   保留，不把所有算力押在一个固定起点上。
2. **强路由骨干层**：保留成熟路线搜索能力；公开原生算例中，业务机制若不存在，
   相关模块必须自然零动作。
3. **机制专用改造层**：只有真实冲突出现时，才对受影响的车场责任、车型、充电
   和时刻做局部改造；不生效时不改轨迹、不耗完整评价。
4. **完整复算层**：任何进入比较的解都用同一完整检查器和成本器独立复算。

多车场、协同、公平和动态需求不会因为第一轮尚未实现就被宣称完成。它们必须在
各自真实绑定的数据区另立拆件门；没有绑定证据的机制保持“未证”。

## 4. 第一门：真正多样初解的诊断门

### 4.1 数据冻结

使用尚未看过算法结果的原始 donor 03，冻结 `source_scale=25` 和
`source_scale=50` 两份开发题。实例名必须写真实客户数，不再把来源规模写成
实际客户数。实例只用于算法开发，不进入正式 benchmark。

本门沿用阶段一当前开发情景的 `B_battery_kwh=280`，随机种子固定为 `1`，档案
容量固定为 `6`。这些参数在看结果前写入锁文件，不因结果调整。

构建前记录生成器、原始来源和本合同的 SHA-256。构建后生成
`blind_lock.json`；运行器若发现合同、候选源码、参数或数据哈希变化，判
`INVALID_GATE_POST_LOCK_MUTATION`。

### 4.2 固定的十二个起点

每题、每种子固定生成十二个完整可行起点：

1. 当前确定性起点；
2. 按最迟服务时间排序；
3. 按最早服务时间排序；
4. 顺时针扫描；
5. 逆时针扫描；
6. 旋转三分之一圈的顺时针扫描；
7. 旋转三分之一圈的逆时针扫描；
8. 最近邻链；
9. 受限候选随机贪心链 A；
10. 受限候选随机贪心链 B；
11. 最迟服务时间顺序加远端客户电动车倾向；
12. 扫描顺序加远端客户电动车倾向。

第 2--10 项使用同一个全 CV 类型提示，隔离路线构造贡献；第 11--12 项才检验
车型与充电感知。当前确定性起点必须原样进入池，保证新池至少保留旧起点。

### 4.3 先隔离构造，再做一次共同终局复核

十二个可行起点先直接用同一完整目标评分。初解选择阶段不得调用 v7 的终局机制
栈，也不得运行任何短 ALNS；否则无法判断收益来自真正不同的构造，还是来自多跑
旧修复器。这是与 v9 的关键区别。

选出原始成本最低的新起点后，只让“当前确定性起点”和“新赢家”各走一次完全
相同的 v7 终局机制栈，并独立复算。这个复核只问：构造优势在共同终局处理后是否
仍然存在。它不参与十二选一，不把局部修复包装成初始化收益。

本门只诊断初始化。第一个固定锚点走 `initial_reference`，其余 11 个参与选择的
完整起点各计一次候选评价；构造时间、顺序解码、可行性检查、终局局部精算和最终
独立复算分别记账。它不构成与 v7、HGS 或 ALNS 的公平算法胜负比较。

### 4.4 预注册通过标准

两题必须同时满足：

- 十二个起点全部覆盖所有客户，最终候选全部可行，成本复算误差不超过
  `1e-7`；
- 每题至少六种不同路线结构；
- 当前确定性起点确实在池中，且质量优先、结构差异优先的档案至少保留四种路线
  结构和两个构造家族；
- 新池的最好原始成本在两题都严格低于当前确定性起点；
- 两题相对改善的中位数至少为 `0.5%`；
- 至少一题的赢家来自非默认构造家族；
- 默认起点和新赢家各走一次共同终局机制栈后，新赢家在两题都不得倒退为劣者；
- 初解选择必须严格满足 `initial_pool_candidate_evals = 11`；任何完整成本计算
  都进入 `full_solution_replays`，任何受影响路线计算都进入
  `route_local_exact_evaluations`，不得出现隐藏完整评价。

全部满足才判 `GO_EMBED_DIVERSE_INITIAL_POOL`。否则判
`STOP_DIVERSE_INITIAL_POOL`，不得扩大种子、不得拿旧题调参数救结果。

## 5. 通过后的第二门（本轮尚不授权运行）

若第一门通过，才把冻结档案接入连续 ALNS。候选与 v7 使用相同完整评价总额；
构造和起点筛选消耗的完整评价从候选预算中扣除，剩余预算才用于 ALNS。第一批
只跑另一组新鲜的两道绑定题和一道自然非绑定题、一个种子。候选必须同时严格胜
v7、ALNS 路线源加共同完成器、HGS 路线源加共同完成器；中位改善至少 `0.5%`，
墙钟不超过强对手中位数的 `1.25` 倍。非绑定题要求机制开关的解、成本、轨迹和
随机数末态完全一致。

第二门通过后仍只允许小规模多种子确认；正式试验必须再次取得用户批准。

## 6. 诚实边界

无法诚实保证每个随机种子、每个已饱和公开算例都严格胜 HGS 或 ALNS。可验收的
底线是：有改进空间的题严格胜；已证明饱和的题匹配最优；完整模型上按实例聚合
后显著胜三类强对手；任何机制在不生效时精确零动作。公开原生 benchmark 与完整
ReSETP 模型必须分开表述，不能把“HGS 路线源加共同完成器”写成“纯 HGS 完整
模型求解器”。
