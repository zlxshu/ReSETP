# 字段与文件改名映射（2026-08-15）

本次是纯改名重构：不改数值、不改计算逻辑、不删除字段。`solver/reports/**` 中已有历史结果未改写、未删除；历史结果通过下面的映射解释。

| 旧名 | 新名 | 改名理由与语义边界 |
|---|---|---|
| `tariff_carbon_48slot_calendar.csv` | `tariff_carbon_hourly_calendar.csv` | 活动碳强度、场内电价、公共电价和服务费在同一小时内取值相同；48 行是存储/积分位置，不是 48 个独立的半小时来源观测。 |
| 活动日历的 `half_hour_slot` | `hourly_calendar_row` | 该列在活动日历中仍保留原数字和行序，只把名称改为实际的小时取值口径。 |
| 独立历史 TVCI 48 格资料的 `half_hour_slot` | `half_hour_interval_index` | 这份资料仍是 30 分钟存储/积分网格；新名只消除旧名歧义，不把它改写成小时观测。 |
| `depot_charger_count` | `configured_depot_gun_count_if_finite` | 保留原值 2，并明确它只在有限车桩容量模式下作为配置输入；当前 `UNBOUNDED` 模式不把它作为有效并发上限。 |
| `depot_power_kw` | `depot_site_power_kw_shadow` | 保留设施表中的原值，但明确它是设施表影子字段；活动运行功率仍由 fleet 表的 `depot_charge_power_kw` 提供。 |
| `default_electrification_level_percent` | `default_fleet_electrification_percent_metadata_only` | B2 中属于只写入元数据、不进入当前运行数值的字段，新名直接标出这一点。 |
| `level_allocations_json` | `fleet_allocation_map_metadata_only` | B2 中属于只写入元数据、不进入当前运行数值的字段，新名直接标出它是车队分配记录而不是活动约束。 |

## 兼容读取

新名优先、旧名兜底集中放在 `solver/src/setp_solver/field_rename_compat.py`：

- 日历路径优先找 `tariff_carbon_hourly_calendar.csv`，找不到时读取旧文件名；
- 日历行、有限模式车桩数、设施影子功率均优先读取新列，缺失时读取旧列。

兼容层只读旧数据，不把旧名重新写回活动代码或活动数据。

## 不在本次精确映射内的名称

其他历史 TVCI/F4 资料中的通用 `48slot` 文件名表示独立的 30 分钟网格，不等同于本次已确诊的小时日历字段，因此没有把它们误改成小时文件。它们的数值和原有 30 分钟语义保持不变。
