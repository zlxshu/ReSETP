# 底层口径地毯式清查清单（2026-08-15，Claude 拟，待 Codex 逐条核对）

**缘起**：2026-08-15 实测发现「48 槽」对碳强度、场内电价、公共电价、服务费**四列全部**是虚假精度
（9 城 × 28 天 × 24 小时内配对共 6048 组，无一例外相同；真实分辨率是 1 小时）。
用户随即下令：「**还有很多类似 48 小时槽数的底层错误，都全面地毯式清查，先拉清单，再去核对。**」

**病的形状**（用来判断"是不是同一类"）：
一个被广泛使用的数字、单位或口径，**跟它声称的来源对不上**——可能是复制出来的假精度、
是脚本内部常量与数据文件打架、是"待批准/占位"状态却已在用、是跨来源拼接而口径未核、
或是代理自造却没标注来源。

**本清单只列疑点与查法，不下结论。** 每条的判定必须由实测/原件给出。

## 查法的硬规矩（对执行者）

1. **每条给结论必须附实测或原件证据**，`文件:行` 或 PDF 页码；没查到就写 `UNKNOWN`，不许推测填空。
2. **报"某处不存在"之前，先拿一个已知必定存在的目标试同样的检索方式**，证明工具是好的
   （本项目已有两次教训：扫描件上 `pdftotext` 零命中、哨兵 grep 撞上自己的提示词）。
3. **不许为了让数字好看而改数据**；发现错就如实登记，修不修由用户定。
4. **区分"错"与"未标注来源"**：前者要改，后者只需补出处或降级为构造值披露。
5. 本清单**不完备**。查的过程中发现新的同类疑点，**加进来**并说明是怎么发现的。
