# 公开与私有试错合并报告

## 先说结论

这轮已经把两条线放到同一份账里：公开 V13 的 28 个算例，以及成渝、京津冀、珠三角各一个 50 客户私有算例。它们都只是试错，不是论文正式实验；本轮没有改算法本体，也没有选最终统一算例。

公开结果暂时不理想：当前自研算法在程序当前的整数化口径下 12 胜 16 负，平均成本比冻结的 PyVRP 0.12.2 HGS 高 0.179779%，总成本合计高 0.395640%。两边都完整服务了客户和需求，但大算例上自研单位时间完成的搜索轮数不够。把保存路线按 v2 的原始精度重新核对后，两边各只有 1/28 个解完全可行，所以这轮还不能说已经打赢 v2 的文献强对手。以上数字来自公开包的 `decision.json` 和 `raw_runs.csv`，本合并包 `raw_runs.csv:2` 只保留了同一汇总口径。

私有静态结果比公开线更有信息量。三个 50 客户样本的完整系统都找到了可行的完整服务解：成渝成本从 2483.6386 降到 2373.3365，京津冀从 2675.9848 降到 2431.2175，珠三角从 2020.7254 降到 1911.1359。三地客户均为 50/50，需求全部完成。成渝和京津冀的完整系统与“只开路线通道”得到同一个最好值；珠三角的完整系统比路线通道额外低 109.5895，排放也额外低 56.2013 kg。这说明机制通道在这个珠三角探路样本里确实打开过路线通道之外的改善，但目前只有一个种子、五轮搜索，不能把它写成稳定规律。数据在本合并包 `raw_runs.csv:3-11`，最终排放在三个 `best_solution.json` 的 `evaluation.breakdown.E_total`（分别为第 240、240、242 行）。

“只开机制通道”的三地最终保存最好值都没有低于初始值。不过轨迹里确实出现过可行的局部机制动作：成渝有两次时变碳充电动作降低局部成本和排放（`cy_mechanism_only_iter5_seed11/trajectory.jsonl:143,288`）；京津冀出现车型交换、充电和车场协同动作（`jjj_mechanism_only_iter5_seed11/trajectory.jsonl:10,2446,4901,5224,9086,9109,9431`）；珠三角出现车型交换和充电动作（`prd_mechanism_only_iter5_seed11/trajectory.jsonl:4,1225,3610`）。这些动作大多发生在一个暂时较差的父代上，未能进入全局保存最好解；因此正确说法是“机制有真实作用通道，但短试跑还没有稳定的最终增量”，不是“机制全部无效”。

私有动态结果显示三地不能用一个漂亮的结论概括：成渝成本下降 21.4073、排放下降 2.9743 kg；京津冀成本下降 59.4236，但排放上升 4.3506 kg；珠三角成本和排放都没有变化。三个动态包都保持了已执行历史，仍完整服务 50/50 客户和全部需求。数据来自动态包各自的 `raw_runs.csv`，合并包对应 `raw_runs.csv:12-14`。所以动态成本改善有试跑信号，但三地排放方向不一致，不能写成稳定的动态减排效应。

## 这轮对算法意味着什么

公开线给出的主要问题是“搜索效率和公开可比性”，不是“算法完全跑不通”：自研在 28 例中有 12 例胜母体，但平均优势没有形成，且大算例上更慢；精度口径又暂时挡住了与 v2 强对手的直接比较。

私有线给出的主要信息是“路线通道是当前最稳定的改善来源，机制通道有时能补上额外改善，但还不稳定”。珠三角静态 system 与 route-only 的差值，是本轮最直接的机制增量信号；成渝、京津冀的 system 与 route-only 相同，说明不能把机制动作的出现次数直接当成最终贡献。

成渝完整 system 的第一次 20 轮请求在第 5 轮进入很慢的机制候选枚举，已经按用户的 20 分钟上限停止，原始轨迹保留在 `duty_hgs_private_three_region_probe_20260809/cy_system_iter20_seed11/`，并明确排除在定量汇总外。随后补跑的成渝 5 轮 system 在 5.82 秒内完成，才纳入本报告；这两个包不能混在一起看。

当前可以交给用户的判断只有三句：

1. 公开 28 例还没有证明自研算法稳定强于母体，且暂时不能与 v2 exact 强对手直接比较。
2. 三个私有 50 客户样本都能完整运行；珠三角出现了机制相对路线通道的额外改善，另外两地没有出现最终增量。
3. 动态成本有局部改善，但排放效应不稳定；三个样本仍是探路候选，尚不是最终统一算例。

本轮之后我不自动改算法、不自动删除 DCREX、不自动选地区或统一算例，也不把这些数字写进论文正文。下一步由用户决定是先处理公开线的精度／效率问题，还是继续用这三个样本做更有针对性的效应试错。
